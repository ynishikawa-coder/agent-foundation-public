# 版の印（git の tag）を自動で打つ型

版の印（git の tag＝ある commit に付ける名札）を、人の手でなく GitHub Actions が打つ型です。この repo で動かし、使う側の repo も同じ形で写します。

## なぜ

窓（AI の作業の場）の git の口から tag を push すると HTTP 403 で断られ、毎回オーナーの手になっていた。`main` に入った時に Actions が `CHANGELOG.md` の版から印を打てば、人の手が要らない。

## 部品は 2 つ

| 物 | 役 |
|---|---|
| `scripts/release/tags_from_changelog.py` | 版ごとに印の先の commit を決め、まだ無い印を `版 SHA` の行で出す |
| `.github/workflows/tag.yml` | `main` への push（と手で回す `workflow_dispatch`）で道具を呼び、注釈付きの印を打って push し、打った物を job の summary に出す |

## 印の先の決め方

版 `vX.Y.Z` の印の先は「`main` の一本道（first-parent＝merge の時に `main` 側をたどる道）で、`CHANGELOG.md` のその版の節（見出しの行と中身）が最後に変わった commit」。

- 版の節が入った commit（`[Unreleased]` を `## [vX.Y.Z] - YYYY-MM-DD` に替えた merge）を指す。
- 次の版の節が入っても、前の版の先は動かない。`[Unreleased]` に足すだけの commit でも動かない。
- 印を打つ前に同じ版の節へ足されたら、足した commit へ進む。
- 既にある印は飛ばす（動かさない・消さない）。`[Unreleased]` の節は打たない。

「その版が一番新しかった最後の commit」で決めない理由: 版を出した後の PR は `[Unreleased]` に足すので、その決め方だと版の中身に無い変更まで印に入り、印の先が次の版まで流れ続ける。節が最後に変わった所で切れば、印は CHANGELOG に書いた中身とそろう。

## 手で打つ口（過去の版）

版の節を CHANGELOG に持たない過去の版（例: 自動で打つ形を入れる前に出した版）は、Actions の `tag` を手で回し（Run workflow）、入力 `version`（`vX.Y.Z`）と `sha`（40 桁）を両方渡して打つ。オーナーの手で `git tag` を打たない。

- 入力は `run` に直に埋めず `env` で渡す（入れ込み＝入力に紛れた命令が走る事を防ぐ）。
- 道具が照らす: 版の形 `vX.Y.Z`・sha の形（小文字 40 桁）・その commit が `origin/main` の祖先か（`git merge-base --is-ancestor`）。違えば止まる。片方だけの時も止まる。
- 既にある印は飛ばす（動かさない・force しない）。打つのは注釈付きの印で、summary に出る。
- 入力が無い時は、上の CHANGELOG からの決め方のまま。

手元で同じ照らしを見る: `python3 scripts/release/tags_from_changelog.py --ref origin/main --version vX.Y.Z --sha <40 桁>`

手元で見る:

```
python3 scripts/release/tags_from_changelog.py --all   # 全部の版と先（既にある印も）
python3 scripts/release/tags_from_changelog.py         # まだ無い印だけ
```

履歴が浅い（shallow clone）時は止まる。`fetch-depth: 0` で取り直す。

## 使う側の repo へ写す

1. 次の 3 つを写す: `scripts/release/tags_from_changelog.py`・`.github/workflows/tag.yml`・`tests/test_tags_from_changelog.py`（この repo の SHA を見る `test_この_repo_の版の印` は消すか、写し先の版と SHA に替える）。`CHANGELOG.md` の版の見出しは `## [vX.Y.Z] - YYYY-MM-DD` にそろえる。版の節を持たない過去の版は、写した後に「手で打つ口」で打つ。
2. 写す時に変える所:
   - **CHANGELOG の場所**が根でない時: workflow の道具の呼び出しに `--changelog <path>` を足す。
   - **入れる枝**が `main` でない時: workflow の `branches: [main]` と、job の `if: github.ref == 'refs/heads/main'`（手で回す時に他の枝を選んでも打たない守り）の 2 か所を替える。
   - **版の見出しの形**: 道具の `HEAD_RE` は替えない。写し先の CHANGELOG の見出しを `## [vX.Y.Z] - YYYY-MM-DD` にそろえる。
   - **既に人の手で打った印**があれば、そのまま残る（飛ばす）。無い版は、写した後の最初の `main` への push で過去の分も打たれる。打つ前に `--all` で先を見て、違えば CHANGELOG を直してから入れる。
3. repo の設定: Settings → Actions → General → Workflow permissions が「Read and write」か、workflow の `permissions: contents: write` が効く設定であること。tag の守り（ruleset）で tag の作成を縛っている時は、GitHub Actions を外す側に入れる。
4. 窓の git の口から `.github/workflows/` への push が断られる時（workflow の許しが無い）は、`tag.yml` の本文をこの文の写しから取り、オーナーの手で置く 1 手にする。

## 打たれた印の見方

Actions の `tag` の実行の summary に「版の印」の表（版・commit）が出る。打つ物が無い時は「打つ印は無い」と出る。
