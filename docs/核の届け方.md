# 核と道具の届け方

土台の核・skill・hook は、使う側の repo へ写さず、**土台の plugin を窓の起動前に入れて**届けます。正本はこの repo の 1 か所だけで、窓は **いつも main の先端** を入れます（版で止めない・版の印は打たない）。

## 何がどう届くか

| 物 | 正本 | 窓に届く道 |
|---|---|---|
| 核（常に読む原則） | `plugins/core/核.md` | plugin `core` の SessionStart の hook（`scripts/kaku.py inject`）が起動時に文脈へ差し込む |
| 細目（形に迷った時に読む） | `plugins/core/細目.md` | 差し込みの末尾に、入った plugin の中の path を知らせる（要る時に Read） |
| skill | `plugins/<名>/skills/<skill>/` | plugin として入る（呼び名は `<plugin>:<skill>`） |
| hook | `plugins/<名>/hooks/hooks.json` | plugin として入る |

plugin は入れた時に自分の dir しか持って来ないため、核も `plugins/core/` の中に置きます。

## 使う側がやる事

1. **起動前に入れる**: クラウドの環境の setup script で、main の先端を user scope に入れる。setup script は窓の箱が新しく作られるたびに回るので、新しい窓にはいつも合流した所までが届く。

   ```bash
   claude plugin marketplace add ynishikawa-coder/agent-foundation-public --scope user || true
   claude plugin install core@agent-foundation --scope user || true
   claude plugin install guard@agent-foundation --scope user || true
   # 使う物だけ: docs-kit・dev-flow・session-watch・checker（どの行も || true を付ける）
   ```

   - 1 行目に `#v0.4.18` のような版（tag）や枝・SHA を付けない（付けると古い土台で止まる）。版の印はこの形に替えた時で打ち止めにした（打った印は消さない）。
   - この repo は public なので、どの環境・どの窓（AI が立てた子の窓も）でも鍵なしで取れます。

   **入れ損ねを黙らせない**: setup script が非 0 で抜けると窓が起動しないので、上の行には `|| true` を付けて失敗しても先へ進めます。その代わり、入れ損ねると核も守りの hook も黙って抜けます。入れた後に次を足し、抜けていれば窓が起動時に必ず読む `~/.claude/CLAUDE.md` に知らせを書きます（全部入れば知らせを消します）。

   ```bash
   want="core guard"   # 入れた plugin の名を並べる
   list="$(claude plugin list 2>/dev/null || true)"; lack=""
   for p in $want; do printf '%s' "$list" | grep -q "${p}@agent-foundation" || lack="$lack $p"; done
   mkdir -p ~/.claude && touch ~/.claude/CLAUDE.md || true
   sed -i '/^<!-- af-plugin-missing -->/d' ~/.claude/CLAUDE.md || true
   [ -n "$lack" ] && echo "<!-- af-plugin-missing --> 土台の plugin が入っていない:$lack。核と守りの hook がこの窓で効いていない。最初にオーナーへ知らせる。" >> ~/.claude/CLAUDE.md || true
   ```
2. **`CLAUDE.md` には、その repo に固有の決まりだけを書く**。核の写しの枠（`<!-- AF-CORE:BEGIN … -->`）は置かない。量の上限は `python3 plugins/core/scripts/kaku.py check --claude <その repo の CLAUDE.md>` で照らせる（数は `kaku.py` の `LIMITS`）。
3. **使う側は何も上げない**。土台が合流した時から、次に立つ窓に新しい物が届く。

## main の先端を配る代わりの守り

版で止めないので、土台の誤りは合流した時に全部の窓へ届きます。それを合流の前に止めるのが CI の job `plugin-smoke`（`scripts/plugin_smoke.py`・main の守りの必須の検査）です。PR の枝を **使う側と同じ入れ方**（`claude plugin marketplace add <repo>#<枝>` → `claude plugin install`）で入れて窓を起動し、次が全部届くかを見ます: 正本の plugin が全部読み込まれる／正本の skill が全部読み込まれる／核が正本と一字違わず差し込まれる／守りの hook（guard の PreToolUse）が止めるべき作り物の入力を止める／入った copy の hook が全部落ちずに回る。窓は鍵なしで立てるのでお金はかかりません。

使う側の振る舞いを変える変更（`CHANGELOG.md` の「壊れる:」）は、2 段で入れます（`CONTRIBUTING.md` §8）。

## 古い土台で立った窓

窓は立った時の土台で動き続けます。立った後に main の先端が窓の振る舞いを変えたら（`plugins/`・`.claude-plugin/` が変わったら）、その窓は **AI が自分で新しい窓を立てて仕事を引き継ぎ、古い窓を閉じます**（🙋 の窓も同じ。人の作業は新しい窓で止まらず続く。止めるのは AI だけ）。

- **見分け方**: plugin `core` の hook が、入った commit（Claude Code が入れた時に書く台帳 `~/.claude/plugins/installed_plugins.json` の `gitCommitSha`）と、main の先端（入れた時の marketplace の clone へ main だけを取って来た commit）を比べ、間で `plugins/`・`.claude-plugin/` が変わったかを見る。文書・試験・CI だけの変更では窓を替えない。
- **いつ見るか**: 窓の最初の起動の時（`kaku.py inject`・文脈の圧縮・`/clear`・resume でもう一度回っても、起動の時の記録は書き直さず外へも見に行かない）と、人が問いを打つたび（`kaku.py fresh`・外へ見に行くのは 15 分に 1 回まで）。
- **起動の後に古くなった**: 問いの隣に引き継ぎの手順が出る — 手の中の変更を push → `create_session` で同じ repo・同じ環境に新しい窓（引き継ぎ文つき）→ 人と親の窓へ新しい URL → `archive_session` で自分を閉じる。
- **起動の時から古かった**（setup script が版を指したまま・入れ損ね）: 直さずに立て直しても同じ物が入るので、先に setup script を上の形に直し（Javis の環境は `get_environment` → `update_environment`）、それから新しい窓へ引き継いで閉じる。直せない時（他のアカウントの環境・道具が無い・その窓自身が引き継ぎで立った窓）は引き継がず（輪にならない）、UTC の環境なら連絡板で直しを頼み、オーナーへ知らせて頼みを続ける。
- **比べられない**（手元の dir から入れた試し・GitHub に出られない）: 知らない値で人の作業を止めないので、何もしない。

## 移る間（写しの枠がまだ在る repo）

開いた repo の根の `CLAUDE.md` に写しの枠が在る時、plugin `core` は核を差し込みません（核が二重に入らないため）。枠を畳むと、次の起動から差し込みが効きます。枠を畳む PR と、plugin `core` を入れる setup script の直しは同じ頃に入れます。

## 確かめ方

新しく立てた窓で `claude plugin list` を打ち、入れた plugin が全部 enabled で、`Version` が main の先端の commit の先頭 12 文字と同じかを見る。起動時の文脈に核（`# 振る舞いの核（agent-foundation）`）が在るかも見る。
