# 核と道具の届け方

土台の核・skill・hook は、使う側の repo へ写さず、**土台の plugin を窓の起動前に入れて**届けます。正本はこの repo の 1 か所だけで、窓は **いつも main の先端** を入れます（版で止めない・版の印は打たない）。

## 何がどう届くか

| 物 | 正本 | 窓に届く道 |
|---|---|---|
| 核（常に読む原則） | `plugins/core/核.md` | plugin `core` の SessionStart の hook（`scripts/kaku.py inject`）が起動時に文脈へ差し込む |
| 振る舞いの既定（AI の癖と逆を求める物・常に読む） | `plugins/core/振る舞い.md` | 核と同じ hook が、核の後ろに毎回差し込む |
| 形の細目（返事・問い・手の窓などの形を書く時に読む） | `plugins/core/細目.md` | 差し込みの末尾に、入った plugin の中の path を知らせる（要る時に Read） |
| skill | `plugins/<名>/skills/<skill>/` | plugin として入る（呼び名は `<plugin>:<skill>`） |
| hook | `plugins/<名>/hooks/hooks.json` | plugin として入る |

plugin は入れた時に自分の dir しか持って来ないため、核も `plugins/core/` の中に置きます。

## 使う側がやる事

1. **起動前に入れる**: クラウドの環境の setup script に、次の塊をそのまま貼る（足す・削る所は無い）。setup script は窓の箱が作られる時に回る。箱は作り置き（作ってから窓に渡るまで何時間も空く・2026-11-20 実測 7 時間）なので、窓に届くのは箱を作った時に合流していた所まで（その後の合流は次に作られる箱から届く）。

   <!-- setup-script: plugin-smoke がこの塊をそのまま回す（目録の repo を試す枝に替えるだけ） -->
   ```bash
   af_k=~/.claude/plugins/known_marketplaces.json; af_e=scripts/setup_plugins.py
   af_old='import json,os,sys;a=sys.argv;m=json.load(open(a[1]))["agent-foundation"];s=m["source"]'
   af_old="$af_old"';sys.exit(not(s.get("ref") or (s.get("repo") or s.get("url"))!=a[2] or not os.path.isfile(m["installLocation"]+"/"+a[3])))'
   python3 -c "$af_old" "$af_k" ynishikawa-coder/agent-foundation-public "$af_e" 2>/dev/null && claude plugin marketplace remove agent-foundation >/dev/null 2>&1 || true
   claude plugin marketplace add ynishikawa-coder/agent-foundation-public --scope user || true; claude plugin marketplace update agent-foundation || true
   af="$(python3 -c 'import json,sys;print(json.load(open(sys.argv[1]))["agent-foundation"]["installLocation"])' "$af_k" 2>/dev/null || true)/$af_e"
   af_w="<!-- af-plugin-missing --> 土台の目録が取れず、土台の plugin が 1 つも入っていない。"
   af_w="${af_w}核と守りの hook がこの窓で効いていない。最初にオーナーへ知らせる。"
   if [ -f "$af" ]; then python3 "$af" || true; else mkdir -p ~/.claude && echo "$af_w" >> ~/.claude/CLAUDE.md || true; fi
   ```

   - **plugin の名を写さない**: 何を入れるかは、土台の入口 `scripts/setup_plugins.py` が土台の配りの器（`.claude-plugin/marketplace.json`）を直に読んで決め、全部入れる。土台が plugin を足せば次の窓から入る。setup script に plugin を 1 つずつ入れる `claude plugin install` の行や、入れる名の並びを書かない（書いた repo は、開いた窓に plugin core が名指しで知らせる）。
   - **目録をいつも取り直す**: 前の setup の目録の clone が残る箱では、`marketplace add` が「already on disk」で何もせず、`plugin update` も目録を進めないので、取り直さないと古い名簿と古い入口のまま入る。`marketplace add` の後の `marketplace update` が、古い入口でも先に clone を先端へ進める。入口も自分で取り直し、入口が変わっていれば新しい入口へ移ってから入れ、入った台帳の commit が名簿の版（clone の HEAD）と同じかを照らす。
   - **入れ損ねを黙らせない**: setup script が非 0 で抜けると窓が起動しないので、どの行も `|| true` で先へ進める（貼る先の setup script が `set -e` でも最後の行まで届く）。その代わり入口が、入らなかった plugin を窓が起動時に必ず読む `~/.claude/CLAUDE.md` に名指しで書く（全部入れば消す）。目録そのものが取れない時は最後の行の else が書く。
   - **前の目録を外してから足す**: 作り置きの容器に、版（`#v0.4.18` のような tag）や枝に止めた目録・出所の違う目録（出所は目録の `repo`（GitHub の短い名）か `url` が `marketplace add` に渡す名と同じかで比べる。名の一部が合うだけの fork などは違う出所）・入口 `scripts/setup_plugins.py` を持たない目録が残ると、`marketplace add` は飛ばされ `marketplace update` も止めた版から動かないので、古い目録から入る。`marketplace remove` の行がその目録だけを外し（今の目録は外さない）、次の `add` が先端を取り直す。
   - **1 行 200 バイト・100 行まで**: クラウドの窓の道具 `update_environment` が setup script を運べるのは 1 行 200 バイト（改行を除く）・100 行まで。超える行があると AI の窓が環境に貼れないので、塊はこの内に収める（長い文は変数に分けて足す・`tests/test_setup_script_line_limit.py` が照らす）。
   - `marketplace add` の行に `#v0.4.18` のような版（tag）や枝・SHA を付けない（付けると古い土台で止まる）。版の印はこの形に替えた時で打ち止めにした（打った印は消さない）。
   - この repo は public なので、どの環境・どの窓（AI が立てた子の窓も）でも鍵なしで取れます。
   - 古い形の setup script（入口を通らず名を写して入れる）で立った窓には、plugin core の起動の hook が「setup script が古い形」と入っていない plugin を名指しで知らせる（入口が `~/.claude/af-foundation/setup.json` に書く印で見分ける）。
2. **`CLAUDE.md` には、その repo に固有の決まりだけを書く**。核の写しの枠（`<!-- AF-CORE:BEGIN … -->`）は置かない（在っても核は正本が差し込まれ、枠は名指しで知らされる）。量の上限は使う側が照らす手も数も持たない: plugin core の起動の hook が、開いた repo の根の `CLAUDE.md` が上限（数は土台の `kaku.py` の `LIMITS` の 1 か所）を越えていれば名指しで知らせる。土台の核と振る舞いの既定は上限の内でも、形の細目（細目.md）も含めて、main より増えたら赤（`scripts/checks/kaku_growth.sh`）＝足すなら同じ変更で同じだけ畳む。
3. **使う側は何も上げない**。土台が合流した時から、次に立つ窓に新しい物が届く。

## main の先端を配る代わりの守り

版で止めないので、土台の誤りは合流した時に全部の窓へ届きます。それを合流の前に止めるのが CI の job `plugin-smoke`（`scripts/plugin_smoke.py`・main の守りの必須の検査）です。PR の枝を **使う側と同じ入れ方**（上の setup script の塊を、目録の repo だけ `<repo>#<枝>` に替えてそのまま回す）で入れて窓を起動し、次が全部届くかを見ます: 正本の plugin が全部読み込まれる／正本の skill が全部読み込まれる／核が正本と一字違わず差し込まれる／守りの hook（guard の PreToolUse）が止めるべき作り物の入力を止める／入った copy の hook が全部落ちずに回る。窓は鍵なしで立てるのでお金はかかりません。

使う側の振る舞いを変える変更（変更の記録 `CHANGELOG.d/` の札「壊れる」）は、2 段で入れます（`CONTRIBUTING.md` §8）。

## 古い土台で立った窓

窓は立った時の土台で動き続けます。立った後に main の先端が窓の振る舞いを変えたら（`plugins/`・`.claude-plugin/` が変わったら）、その窓は **AI が自分で新しい窓を立てて仕事を引き継ぎ、古い窓を閉じます**（🙋 の窓も同じ。人の作業は新しい窓で止まらず続く。止めるのは AI だけ）。

- **見分け方**: plugin `core` の hook が、入った commit（Claude Code が入れた時に書く台帳 `~/.claude/plugins/installed_plugins.json` の `gitCommitSha`）と、main の先端（入れた時の marketplace の clone へ main だけを取って来た commit）を比べ、間で `plugins/`・`.claude-plugin/` が変わったかを見る。文書・試験・CI だけの変更では窓を替えない。
- **いつ見るか**: 窓の最初の起動の時（`kaku.py inject`・文脈の圧縮・`/clear`・resume でもう一度回っても、起動の時の記録は書き直さず外へも見に行かない）と、人が問いを打つたび（`kaku.py fresh`・外へ見に行くのは 15 分に 1 回まで）。
- **起動の後に古くなった**（窓が立った時の main の先端から、先端が `plugins/`・`.claude-plugin/` を変えた。立つ前の進みは数えない）: 問いの隣に引き継ぎの手順が出る — 手の中の変更を push → `create_session` で同じ repo・同じ環境に新しい窓（引き継ぎ文つき）→ 人と親の窓へ新しい URL → `archive_session` で自分を閉じる。
- **起動の時の古さの訳**: 入った commit を、hook の時の main でなく **setup の時に入れた main の先端の記録**（入口 `scripts/setup_plugins.py` が出所の main を直に読み、`~/.claude/af-foundation/setup.json` と版ごとの `setup-<入れた版>.json` の `main_at_setup` に書く）と比べる。読むのは今動いている版の記録（起動の時に使う側の hook が入口を回し直すと setup.json は新しい版の記録に替わるので、版の名で引く。台帳の行が新しい版の dir を指した時も、今動いている dir の名＝commit の頭 12 字と版ごとの記録で入った版を引く）。同じなら setup は正しく、箱を作った後に main が進んだだけ＝setup script は直さず、引き継ぎもしない（引き継いだ新しい窓も作り置きの箱から立つので新しくならず、引き継ぎが輪になる）。違えば次の「起動の時から古かった」。記録が無い（入口を通らない古い形・記録を書く前の入口）時は、どちらとも言い切らず「分からない」と名指し、setup script を読んで形を照らしてから直すか引き継ぐ。
- **起動の時から古かった**（setup が `main_at_setup` と違う物を入れた＝setup script が版を指したまま・目録を取り直さない古い形・入れ損ね）: 直さずに立て直しても同じ物が入るので、先に setup script を上の形に直し（Javis の環境は `get_environment` → `update_environment`）、それから新しい窓へ引き継いで閉じる。直せない時（他のアカウントの環境・道具が無い・その窓自身が引き継ぎで立った窓）は引き継がず（輪にならない）、UTC の環境なら連絡板で直しを頼み、オーナーへ知らせて頼みを続ける。
- **比べられない**（手元の dir から入れた試し・GitHub に出られない）: 知らない値で人の作業を止めないので、何もしない。

## 使う側に残った写し・古い形

土台が形を変えた後、使う側（製品の repo・環境の setup script）に古い形が残っても、写しは誰も止めません。なので土台が見つけて名指しします。

- **一覧**: 使う側に残りうる古い形は `plugins/core/古い形.json`（核の写しの枠・plugin の名を写した setup の行など）。
- **窓ごとに名指し**: plugin core の起動の hook が、開いた repo にその古い形が残っていれば file ごとに知らせる。核はいつも正本を差し込む（写しの枠が在っても、写しでなく正本が効く）。知らされた窓は、土台を直した同じ仕事として、その repo の手順で枠や行を消す PR を出す。
- **読む物は main の中身**: 起動の hook も `olds` も、開いた repo の作業の枝の checkout でなく main（origin の既定の枝）の中身を読む。checkout にだけ在る形は枝と main の分かれ目の中身で分け、分かれ目に在れば「枝が main より古い（main で直った）」、無ければ「この枝で足した（消す）」、分かれ目が読めない（浅い clone）時は「分からない」と名指す。main を持たない dir（git でない・origin が無い）は checkout を読む。
- **移ったのを記録で確かめる**: `python3 plugins/core/scripts/kaku.py olds <使う側の checkout>...` が古い形 0 か外れを file ごとに出す（読んだ main の commit も出す・先に `git fetch` で main を新しくしておく）（「壊れる（2 段目）」の前に回す・`CONTRIBUTING.md` §8）。

## 確かめ方

新しく立てた窓で `claude plugin list` を打ち、入れた plugin が全部 enabled で、`Version` が setup の時の main の先端（`~/.claude/af-foundation/setup.json` の `main_at_setup`）の先頭 12 文字と同じかを見る（確かめる時の main の先端と比べない＝setup の後に main が進んでも setup の誤りではない）。また、起動時の文脈に核（`# 振る舞いの核（agent-foundation）`）と振る舞いの既定（`# 振る舞いの既定（agent-foundation）`）が在るかを見る。
