# 公開の検査

核 §1 の「公開の repo は、いつ誰に見られてもよい状態に保つ」を機械で担う仕組みです。中身は土台に 1 つだけ置き、各公開 repo は main の先端（`@main`）で呼ぶだけにします（写さない・版で止めない）。土台の直しは合流した時から全部の公開 repo に届くので、誤った検査で全部の公開 repo の合流が止まらないよう、土台は合流の前に自分の CI（job `public-guard`・`check`）で検査を試します。

## 3 つの部品

| 部品 | 置き場 | 役 |
|---|---|---|
| 検査の本体 | `public-guard/guard.py` | 置かない物を照らして止める |
| 呼ばれる口 | `public-guard/action.yml`（action `public-guard`） | 各公開 repo の CI が呼ぶ。取り出し（歴史ごと）と本体の実行 |
| 見回り | `public-guard/patrol.py`・`.github/workflows/patrol.yml` | 外れた公開 repo を毎日見つけて知らせる |
| workflow の読み手 | `public-guard/workflow_reader.py` | どの workflow の・どの job の・どの step が・どの起こり方で action `public-guard` を呼ぶかを読む正本。見回り・守りの hook・手元の検査は皆ここを通して読む |

## 検査が見る物

- **中身**: git の追跡するファイルと、まだ git に入れていない新しいファイル（`.gitignore` の外）の名と全行。UTF-8 で読めない字は置き換えて読む（中身を空にしない＝ASCII の鍵の形は照らす）。作業の木で消した追跡のファイルは index の中身を照らす。submodule は名だけ照らし、中身は照らしていない物として名指す。
- **歴史**: 照らす範囲（PR は base..head・main への push は before..after・新しい枝の push〔before が 0 の並び〕は既定の枝の今の先端..after、既定の枝そのものの初めての push か先端を聞けない時は after の全ての歴史）の各 commit で足された行。消しても歴史に残るため。バイナリの差分も字として照らす。名が日本語のファイルも、名に `"`・タブ・改行・`\` を含むファイル（git が引用符つきで出す名。解けない名も仮の名で照らす）も、merge の commit で足された行（各親との差）も見る。
- **外側**: commit の説明・名義と、PR の題・本文。名義のメールは noreply（GitHub の `<id>+<名>@users.noreply.github.com`・`noreply@anthropic.com`）だけ通す。
- **照らす中身**: 鍵の形・個人の情報の形（メール・電話・郵便番号・Notion と Google の文書の URL）・その repo の置かない語の表（任意）・顧客の語。照合の前の正規化は `normalize()` 1 つ（NFKC・幅の無い空白などの書式の字を除く）で、形・置かない語・顧客の語（平文と束）は皆これを通す（全角・互換の字ですり抜けない）。語は大文字・小文字を区別しない。
- **形の照らしから外す所**（`pattern-skip`）: 形を書いた検査の道具のファイルだけを名指す。壊れるの 1 段目: 個人の情報の形は前の形のまま file ごと外す。秘密の形（鍵・トークン）は file 全体で照らす。置かない語と顧客の語は外さない。印の行だけに絞るのは 2 段目。
- 当たりの場所はファイルの名で出す。ただし名そのものに置かない物がある時は、名を伏せて番号で出す（公開の repo の Actions のログは誰でも読める）。
- **顧客の語** は repo に書かない。repo の secret `AF_DENY_BUNDLE`（Javis の顧客の語の束 `pct1.…` と同じ値）か `AF_DENY_WORDS`（1 行 1 語）から渡す。**CI でどちらも無い時は赤**（照合が飛んだまま緑にしない）。語そのものは出力に出さない。
- **照らしていない物は緑と言わない**: 当たりが 0 でも、照らしていない物が在れば exit 3（照らしていない）で何かを名指す。照らしていない物＝顧客の語が無く照合を飛ばした（手元）・照らす範囲の commit が 0（手元で枝の先端が main と同じ等）・照らすファイルが 0（数えるのは中身を読んで照らした物だけ。読めずに名指した物は数えない）・手元で PR の event が無く PR の題・本文を照らしていない・event の file が無い・読めない（CI で GITHUB_EVENT_PATH が無い時も）・submodule の中身や読めない file の中身。名指した置かない語の表に語が 0 の時は 1 段目: 名指して ✅ とは言わず exit 0（前の形は止めない）。CI では exit 0 でない物は皆赤（action の step が落ちる）。名指した置かない語の表が無い時は exit 2。
- **手元の検査**（`scripts/checks/public_guard.sh`）: ci.yml の job `public-guard` の呼び口の `with:` を workflow の読み手で読んで同じ値で回す。CI の中では照らさず exit 3 を返すが、その訳「job `public-guard` が照らす」は、読み手でその job に数える呼び口が在る事を確かめてから言う（無ければ赤）。手元には PR の event が無いので、手元の検査は当たり 0 でも exit 3（PR の題・本文は CI の job と出す前の守りの hook が照らす）。

## 出す前の文

PR の題・本文とコメントは、GitHub に出すと書き替えても古い版が編集の履歴に公開で残ります。そこで、窓が GitHub の道具で出す前に、守りの hook（plugin guard の `pr_text`）が同じ本体を `python3 public-guard/guard.py --text "PR の本文=<file>" [--deny-words-file <表>]` の口で呼び、当たれば AI の呼び出しを止めます（中身・歴史は見ない）。顧客の語が環境に無い時・表に語が 0 の時は、その照合を飛ばした事を出力に名指し、緑（✅）とは言わない。ただし exit は CI でも 0 のまま（hook は 0 以外を止めるので、3 や 1 にすると顧客の語の無い窓の出す前の文が皆止まる＝新しく止める物になる）。当たりは顧客の語が無くても出して止める。公開かは、窓の repo の取り出し（origin の URL を `owner/repo` に読み、名の全体で比べる。https・ssh のどの形でも）の workflow に、PR か push で走る job の step で action `public-guard` を呼ぶ物が在るかで見分けます（workflow_dispatch・schedule だけで走る workflow や `if: false` の job の呼び口は数えない）。置かない語の表は、数える呼び口の全部の `with:` の `deny-words-file` の和を使います（同じ workflow の別の step・job の `deny-words-file` は読みません）。読み方は workflow の読み手が正本です。手元に取り出しの無い公開の repo は値の表 `guard.public_repos_extra` に、名の全体に当てる正規表現（`^owner/repo$`）で足します。

## 公開の repo を作る・直す

手順の正本は skill `dev-flow:public-repo`。要は次の 4 つです。

1. **綺麗な所から作る** — 非公開の repo をそのまま公開に切り替えない（歴史と名義が全部見える）。新しい repo に、照らした今の中身を noreply の名義の 1 commit で置く。
2. **呼び口を置く** — `public-guard/caller-template.yml` を `.github/workflows/public-guard.yml` へ写し、`@main` のまま置く（版の印や SHA で止めない）。job の名 `public-guard` は変えない。
3. **secret を置く**（持ち主の手）— Settings → Secrets and variables → Actions に `AF_DENY_BUNDLE`。
4. **既定の枝（main）を守る**（持ち主の手）— Settings → Rules → Rulesets で既定の枝に: PR を必須・必須の検査に `public-guard`・force push と削除を禁止。個人の無料の plan では非公開の repo に ruleset が効かないので、公開に切り替えた直後に入れる（切り替えまでの間も CI の検査は回る）。

- 呼ぶ側の job は `runs-on: ubuntu-latest` にする（action の中の bash は bash 5 を前提にしている。macOS の runner の bash 3.2 では空の入力で落ちる）。

## 見回り

- 毎日 06:17 日本時間と、土台の main に入った時に回る。相手は `public-guard/patrol.json` の `owners` の公開 repo（archive 済みは除く）。UTC 側の持ち主を足す時は、その 1 行を PR で足す。
- 外れ: ①呼び口が無い（job `public-guard` の step で、PR か push の時に呼ぶ物。コメントの行・`run:` の字・別の job の step・手で回すだけの workflow・`if: false` の job は数えない＝workflow の読み手が見分ける） ②`@main` 以外（版の印・SHA・枝）で止めている ③既定の枝（main）の守りの必須の検査に `public-guard` が無い（土台そのものは `plugin-smoke` も要る＝`CONTRIBUTING.md` §3）。
- fork も見る。持ち主の名の下にある公開の repo は、fork でも世界に見えるため。fork を公開で持たない時は、archive するか消す。
- 外れがあれば、この repo の issue「公開の検査の見回り」を立てる（書き替える）と同時に、Actions の `patrol` が赤で終わる。0 件になれば issue を閉じる。
- 呼び口の外れには、その repo の開いた PR のうち合流すれば外れが消える物（PR の先端の workflow を同じ読み手で読む）を「次の手」として名指す（赤と issue の本文の両方）。直しの PR がレビューを通ったまま合流されず、赤が続くのを見えるようにするため。合流までは赤のまま。守りの外れ（必須の検査）は設定なので PR では消えない。
- 手元で: `python3 public-guard/patrol.py --owner <持ち主>`（GitHub の API に出られる所で）。

## 外せない、の担保

GitHub の設定（secret・ruleset・公開の切り替え）は AI には固定できません。なので、外れたら必ず見つけて知らせる形にしています。検査の本体は土台に 1 つで、各 repo は main の先端で呼ぶだけなので、中身を写した古い検査も、古い版で止まった検査も残りません。
