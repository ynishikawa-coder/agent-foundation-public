# 公開の検査

核 §1 の「公開の repo は、いつ誰に見られてもよい状態に保つ」を機械で担う仕組みです。中身は土台に 1 つだけ置き、各公開 repo は版の印で固定して呼ぶだけにします（写さない）。

## 3 つの部品

| 部品 | 置き場 | 役 |
|---|---|---|
| 検査の本体 | `public-guard/guard.py` | 置かない物を照らして止める |
| 呼ばれる口 | `public-guard/action.yml`（action `public-guard`） | 各公開 repo の CI が呼ぶ。取り出し（歴史ごと）と本体の実行 |
| 見回り | `public-guard/patrol.py`・`.github/workflows/patrol.yml` | 外れた公開 repo を毎日見つけて知らせる |

## 検査が見る物

- **中身**: git の追跡するファイルの名と全行。
- **歴史**: 照らす範囲（PR は base..head・main への push は before..after）の各 commit で足された行。消しても歴史に残るため。名が日本語のファイルも、merge の commit で足された行（各親との差）も見る。
- **外側**: commit の説明・名義と、PR の題・本文。名義のメールは noreply（GitHub の `<id>+<名>@users.noreply.github.com`・`noreply@anthropic.com`）だけ通す。
- **照らす中身**: 鍵の形・個人の情報の形（メール・電話・郵便番号・Notion と Google の文書の URL）・その repo の置かない語の表（任意）・顧客の語。
- 当たりの場所はファイルの名で出す。ただし名そのものに置かない物がある時は、名を伏せて番号で出す（公開の repo の Actions のログは誰でも読める）。
- **顧客の語** は repo に書かない。repo の secret `AF_DENY_BUNDLE`（Javis の顧客の語の束 `pct1.…` と同じ値）か `AF_DENY_WORDS`（1 行 1 語）から渡す。**CI でどちらも無い時は赤**（照合が飛んだまま緑にしない）。語そのものは出力に出さない。

## 公開の repo を作る・直す

手順の正本は skill `dev-flow:public-repo`。要は次の 4 つです。

1. **綺麗な所から作る** — 非公開の repo をそのまま公開に切り替えない（歴史と名義が全部見える）。新しい repo に、照らした今の中身を noreply の名義の 1 commit で置く。
2. **呼び口を置く** — `public-guard/caller-template.yml` を `.github/workflows/public-guard.yml` へ写し、`@vX.Y.Z` を土台の一番新しい印にする。job の名 `public-guard` は変えない。
3. **secret を置く**（持ち主の手）— Settings → Secrets and variables → Actions に `AF_DENY_BUNDLE`。
4. **既定の枝（main）を守る**（持ち主の手）— Settings → Rules → Rulesets で既定の枝に: PR を必須・必須の検査に `public-guard`・force push と削除を禁止。個人の無料の plan では非公開の repo に ruleset が効かないので、公開に切り替えた直後に入れる（切り替えまでの間も CI の検査は回る）。

- 呼ぶ側の job は `runs-on: ubuntu-latest` にする（action の中の bash は bash 5 を前提にしている。macOS の runner の bash 3.2 では空の入力で落ちる）。

## 見回り

- 毎日 06:17 日本時間と、土台の main に入った時に回る。相手は `public-guard/patrol.json` の `owners` の公開 repo（archive 済みは除く）。UTC 側の持ち主を足す時は、その 1 行を PR で足す。
- 外れ: ①呼び口が無い ②版の印で固定していない（`@main` など）③既定の枝（main）の守りの必須の検査に `public-guard` が無い。
- fork も見る。持ち主の名の下にある公開の repo は、fork でも世界に見えるため。fork を公開で持たない時は、archive するか消す。
- 外れがあれば、この repo の issue「公開の検査の見回り」を立てる（書き替える）と同時に、Actions の `patrol` が赤で終わる。0 件になれば issue を閉じる。
- 手元で: `python3 public-guard/patrol.py --owner <持ち主>`（GitHub の API に出られる所で）。

## 外せない、の担保

GitHub の設定（secret・ruleset・公開の切り替え）は AI には固定できません。なので、外れたら必ず見つけて知らせる形にしています。検査の本体は土台に 1 つで、各 repo は版の印で呼ぶだけなので、中身を写した古い検査が残ることもありません。
