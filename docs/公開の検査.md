# 公開の検査

核 §1 の「公開の repo は、いつ誰に見られてもよい状態に保つ」を機械で担う仕組みです。中身は土台に 1 つだけ置き、各公開 repo は main の先端（`@main`）で呼ぶだけにします（写さない・版で止めない）。土台の直しは合流した時から全部の公開 repo に届くので、誤った検査で全部の公開 repo の合流が止まらないよう、土台は合流の前に自分の CI（job `public-guard`・`check`）で検査を試します。

## 3 つの部品

| 部品 | 置き場 | 役 |
|---|---|---|
| 検査の本体 | `public-guard/guard.py` | 置かない物を照らして止める |
| 呼ばれる口 | `public-guard/action.yml`（action `public-guard`） | 各公開 repo の CI が呼ぶ。取り出し（歴史ごと）と本体の実行 |
| 呼び口の雛形 | `public-guard/caller-template.yml` | 各公開 repo の `.github/workflows/public-guard.yml` の正本。見回りが一字ずつ比べる |
| 顧客の語の置き場の表 | `public-guard/deny-source.json` | 持ち主ごとに、顧客の語の束の正本を置いた非公開の repo と path |
| 見回り | `public-guard/patrol.py`・`.github/workflows/patrol.yml` | 外れた公開 repo を毎日見つけて知らせる |

## 検査が見る物

- **中身**: git の追跡するファイルの名と全行。
- **歴史**: 照らす範囲（PR は base..head・main への push は before..after）の各 commit で足された行。消しても歴史に残るため。名が日本語のファイルも、名に `"`・タブ・改行・`\` を含むファイル（git が引用符つきで出す名。解けない名も仮の名で照らす）も、merge の commit で足された行（各親との差）も見る。
- **外側**: commit の説明・名義と、PR の題・本文。名義のメールは noreply（GitHub の `<id>+<名>@users.noreply.github.com`・`noreply@anthropic.com`）だけ通す。
- **照らす中身**: 鍵の形・個人の情報の形（メール・電話・郵便番号・Notion と Google の文書の URL）・その repo の置かない語の表（任意）・顧客の語。
- 当たりの場所はファイルの名で出す。ただし名そのものに置かない物がある時は、名を伏せて番号で出す（公開の repo の Actions のログは誰でも読める）。
- **顧客の語** は repo に書かない。語を HMAC にした束（`pct1.<鍵>.<束>` の 1 行）の正本を、持ち主ごとに 1 か所の非公開の repo に置き（`public-guard/deny-source.json`）、検査はそこを直に読む。各公開 repo には束を写さず、置き場を読むだけの鍵 `AF_DENY_SOURCE_TOKEN` だけを secret に置く。語を足す時は置き場の 1 行を替えるだけで、次に回る検査から全部の公開 repo に届く。
  - 鍵があって置き場が読めない（鍵が切れた・許しが無い・置き場が無い）・中身が束の 1 行でない・表に無い持ち主・表の行に知らない鍵がある時は、写しへ落ちず止める。
  - 古い道（2 段の 1 段目として残す）: 束の写し `AF_DENY_BUNDLE`・平文 `AF_DENY_WORDS`。鍵が無く写しで照らした時は、通すが Actions の注記と job の要約に「顧客の語が写し」と名指しで出す。鍵があれば写しは使わない。全部の公開 repo が鍵へ移ったら、写しの道を畳む（2 段目）。
  - **CI でどれも無い時は赤**（照合が飛んだまま緑にしない）。語そのものは出力に出さない。

## 出す前に照らす（窓の手）

公開の repo の PR の題・本文・コメントは、出した瞬間に世界に見え、後で直しても古い版が編集の履歴に残ります。CI の `public-guard` は出した後にしか止められないので、窓は出す前に同じ照らしを手元で当てます。

```bash
python3 public-guard/guard.py --text body.md            # 本文を file に書いてから。- なら標準入力
python3 public-guard/guard.py --text body.md --deny-words-file tests/data/denylist.txt   # 土台（業務の語の表）
```

当たりがあれば直してから出します（語そのものは出力に出ません）。使う側の repo の窓は、土台の checkout（または入った plugin の在る所）の `public-guard/guard.py` を呼びます。

## 公開の repo を作る・直す

手順の正本は skill `dev-flow:public-repo`。要は次の 4 つです。

1. **綺麗な所から作る** — 非公開の repo をそのまま公開に切り替えない（歴史と名義が全部見える）。新しい repo に、照らした今の中身を noreply の名義の 1 commit で置く。
2. **呼び口を置く** — `public-guard/caller-template.yml` を `.github/workflows/public-guard.yml` へ一字も変えずに写す（`on`・`permissions`・`with` の入力名・`@main` まで。注釈の行は足してよい）。雛形が変わったら写し直す（見回りが知らせる）。
3. **secret を置く**（持ち主の手）— Settings → Secrets and variables → Actions に `AF_DENY_SOURCE_TOKEN`（持ち主の顧客の語の置き場の repo 1 つだけを読める fine-grained の鍵・Contents: Read-only）。束そのもの（`AF_DENY_BUNDLE`）は置かない。
4. **既定の枝（main）を守る**（持ち主の手）— Settings → Rules → Rulesets で既定の枝に: PR を必須・必須の検査に `public-guard`・force push と削除を禁止。個人の無料の plan では非公開の repo に ruleset が効かないので、公開に切り替えた直後に入れる（切り替えまでの間も CI の検査は回る）。

- 呼ぶ側の job は `runs-on: ubuntu-latest` にする（action の中の bash は bash 5 を前提にしている。macOS の runner の bash 3.2 では空の入力で落ちる）。

## 見回り

- 毎日 06:17 日本時間と、土台の main に入った時に回る。相手は `public-guard/patrol.json` の `owners` の公開 repo（archive 済みは除く）。UTC 側の持ち主を足す時は、その 1 行を PR で足す。
- 外れ: ①呼び口 `.github/workflows/public-guard.yml` が無い ②呼び口が雛形 `public-guard/caller-template.yml` と違う（注釈の行と行末の空白の外を一字ずつ比べる。雛形は見回りが土台の物を直に読む。土台そのものは `ci.yml` の job が雛形の `on`・`permissions` と `with` の行を全部持つか） ③どの workflow でも `@main` 以外（版の印・SHA・枝）で呼んでいる ④既定の枝（main）の守りの必須の検査に `public-guard` が無い（土台そのものは `plugin-smoke` も要る＝`CONTRIBUTING.md` §3）。
- fork も見る。持ち主の名の下にある公開の repo は、fork でも世界に見えるため。fork を公開で持たない時は、archive するか消す。
- 外れがあれば、この repo の issue「公開の検査の見回り」を立てる（書き替える）と同時に、Actions の `patrol` が赤で終わる。0 件になれば issue を閉じる。
- 手元で: `python3 public-guard/patrol.py --owner <持ち主>`（GitHub の API に出られる所で）。

## 外せない、の担保

GitHub の設定（secret・ruleset・公開の切り替え）は AI には固定できません。なので、外れたら必ず見つけて知らせる形にしています。検査の本体は土台に 1 つで、各 repo は main の先端で呼ぶだけなので、中身を写した古い検査も、古い版で止まった検査も残りません。顧客の語も持ち主ごとに 1 か所の正本を検査が直に読むので、写した束が古いまま緑になる事がありません（写しの道は畳むまで名指しで知らせます）。呼び口は雛形と一字ずつ比べるので、写した呼び口の `on`・`permissions`・入力名のずれも見回りが見つけます。
