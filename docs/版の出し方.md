# 版の出し方

この repo を道具として使う側（別のアカウントの窓・別の repo）が、決まった中身を読めるように、版（git のタグ）を出します。

## 版の名

- semver に `v` を付ける: `v<大>.<中>.<小>`（例: `v0.1.0`）。
  - **大**: 使う側が直さないと壊れる変更（skill の名を変える・消す、核の文の約束を変える）。
  - **中**: 足すだけの変更（skill・道具・決まりを足す）。
  - **小**: 直しだけの変更（誤りの直し・文の手入れ）。
- `v1.0.0` の前（`v0.x.y`）は、中の位を上げて壊れる変更を出してよい。その時は CHANGELOG に「壊れる」と書く。

## CHANGELOG の形

`CHANGELOG.md` は新しい版が上。先頭は必ず `## [Unreleased]`。

```
## [Unreleased]

### 足した
- …
### 変えた
- …
### 消した
- …
### 直した
- …

## [v0.1.0] - 2026-11-11
…
```

- PR を出す窓は、同じ PR で `## [Unreleased]` に 1 行足す（使う側に関係ない変更なら足さなくてよい）。
- 版の見出しは `## [vX.Y.Z] - YYYY-MM-DD`（日付は日本時間）。

## 出す手順（親窓だけ）

版を決めるのは **Javis 側の親窓だけ**。印（タグ）は人も窓も打たない。`main` に入った時に GitHub Actions（`.github/workflows/tag.yml`）が打つ。決め方と型は `docs/版の印.md`。

1. 出す中身が全部 `main` に入っている（squash 済み）ことを見る。
2. 新しい枝で `CHANGELOG.md` の `## [Unreleased]` を `## [vX.Y.Z] - YYYY-MM-DD` に替え、空の `## [Unreleased]` を上に足す。PR → レビュー → squash merge。
   同じ PR で、各 plugin の `plugins/*/.claude-plugin/plugin.json` の `version` を全部 `X.Y.Z`（`v` 無し）にそろえる。plugin ごとに別の番号は持たない（版の番号の物差しは土台の版 1 つ）。`tests/test_版の番号.py` が照らす。
3. merge で Actions の `tag` が走り、その merge の commit に注釈付きの印 `vX.Y.Z` を打つ。打った物は実行の summary に出る。
4. 一度出したタグは動かさない・消さない。誤りは次の版（小を上げる）で直す。出した版の節は書き換えない（印の前に足すと印の先が動く）。

## 使う側の読み方

- 使う側は **版を固定して読む**。`main` の先端を直に読まない。
  - 例: プラグインの配りの器や clone で、ref に `vX.Y.Z` を指定する。
- 版を上げる時は、CHANGELOG のその間の節を読み、`壊れる` があれば使う側を先に直す。
