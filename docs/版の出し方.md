# 版の出し方

この repo を道具として使う側（Javis と UTC エージェントの窓）が読む版（git の tag＝ある commit に付ける名札）は、**main に入るたびに GitHub Actions が自動で打つ**。人も窓も版を出す手を打たない。

## 決め方

- 版の名は `v<大>.<中>.<小>`（例: `v0.4.1`）。
- main に入るたびに、一番新しい印の **小の位を 1 上げた印** を、その merge の commit に打つ（`.github/workflows/tag.yml` が `scripts/release/next_tag.py` を呼ぶ）。印の注には merge の題が入る。
- その commit に印が既にあれば打たない。印は動かさない・消さない。誤りは次の合流で直す（次の印になる）。
- 中・大の位を上げたい時（大きな区切りを名で示したい時）だけ、Actions の `tag` を手で回し（Run workflow）、入力 `version` に `vX.Y.Z` を渡す。今の main の先端に打つ。今の一番新しい版より新しくない名は止まる。
- plugin（`plugins/*/.claude-plugin/plugin.json`）は版の番号を持たない。番号は印 1 つだけ（合流のたびにそろえる手を持たない・`tests/test_next_tag.py` が照らす）。

## 使う側の読み方

- 使う側は `ref: latest`（一番新しい印）を読むか、止めたい時だけ印の名（例 `v0.4.1`）を書く。main の先端を直に読まない（印を読めば、壊れた時に 1 つ前の印へ戻せる）。
- 印は合流ごとに出るので、合流した後に立てた窓から新しい物が効く。

## CHANGELOG

- `CHANGELOG.md` の先頭の節「合流ごと」に、使う側に関係する変更を PR ごとに 1 行足す（新しい物が上・PR の番号を添える）。版の見出しは書かない（印が版）。
- 使う側の振る舞いが変わる物は、行の頭に「壊れる:」と書く。

## repo の設定

- Settings → Actions → General → Workflow permissions が「Read and write」か、workflow の `permissions: contents: write` が効くこと。tag の守り（ruleset）で tag の作成を縛る時は、GitHub Actions を外す側に入れる。
- 窓の git の口から tag を push すると断られる（HTTP 403）。印は Actions だけが打つ。
