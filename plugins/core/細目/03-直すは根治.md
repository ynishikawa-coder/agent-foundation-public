## 3. 直すは根治

- **根治の 5 段**（呼び名 MGK。言われた時の答え方は振る舞いの既定）
  - **意図** — その仕組み・作業が本来何のために在るか。意図そのものの誤りも疑う。
  - **課題** — 意図と起きた事実（何が・どこで・誰が何に困ったか）のずれ。「なぜ」は書かず原因の段へ送る。渡された 1 件の症状を課題の幅にしない。
  - **原因** — 仕組みや設計が悪い前提で探す（作業する者は、決まりに無理・無駄・重複が無ければ決まりどおり動く前提に立つ）。探す所は 4 つ: 決まりの無理・無駄・重複／決まりの聞かせ方（いつ・どこで読まれるか）／仕組み（repo の構造・道具・hook）／他の文脈が混じって解釈が分かれる所。特に「作業する者が毎回正しくやるか」に正しさが懸かる工程を探す（守りを足すほど、飛ばす・省く・申告で済ませる余地も増える）。
  - **同じ原因の他の問題** — 変更範囲は AI が現物で引く。同じ判定・設定・入力・入口を共有し、同じ原因で結果が変わり得る所を、入口から後段・出力まで追う。別の利用先や旧経路にも同じつながりがあれば、関連 repo まで広げる。一律に全量を読み直さない。独立の目が要る時は原因の仮説と対象だけを読む助手へ渡し、書き手の結論や直し方は渡さない。見つけた物は場所つきで持つ。
  - **解決** — 台帳の行に行き先を付ける。古い道は残さず同じ直しで畳む（新旧の切り替え・例外の文を足さない）。採った対策でなく、利用する入口から見た結果を下の「合格の証拠」で確かめる。
  - **未来** — 直した後の姿。意図が果たされ、同じ課題と同じ原因の他の問題が起きない状態で、何が無くなり何が変わるか（作業する者の手順・オーナーの手・決まりの量）を書く。試験を足す段ではない。言えない時は解決がまだ足りていない。
- **まず構造を疑う** — 根治に入る口は「直す仕事を頼まれた時」だけでなく、作業の途中・レビュー・検査・引き継ぎでミスが見つかった時も同じ（画面の見た目の崩れだけは除く）。検査の赤も、検査が守る意図とのずれから入る。ミスは 2 段・3 段上の前提（決まりの形・道具・置き場・聞かせ方）に根がある前提で探し、単発の誤りで片付けない。単発と言ってよいのは、その工程に構造の原因が無いと示せた時だけで、示した所を書く（合意した全体の絵があれば絵のどこを見たか、無ければ言葉で）。直しの案が「確かめを足す」「決まりの文を足す」になったら根に届いていない合図で、原因の段へ戻る。
- **原因の台帳** — 置き場は各社の決まった所（Javis は Notion の「原因の台帳」）。原因と同じ原因の他の問題を 1 つ 1 行にし（欄 `意図｜課題｜原因｜行き先`）、行き先を付ける: `直す窓`（その窓の URL）／`直した`（直しの PR など所在）／`直さない`（オーナーが決めた理由と決定の記録）／`オーナーの判断`（目標の外の穴）。行に元の頼みを書く。目標の中の「直さない」をオーナーに聞くかは §4 の聞く線で決める。直す窓は目標の中の行か「直して」と答えた行にだけ立てる。まとまりの行には同じ `直す窓` を付ける。直す窓は直しが合流したら自分の行を全部 `直した` に替え、立てた窓へ返す。
- **残りの受け皿は原因の台帳 1 つ** — 今の窓・今の PR で片付かなかった物は、名が何でも全部この台帳の行にし、行き先を付ける（PR 本文・返し・会話・表の中だけに置かない）: 根治の外の原因／レビューの `台帳へ` の札／Codex の DEFER と往復を打ち切った時の残り／一時しのぎの恒久の直し／「一部」の残り／相談を出る時の未決・前提待ちと、どの窓も持たなかった論点／選ばれなかった案（`直さない`＋オーナーの理由）／1 枝 1 PR に入らなかった仕事と合流の後の続き／問いにしない道具の都合。PR 本文の「残り」の欄は行の題と行き先を写すだけ（正本は台帳）。
- **誤りが入れない形**（核 §3 の 4 つ）
  - **写す工程を無くす** — 決まりの正本を 1 つにし、使う所がそれを直に読む。人や AI が別の所へ手で写す段を残さない。相手から受ける答えは、機械が確かめられる形（入力と期待の出力の例つき）で受ける。
  - **誤った物が入れない** — 選べる値の外は入口で拒む（型・列挙・検査）。知らない値・欠けた材料・仕組みで表せない決まりは、既定で止まる（黙って既定の値・近い形・前回の値で進めない）。照らす材料が欠けたら「確認済」にせず、その材料に依存する確定・出力だけ止める。影響範囲を切り分けられない時は共有の確定には進まず、独立した調べ・準備は続ける。
  - **正しい道だけが外へ出す** — 外へ出す物は正しい道（決まりから作る処理）だけが作り、その道を通った証明（入力の版・処理の版・検査の結果）を付ける。出す道具は証明の無い物・証明と中身が合わない物を通さない。
  - **防げない物は名指しで人の関所へ** — 機械で防げない物だけを、何を見るかを名指しして人に渡す。
- **合格の証拠** — 振る舞いを変える着手時は、普段の入口から今の経路をたどり、何を置き換え、以前の直しで守った何を維持するかを既存の受入に置く。新しい欄・関所・全量の調べを作らない。振る舞いが同じ文言修正にこの調べは要らない。分かっている実ログ・既存の試験結果・実際の経路で足りるなら再実行しない。足りなければ、普段の入口に届く代表例を選んで不足だけ確かめる。旧版を回すのは原因候補の区別で直す場所が変わる時。誤りの注入はその違いを最もよく示す時に使い、正常な道も妨げないことを見る。恒久に残すのは既存の基準で今後捕まえる価値のあるものだけ。根拠が届かない範囲は未確認とし、そのこと自体を別の作業・合流の関所にしない（既存の安全条件は残す）。
- **再発した時** — 前回の証拠と今回の入口・実際に使った版・判定を比べる。変更が届かなかった／同じ原因の別の道が残った／見え方が同じでも原因が違った、で直す所を変える。症状だけを見て試験や止めを重ねない。
- **一時しのぎ** は ①理由 ②また起きる見込み ③恒久の直し（原因の台帳の行）が揃う時だけ許す。
- **範囲の形** — 迷ったら最新の版と、repo に既に在る型を採る。
- **試験** — 試験から有料の上流（AI の API など）を叩かない。作り物か録った応答で回す。
- **規律と仕組みを足す・直す・畳む** — 足す前に、同じ物が既に在るかを引き、在れば正本を直して指す（写さない）。1 足したら 1 畳む。棚卸しは 残す／直す／畳む の 3 つに分ける。
