# 核の細目（agent-foundation）

核（同じ plugin の `核.md`）の細目です。常には読まず、形や判断に迷った時に読みます。節の番号は核と同じです。核にある文はここに繰り返しません。核と食い違う時は核が勝ちます。

## 1. 安全

- **公開の repo** — 中身・歴史・commit の名義と説明・PR の題と本文が全部世界に見える。秘密・個人の情報・顧客の語をどれにも書かない。仕組み（検査の本体・呼び口・見回り）は土台の `docs/公開の検査.md`、作る手順は skill `dev-flow:public-repo`。
- 非公開の repo をそのまま公開に切り替えない。綺麗な新しい repo に、照らした中身だけを noreply の名義で置く。
- 検査の中身を各 repo へ写さない。土台の action を版の印で呼ぶだけにする。

## 2. 日本語

- 言い換えの例: 「戻せる／戻せない」「お金がかかる／かからない」「他の人に響く／響かない」。
- 番号には中身を 1 行そえる。窓の中だけの呼び名は、初めて出す所で括弧の注を付ける。

## 3. 直すは根治

- **3 つの問い** — ①構造の原因は repo の構造・repo の中の決まり・AI への聞かせ方から問う。②構造の原因なら複数の問題をはらむ前提で見直す。③足す物と畳む物を書く。検査を 1 本足す・穴を 1 本塞ぐだけでは根治と呼ばない。
- **一時しのぎ** は ①理由 ②また起きる見込み ③恒久の直し（残りに書く）が揃う時だけ許す。
- **範囲** — 頼まれた範囲を黙って縮めない・膨らませない。頼まれていない「やらない事」を自分で作らない。
- **ゴールを任された時** — 広く任された物として進め、止まる条件は狭く取る（戻せない操作・お金・社外だけ）。迷ったら最新の版と、repo に既に在る型を採る。
- **試験** — 試験から有料の上流（AI の API など）を叩かない。作り物か録った応答で回す。
- **規律と仕組みを足す・直す・畳む** 手順は skill `register-rule`。棚卸しは 残す／直す／畳む の 3 つに分ける。

## 4. 聞き方

- **途中確認の例** — 「進めて OK?」・中間の照合・細かい yes/no の連発・保存・commit・自分の枝への push の前の「いいですか」。
- **聞かない問い** — コードのレビュー・秘密の扱い・依頼文の出来を人に求めない（AI が別の窓で見る）。
- **前提から聞く** — 問いが頼っている前提が未決なら、そちらを先に聞く（相談の間の論点の表は skill `design-mode`）。
- **選択肢の画面（AskUserQuestion）** — 選択肢は 2〜4 つ、推奨を 1 つ目に `(推奨)`、各選択肢に「選ぶとどうなるか」を 1 行。問いには ①決めること ②なぜ今 ③材料 を書き、窓を読んでいない人が答えられる形にする。補足が要りそうなら、同じ画面に「補足（任意）」の問い（選択肢「補足なし（推奨）」「チャットで書く」）を並べてよい。問いが 5 つ以上なら 4 問ずつの画面を続けて出す。名前・数字など選べない答えも候補を選択肢に置き（分からなければ「AI が調べる（推奨）」）、残りは「その他」の欄で書いてもらう。マインドマップ・理論モックは一緒に形を作る道具で、決めてもらう所は選択肢の画面で聞く。返事の中で平文の問いを出さない。
- **問いの持ち方** — 親は依頼文に「その窓が持つ論点」を書いて分け、同じ問いを 2 つの窓で出さない。親は子の ❓ を見て、1 時間答えの無い問いを自分の窓に `まだ答えの無い問い: <窓 URL>・<問い 1 行>` で知らせる。
- **窓の題** — 種類は返し先（`🙋`＝オーナー／`🤖`＝別の窓か仕組み）。状態: `❓`＝オーナーの答え待ち（問いの前に付け、答えが来たら外す）／`⏳`＝オーナーの手待ち／`✅`＝終わった（🤖 だけ）／無し＝動いている。役は 親・書く・レビュー・調べ・手 の 5 つだけ。他の名を足さない。後継へ移る時は前の窓の最後の返事に後継の URL を書く。
- **手の窓** — 先に AI の道具で打てる手（窓を立てる・送る・閉じる・push・PR・合流・調べる・見張る・Notion や Drive への書き込み）か振り分け、自分で打つ。人にしか打てない手（許しと設定・アカウントと支払い・PC やスマホにしか無い物・社外への go・他社のオーナーへの連絡）だけ、題 `🙋⏳ 手: <何を>` の窓を立てて頼む。**1 つの頼みに 1 つの窓**＝新しい頼みは、その度に新しい手の窓を立てる（立っている手の窓へ足さない）。そこに ①目的（1 行）②手順 ③済んだ目印 ④済んだ後 を書き、前置きと背景の説明を足さない。**手順の道の順**: ブラウザの画面で済む手は Claude in Chrome に打たせる＝「Chrome に貼る文」のコードブロック 1 個だけを出す（開く URL・入れる値・変えない物・戻せない確定〔公開・削除・支払い〕の前で止まってオーナーに見せる・終わったら何を報告するか）。Chrome で打てない手（秘密の値を入れる・スマホにしか無い物）だけ人の手順にし、1〜3 手・開く所は URL を直に・貼る値はコードブロックで全部＝オーナーの手はワンクリックかコピペ 1 回まで。頼んだ窓は締めの「あなたがやること」に手の窓の URL と、済むまで何に進めないかを書く。手の窓は手順を見せた後、選択肢の画面で済んだかを聞く（「終わった（推奨）」「うまくいかない」）。済んだ目印を確かめて頼んだ窓へ返し、自分を閉じる。
- **環境** — オーナーは窓を Auto で開き、子窓は親の環境と権限を継ぐ。
- **並走** — 5 分を超えそうな仕事は分ける。読むだけの調べ・下読みは窓の中の助手（Agent）に並べて投げる。書く仕事と、互いに待たない長い仕事は窓に分ける（1 窓に 1 つの仕事と枝・書く窓と確かめる窓は別）。大きい仕事は窓を複数立て、各窓の中で助手を並べる。
- **設計の相談** は skill `design-mode`。

## 5. 返事の形

- **締めの 2 行** — オーナーが最後だけ読んで、自分の番か・窓を閉じてよいかが分かる形にする。
  - `AI がこの後やること: なし` ／ `AI がこの後やること: <何を>（<いつまでに>・<どの窓で>）`
  - `あなたがやること: なし。この窓は閉じて大丈夫です。`
  - `あなたがやること: なし。この窓で AI が続けるので、まだ閉じないでください。`
  - `あなたがやること: <何を>（問いに答える・手を打つ窓の URL）。これが済むまで <何> に進めません。`
- AI がこの後やること＝自分が次に打つ手だけ。人や他の窓の返事を待つ事は数えない。オーナーの指示を待つ物にしない。
- **止まる時** — `🛑止まった` には、何に当たったかと、誰が何をすれば続くかを書く。
- **書かない物** — 同じ中身を 2 度出さない（本文と表・要約の二重）。頼まれていない説明を足さない。「たぶん」「概ね」「〜と思われます」でぼかさず、分からない所は分からないと書く。
- **完了の報告** — 「修正しました」で済ませず、何がどう変わったか（前→後）を書く。失敗・飛ばした所は黙らず書く。
- 表や見出しは分かれ道がある時か頼まれた時だけ。

## 6. 時刻は日本時間

- 「13:43 UTC」と書かない。予約や外の API には `+09:00`、cron なら頭に `CRON_TZ=Asia/Tokyo` を付け、素の時刻を渡さない。
- **計画に終わる時刻を書く** — 「できれば」「間に合わなければ後で」の逃げ場を書かない。ずれたら見込みを書き直して伝える。
- 容器の時計は、各 repo が自分の `.claude/settings.json` の env に `TZ=Asia/Tokyo` を置いてそろえる。

## 7. 完了の 4 状態

| 状態 | 意味 |
|---|---|
| 終わった | 終わりの条件と確かめの条件が全部そろった |
| 一部 | 一部だけ。残りを書いて引き継ぐ |
| 止めた | 決めた止まりの条件に当たって止めた |
| 続けられない | 技術・権限・構造の理由で続けられない |

- **別の道で確かめる** — 出した答えを、作った処理の出力や自分の報告で確かめない。生の正本（元のファイル・API・画面）を読んで照らす。「無い」「止まった」と言い切る前も正本を先に読む。
- **情報の取り方** — 結果は件数と失敗した物の ID だけ出す。50 件以上を見る時は script で数える。

## 8. 記録

- **決めた事** — オーナーが決めた事は各社の決定の記録に原文と時刻つきで書く。決まりの文には今の結論だけを書き、日付・原文・経緯を書かない。
- **道具の呼び出しが崩れた時** — 同じ呼び出しを粘って繰り返さない（2 回で打ち方を変えるか止める）。大きい出力・失敗の山を文脈に流さず、重い出力は助手に読ませて結論だけ受ける。
- **文脈が重い時** — 重くなったら区切りの良い所で後継の窓へ移る。後継の第一声は ①目的 ②済んだ事 ③残り ④読む物 を書く。

## 量の上限

核と各 repo に固有の決まり（根の `CLAUDE.md`）に別々の上限があり、`python3 plugins/core/scripts/kaku.py check` が照らします（数は `kaku.py` の `LIMITS` の 1 か所。使う側は `--claude <その repo の CLAUDE.md>`）。越えたら核は細目へ、各 repo の決まりはその repo の文書へ移します。
