# 見張りごとの細目（guard）

目次（SKILL.md）の表の見張りごとに、出来事・する事・止められた・知らされた時の直し方の全文。目次の表に書いた形と直し方はここに重ねない。

## irreversible（離席中の戻せない操作）

- 出来事: PreToolUse
- する事: この窓で選択肢モーダルが答えのないまま閉じ、オーナーがまだ戻っていない間だけ、DB の破棄・メールの送信・Notion の物理削除・git で戻せない rm -r を止める（作業場〔一時の置き場〕と変更の無い作業部屋の掃除は通す）
- 直し方: 戻せる作業を先に進める。その操作が要るなら同じ問いをモーダルで出し直し、答えが返ってから行う（答えが返るかオーナーが打てば解ける）

## paid_upstream（試験から有料の上流）

- 出来事: PreToolUse
- する事: 試験らしい path へ書く中身に、AI の API の鍵名・公式のエンドポイントがあれば止める。Bash で試験らしい path へ書く形（`>`・`>>`・`tee`・`sed -i`／`perl -i` の的）も、命令の文全体（heredoc の中身を含む）に印があれば止める
- 直し方: 既定を録画の再生か偽物にする。本物が要るなら環境変数 1 本で切り替える関所を通し、その file に `PAID_UPSTREAM_GUARD` を書く

## qa_page（問いのページの検査）

- 出来事: PreToolUse
- する事: Artifact の publish（file_path と `files` で足す file のうち .html・.json）の前に、そのページが問いのページ（型の印 `<body data-dest>`・`CustomEvent('qa:submit')`／`<script>` の JSON に `questions`・`qs` と選択肢／radio と答えを外へ出す仕組み〔form・sendPrompt・window.claude の書く呼び出し・POST 等の fetch・clipboard への書き込み〕の両方／問いのデータの JSON。読むだけの fetch や表示の切り替えの radio は数えない）なら qa-html の `check.mjs` をかけ、赤なら止める。検査が見つからない・node が無い・検査が壊れた時も止める（緑を確かめられない物は出さない）
- 直し方: ①聞く前に引き（細目 §4）、答え済み・資料で決まる・道具の都合の問いを消す ②オーナーへの問いなら選択肢の画面で聞く ③ページで出すなら skill `docs-kit:qa-html` の型（`check.mjs --template` が出す正本）で作り直し、止めた文に出る `node <check.mjs> <file>` が緑になってから出し直す。検査が無いなら plugin docs-kit を guard と同じ版で入れ直し、node を入れる（別の版の検査・path を渡す口では照らさない）。問いのページでないのに止まった時だけ、値の表の `qa_page_exempt` で外す（PR とレビューを通す）

## ask_shape（選択肢の画面の問いの形）

- 出来事: PreToolUse
- する事: AskUserQuestion の画面が人に出る前に問いを照らし、崩れていれば AI だけを止める（人の操作は止めない）。`long` と `rec` の形は目次の表。`inner`＝問い・見出し・選択肢に AI の中の言葉らしい字（`E02`・`Q202611-67` のような番号・`#616`・`v0.21.0` のような版・file 名・path・snake_case や `直し_0020` のような識別子・窓の id・commit の印・`` ` `` で囲んだ字。URL は数えない）／`topic`＝2 問以上の画面で、問いと見出しの語（漢字・カタカナ・英字の 2 字の並び・送り仮名は詰める）を共にしない組に分かれる
- 直し方: `long`: 問いの文は何を決めるかの 1 文。背景と材料は先にチャットで見せ、違いと選ぶとどうなるかは選択肢の説明へ（細目 §4）。`inner`: それが何かを日常の言葉で言い換える。`topic`: 話題ごとに画面を分けて続けて出す（捨てない）。同じ話題なら問いか見出しにその語を入れる。字の形だけ当たった誤りは値の表の `ask_term_allow`（字）か `ask_shape_exempt`（問いの文）に足す（PR とレビューを通す）。`rec`: 印は作り方の分かれ道の問いだけに 1 つ、1 つ目の見出しの末に `(推奨)` の形で付け、推奨しない訳などは説明へ書き、理由はその選択肢の説明へ（細目 §4「推奨の印」）。推せる案が 2 つなら問いを分けるか印を外す。意図・考えを聞く問いと済んだかの確認には付けない。中の言葉の見分け（`ask_shape.inner_terms`）は session-watch の返事の見張りも直に呼ぶ（`ask_term_allow` と `ask_inner_terms_extra` は両方に効く。返事では file 名・path・版・英字の識別子を数えない）。

## ask_shape の notice（推奨の印の知らせ）

- 出来事: PostToolUse
- する事: 推奨の印が付いた選択肢の画面の問いの文が、済んだかの確認（「終わりましたか」「送りましたか」「済んでいますか」「反映されましたか」等）か意図・考えを聞く形（「なぜ」「どういう意図」「意図は」「どう思い」「お好み」等）に見えたら、画面の後に知らせる（止めない・形は `ask_rec_notice_kinds` で替える）
- 直し方: 答えが印に引かれて寄っていないかを確かめ（済んだかは AI が確かめられる所を先に確かめる）、次から印を外す。字の形だけ当たった誤りは値の表の `ask_rec_notice_exempt`（問いの文）に足す。値の表の正規表現が壊れていると、その形を照らせていないと知らせる（他の形は照らす）

## pick_one（1 つだけ選ばせる問い）

- 出来事: PreToolUse
- する事: 選択肢の画面（AskUserQuestion）で、1 つだけ選ぶ問い（multiSelect が偽）の文が、これからやる物・手を付ける順を選ばせる意志の形（どれを進めますか・何から始めますか・どの論点を先に詰めますか・どれを優先しますか）か、原因の見立てを選ばせる形（原因はどれだと思いますか・どれが原因に近いですか）なら止める。全部を選べる問い・選択肢に全部やる道（全部・すべて・両方・同時・並行）が在る問いは通す。過去（〜しましたか）・受け身（〜されますか）・「が」を挟む形・意味や事実の問い（どちらの意味ですか・原因はどの資料に書いてありますか）は当てない。画面はまだ人に出ていない＝止まるのは AI の問いだけ
- 直し方: 直し方の①〜④は目次の表。推奨の印は作り方の分かれ道の問いだけ（細目 §4「推奨の印」）で、やり方・全部やるかを問う選択肢には付けない。誤って止まった（意図・事実・意味の問い）時は問いの文を「どちらが正しいか／どの意味か／どちらにするか」の形に直して出し直し、同じ形で何度も止まるなら値の表の `ask_pick_one_exempt` に足す（PR とレビューを通す）

## outbound（外へ渡す道具の入力）

- 出来事: PreToolUse・PostToolUse（知らせる）
- する事: 人や他の窓へ渡る道具の入力を出る前に照らし、崩れていれば AI だけを止める（人の操作は止めない）。`secret`＝MCP の道具（`mcp__…`）・Artifact・SendMessage の入力の全部の字と Artifact で出す file の中身に、鍵・トークンの形（正本は公開の検査 `public-guard/guard.py` の `SECRET_PATTERNS` を直に読む。見つからない時は止める。大きすぎる〔2,000,000 バイト超〕・開けない file は照らした扱いにせず、出した後に PostToolUse が名と訳を知らせる＝止めない）／`number`＝send_message・SendMessage の文と create_session の頼みの文に、番号（`E02`・`#3` の形）だけで中身の名の無い文（番号の見分けは ask_shape の中の言葉、中身の語は ask_shape の話題の語を直に呼ぶ）／`title`＝set_session_title と create_session の title が `<種類><状態> <作業名>` でない（種類×状態の表に無い印・表に無い組み合わせ）・手の窓（`✋ <何を>`）を立てる頼みの文に目的・手順・済んだ目印・済んだ後が揃わない（正本は session-watch の `TITLE_TABLE`・`title_shape`・`HAND_PARTS`）
- 直し方: `secret`: 鍵の値を文から抜き、名だけ書く。鍵が要る相手には環境の秘密（request_credential）で渡す。正本が無いと出たら土台の plugin を市場から入れ直す（`AF_PUBLIC_GUARD` で path を渡せる）。作り物の見本だけ値の表の `outbound_secret_allow` で外す。`number`: 直し方は目次の表。誤りは `number_request_exempt`。`title`: skill `session-watch:title-mark` の形に直す。手の窓は頼みの文に 4 欄を書く

## spec_gate（設計書の型の gate を直に呼ぶ手）

- 出来事: PreToolUse
- する事: Bash の命令に設計書の型の gate `check_spec_doc.py` と `--lock` の両方が在れば止める（封の入口 `seal.py` は 15 §6 の決定照合が済むまで gate を呼ばない。直に呼ぶとその照合を飛ばせた）。AI の道具の呼び出しだけを止める（人の手の命令は止めない）。`--lock` の無い呼び出し（各 step の機械チェック・`--verify-receipt`・`--stamp`）は通す
- 直し方: spec-doc の入口から封をする: `python3 <spec-doc の skill の dir>/seal.py <設計書dir>`（照合だけなら `--match-only`）。照合で止まったら 15 §6 の行を直す（seal.py の直し方の文）

## pr_text（GitHub へ出す前の PR の文）

- 出来事: PreToolUse・PostToolUse（知らせる）
- する事: GitHub の道具（名の末尾で見る: `create_pull_request`・`update_pull_request`・`add_issue_comment`・`update_issue_comment`・`add_reply_to_pull_request_comment`・`pull_request_review_write`・`add_comment_to_pending_review`・`issue_write`。MCP から出す commit の説明＝`merge_pull_request`・`push_files`・`create_or_update_file`・`delete_file` は `public` だけ）の文を、出す前に照らし AI だけを止める。`verdict`＝コメントがレビューの判定（どの行かに `レビューした窓: … 判定: green|red` が揃うか verdict の見出し〔# の数・大小を問わない〕が在る。文中に「判定: green」と書いた普通のコメント・「レビューした窓は…」の文・引用の中は見ない）なら checker の `verdict_form.py` を直に呼び、赤なら止める／`cleanup`＝PR の本文に、dev-flow の preimpl-cleanup の `整地受領証.template.md` の見出し（名は雛形から読む・`##` でも `###` でもよい）が全部在り、雛形の `〔…〕` が残っていない。整地の要らない PR は `整地: 不要（<訳>）` の 1 行で通る／`words`＝PR の題・本文に窓の id（`session_01…`）がそのまま在る（本文の頭の塊〔最初の空行まで〕の `書いた窓:` の欄〔PR の型から畳んだ・使う側の型に残る間〕・コード・URL の中は数えない。job・検査の欄や頭の塊の外の行は数える。`親窓:` の欄は PR の型から畳んだ＝窓の親はサーバの記録 `get_session` の `parent_session_id`。使う側の型に残る間は頭の塊の `親窓:` も数えない）／`public`＝公開の repo（窓の repo の取り出しの workflow が action `public-guard` を呼ぶ・値の表 `public_repos_extra`）なら題・本文を `public-guard/guard.py --text` に渡す（置かない語の表は public-guard を呼ぶ step の `with:` の `deny-words-file`・別の step・job の物は読まない。開けない・壊れた〔読み手が jobs の形を読めない〕workflow は黙って飛ばさず、出した後に PostToolUse が名と訳を知らせる＝止めない）。判定の道具・雛形・公開の検査（と workflow が名指す置かない語の表）が見つからない・壊れた時と、照らしの途中で壊れた時（`broken`・一時の置き場に書けない等）も止める
- 直し方: `verdict`: skill `checker:review-pr` の形で書き直し、`verdict_form.py` が exit 0 になってから出す。`cleanup`: `## 整地（根治の段）` の下に雛形の見出しで書く（skill `dev-flow:preimpl-cleanup`）。振る舞いを変えない PR（誤字・記録だけ・版だけ等）は欄の代わりに `整地: 不要（<なぜ要らないか>）`。`words`: 窓の id は開けるリンク（`https://claude.ai/code/<id>`）にして役の名を添えるか、役の名だけにする。`public`: 当たった所を書き直す（GitHub の本文は書き替えても古い版が編集の履歴に公開で残る）。道具が無い時は plugin checker・dev-flow を入れる（`AF_VERDICT_FORM`・`AF_CLEANUP_TEMPLATE`・`AF_PUBLIC_GUARD` で path を渡せる）。整地を PR 本文の外に置く repo・言葉の照らしが合わない repo だけ、値の表の `pr_cleanup_exempt_repos`・`pr_words_exempt_repos` で外す（PR とレビューを通す）。判定の形と公開の検査は外さない

## values_keys（値の表の知らない鍵）

- 出来事: PreToolUse・SessionStart
- する事: 使う側の repo の `config/skill-values.json` を Write・Edit・MultiEdit で書いた後に、土台が読まない鍵（土台が畳んだ・名を変えた鍵か書き違い・型の違う値）が残り、書く前より減っていなければ止める（AI の書き込みだけ・人の手は止めない）。起動の時に在れば知らせる（止めない）。知っている鍵・畳んだ鍵・型の正本は値の表の 1 本の口 `lib/skill_values.py` と鍵の一覧 `lib/schema.json`（土台の `skill-values/`・SKILL.md の「repo ごとの値」の表と同じ。照らすのは頭が土台の plugin の名か `common` の所だけ・`_` で始まる注は通す）
- 直し方: 名指しされた鍵を消すか今の名の鍵へ移し（畳んだ鍵は理由と直し方が出る）、その repo の PR で直す。repo が自分で持つ値なら土台の plugin の名と `common` の外の頭へ移す。土台の道具が今も読む鍵なのに一覧に無いだけなら、土台の `skill-values/schema.json` と SKILL.md の表に行を足す PR を出す。手で照らす口: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/values_keys.py" config/skill-values.json`（問題の鍵が在れば exit 1）

## prior_ask（聞く前に引いた跡）

- 出来事: PreToolUse
- する事: AskUserQuestion の画面が人に出る前に、会話ログの最後の頼み（人か親の窓が打った行）より後に、決定の記録と問いの表を引いた跡（値の表 `ask_prior_lookup` の正規表現に「道具の名 + 入力の JSON」が当たる道具の呼び出し）があるかを見る。無ければ AI だけを止める（止める回数は目次の表）。`ask_prior_lookup` が無い repo は引いたかを見分けられないので、窓ごとに 1 回だけ止める
- 直し方: 細目 §4 の「聞く前に引く」をして、答え済み・資料で決まる・道具の都合の問いを外し、引いた結果を問いの前にチャットで 1 行書いて出し直す。引けない時は 2 回止まった後に通るので、引けなかった事を問いの前に書く。引いたのに止まった時は使った道具の形を `ask_prior_lookup` に、引く要の無い問い（手の作業が済んだかの確かめ等）は `ask_prior_exempt` に足す（PR とレビューを通す）

## unanswered（未回答の台帳）

- 出来事: PostToolUse・SessionStart
- する事: モーダルが答えのないまま閉じた問いを台帳に積み、寿命（`unanswered.py` の `LEDGER_TTL_HOURS`）の間、次の窓の冒頭に全部を渡す（頭の何件かで切らない）。寿命を過ぎた問いと文面の無い行は冒頭で一度知らせてから降ろす（控えは expired_recent）。人のいない窓では知らせず控えへ移すだけで、次の人のいる窓が一度知らせる。`list` は寿命切れ・文面の無い行・控えへ移した行に印を付ける。答えが返れば降ろす（同じ問いの見分けは文面の一致か含有だけ。字の形で別の問いを結ばない）。子の窓の問いも同じ
- 直し方: 1 件ずつ、今の窓の流れで扱う: ①答え済み・もう要らない → 出さずに `python3 <unanswered.py> drop <key> --why <訳>` で降ろす（渡された文に path が出る・`list` で一覧）②今の頼みと関わる → チャットで前提を 1〜2 文添えてから出し直す（問いの文は短く言い直してよい。言い直した問いに答えが返ったら、元の問いを drop で降ろす＝機械は結ばない）③関わらない → 冒頭で画面に出さず、締めの「あなたがやること」に 1 行で知らせ、求められたら出す。1 画面に出す問いの数は渡された文と細目 §4 の形のとおり。言い方だけ変えて何度も出さない
