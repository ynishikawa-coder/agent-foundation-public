# ask_shape（選択肢の画面の問いの形・推奨の印の知らせ）

- 出来事: PreToolUse（止める）・PostToolUse（推奨の印の知らせ・止めない）
- する事（PreToolUse）: AskUserQuestion の画面が人に出る前に問いを照らし、崩れていれば AI だけを止める（人の操作は止めない）。`long`＝問いの文が `ask_question_max_chars` 字（既定 60）か `ask_question_max_sentences` 文（既定 1）を越える／`inner`＝問い・見出し・選択肢に AI の中の言葉らしい字（`E02`・`Q202611-67` のような番号・`#616`・`v0.21.0` のような版・file 名・path・snake_case や `直し_0020` のような識別子・窓の id・commit の印・`` ` `` で囲んだ字。URL は数えない）／`topic`＝2 問以上の画面で、問いと見出しの語（漢字・カタカナ・英字の 2 字の並び・送り仮名は詰める）を共にしない組に分かれる／`rec`＝推奨の印の付け方: 選択肢の見出しに推奨の語（推奨・おすすめ・お勧め・お薦め・オススメ・イチオシ・recommend・suggested）が決まりの形（見出しの末の `(推奨)`・`（推奨）`・`(Recommended)`）以外で在る（「非推奨」「推奨なし」「推奨どおり」も見出しでは止まる・説明の文の中は数えない）・1 問に 2 つ以上・1 つ目でない選択肢・「分からない」の選択肢（見出しの頭が分からない・分かりません・知らない・不明・Unknown・I don't know）に在る
- する事（PostToolUse）: 推奨の印が付いた選択肢の画面の問いの文が、済んだかの確認（「終わりましたか」「送りましたか」「済んでいますか」「反映されましたか」等）か意図・考えを聞く形（「なぜ」「どういう意図」「意図は」「どう思い」「お好み」等）に見えたら、画面の後に知らせる（止めない・形は `ask_rec_notice_kinds` で替える）

## 止められた・知らされた時の直し方

- 止められた時: `long`: 問いの文は何を決めるかの 1 文。背景と材料は先にチャットで見せ、違いと選ぶとどうなるかは選択肢の説明へ（細目 §4）。`inner`: それが何かを日常の言葉で言い換える。`topic`: 話題ごとに画面を分けて続けて出す（捨てない）。同じ話題なら問いか見出しにその語を入れる。字の形だけ当たった誤りは値の表の `ask_term_allow`（字）か `ask_shape_exempt`（問いの文）に足す（PR とレビューを通す）。`rec`: 印は作り方の分かれ道の問いだけに 1 つ、1 つ目の見出しの末に `(推奨)` の形で付け、推奨しない訳などは説明へ書き、理由はその選択肢の説明へ（細目 §4「推奨の印」）。推せる案が 2 つなら問いを分けるか印を外す。意図・考えを聞く問いと済んだかの確認には付けない
- 推奨の印を知らされた時: 答えが印に引かれて寄っていないかを確かめ（済んだかは AI が確かめられる所を先に確かめる）、次から印を外す。字の形だけ当たった誤りは値の表の `ask_rec_notice_exempt`（問いの文）に足す。値の表の正規表現が壊れていると、その形を照らせていないと知らせる（他の形は照らす）

## 値の表の鍵

repo の根の `config/skill-values.json` の `"guard"` に書く（既定はこの見張りの file の頭の `VALUES`）。

```json
{
  "guard": {
    "ask_question_max_chars": 60,
    "ask_question_max_sentences": 1,
    "ask_inner_terms_extra": ["例の関所"],
    "ask_term_allow": ["^ISO\\d+$"],
    "ask_topic_stopwords_extra": [],
    "ask_shape_exempt": [],
    "ask_rec_notice_kinds": {"済んだかの確認": ["終わりましたか"]},
    "ask_rec_notice_exempt": []
  }
}
```

## 射程の外

- 選択肢の画面の問いの形の見張りは字の形の推し量り（意味は読まない）。日常の言葉で書いた内輪の呼び名（「例の関所」など）は値の表の `ask_inner_terms_extra` に足すまで素通り。日常の英数字の名（`B202` の部屋・`COVID19`・`見積書.xlsx`・`Node.js`・`Wi-Fi/LAN/USB` など）も字の形で止まる（`ask_term_allow` で外す）。話題の見分けは語の重なりなので、別の話題でも同じ語（「検査」など）を共にすれば通り、同じ話題でも語を共にしなければ止まる（見出しに話題の語を入れて直す）。案や前提をチャットで先に見せたかと、オーナーが決めなくてよい事を聞いていないかは見ない。推奨の印は見出しの推奨の語（上の並び）の形・数・位置・「分からない」だけを見て（並びの外の言い回し〔「一押し」「ベスト」など〕は素通り・見出しの中身として推奨の語を使う「推奨環境に合わせる」も止まるので言い換える）、その問いが印を付けてよい作り方の分かれ道かは止めては見ず、済んだか・意図の形の字が在る時だけ画面の後に知らせる（字の形の推し量り＝言い回しを変えれば素通り・作り方の問いが「〜しましたか」で知らされることもある）。
- Artifact の文（報告・マインドマップ・理論モック）の言葉は照らさない。オーナーに出した報告 4 枚に中の言葉の見分けを当てると 4 枚とも止まり、当たったのはオーナーに要る本当の file 名・path が主だった（核 §2「物は本当の名で呼ぶ」と食い違う）ため。
