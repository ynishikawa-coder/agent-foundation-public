# 守りの hook（guard）

1 本の入口（`${CLAUDE_PLUGIN_ROOT}/scripts/guard.py`）を、プラグインの `hooks/hooks.json` が 3 つの出来事（PreToolUse・PostToolUse・SessionStart）で回す。止めるのは PreToolUse（AI の道具の呼び出し）だけで、他は隣に文を出すだけ（AI の締めを差し戻す口は持たない）。どれも壊れた時は黙って通す。止められた・知らされた時は下の直し方でその場を出し直すだけで済ませず、その形が出た原因を細目 §3「まず構造を疑う」で探して直す。

| 見張り | 出来事 | する事 | 止められた・知らされた時の直し方 |
|---|---|---|---|
| irreversible（離席中の戻せない操作） | PreToolUse | この窓で選択肢モーダルが答えのないまま閉じ、オーナーがまだ戻っていない間だけ、DB の破棄・メールの送信・Notion の物理削除・git で戻せない rm -r を止める（作業場〔一時の置き場〕と変更の無い作業部屋の掃除は通す） | 戻せる作業を先に進める。その操作が要るなら同じ問いをモーダルで出し直し、答えが返ってから行う（答えが返るかオーナーが打てば解ける） |
| paid_upstream（試験から有料の上流） | PreToolUse | 試験らしい path へ書く中身に、AI の API の鍵名・公式のエンドポイントがあれば止める。Bash で試験らしい path へ書く形（`>`・`>>`・`tee`・`sed -i`／`perl -i` の的）も、命令の文全体（heredoc の中身を含む）に印があれば止める | 既定を録画の再生か偽物にする。本物が要るなら環境変数 1 本で切り替える関所を通し、その file に `PAID_UPSTREAM_GUARD` を書く |
| qa_page（問いのページの検査） | PreToolUse | Artifact の publish（file_path と `files` で足す file のうち .html・.json）の前に、そのページが問いのページ（型の印 `<body data-dest>`・`CustomEvent('qa:submit')`／`<script>` の JSON に `questions`・`qs` と選択肢／radio と答えを外へ出す仕組み〔form・sendPrompt・window.claude の書く呼び出し・POST 等の fetch・clipboard への書き込み〕の両方／問いのデータの JSON。読むだけの fetch や表示の切り替えの radio は数えない）なら qa-html の `check.mjs` をかけ、赤なら止める。検査が見つからない・node が無い・検査が壊れた時も止める（緑を確かめられない物は出さない） | ①聞く前に引き（細目 §4）、答え済み・資料で決まる・道具の都合の問いを消す ②オーナーへの問いなら選択肢の画面で聞く ③ページで出すなら skill `docs-kit:qa-html` の型（`check.mjs --template` が出す正本）で作り直し、止めた文に出る `node <check.mjs> <file>` が緑になってから出し直す。検査が無いなら plugin docs-kit を guard と同じ版で入れ直し、node を入れる（別の版の検査・path を渡す口では照らさない）。問いのページでないのに止まった時だけ、値の表の `qa_page_exempt` で外す（PR とレビューを通す） |
| ask_shape（選択肢の画面の問いの形） | PreToolUse | AskUserQuestion の画面が人に出る前に問いを照らし、崩れていれば AI だけを止める（人の操作は止めない）。`long`＝問いの文が `ask_question_max_chars` 字（既定 60）か `ask_question_max_sentences` 文（既定 1）を越える／`inner`＝問い・見出し・選択肢に AI の中の言葉らしい字（`E02`・`Q202611-67` のような番号・`#616`・`v0.21.0` のような版・file 名・path・snake_case や `直し_0020` のような識別子・窓の id・commit の印・`` ` `` で囲んだ字。URL は数えない）／`topic`＝2 問以上の画面で、問いと見出しの語（漢字・カタカナ・英字の 2 字の並び・送り仮名は詰める）を共にしない組に分かれる／`rec`＝推奨の印の付け方: 選択肢の見出しに推奨の語（推奨・おすすめ・お勧め・お薦め・オススメ・おススメ・イチオシ・recommend・suggested。大小を問わない・確認ページの検査 qa-html の `check.mjs` の `recommend` も同じ並び）が決まりの形（見出しの末の `(推奨)`・`（推奨）`・`(Recommended)`）以外で在る（「非推奨」「推奨なし」「推奨どおり」も見出しでは止まる・説明の文の中は数えない）・1 問に 2 つ以上・1 つ目でない選択肢・「分からない」の選択肢（見出しの頭が分からない・分かりません・知らない・不明・Unknown・I don't know）に在る（この見分け `ask_shape.is_dunno` は session-watch の「分からない」の無い問いの見張りも直に呼ぶ）／`premise`＝画面の前のチャット（会話ログの、人が打った最後の頼みより後の AI の文）に、行頭が `具体例:` と `判断の物差し:` の 2 行（箇条の印・太字は可・中身が空は数えない）が無い（会話ログが読めない時と助手の中は照らさない） | `premise`: 問いが懸かる実物の 1 例を `具体例: …`、どんな理由で選んでほしいかを `判断の物差し: …` の行でチャットに書いて確かめてから、同じ問いを出し直す（細目 §4「見せてから聞く」）。照らさない問いは `ask_shape_exempt` に足す。`long`: 問いの文は何を決めるかの 1 文。背景と材料は先にチャットで見せ、違いと選ぶとどうなるかは選択肢の説明へ（細目 §4）。`inner`: それが何かを日常の言葉で言い換える。`topic`: 話題ごとに画面を分けて続けて出す（捨てない）。同じ話題なら問いか見出しにその語を入れる。字の形だけ当たった誤りは値の表の `ask_term_allow`（字）か `ask_shape_exempt`（問いの文）に足す（PR とレビューを通す）。`rec`: 印は作り方の分かれ道の問いだけに 1 つ、1 つ目の見出しの末に `(推奨)` の形で付け、推奨しない訳などは説明へ書き、理由はその選択肢の説明へ（細目 §4「推奨の印」）。推せる案が 2 つなら問いを分けるか印を外す。意図・考えを聞く問いと済んだかの確認には付けない。中の言葉の見分け（`ask_shape.inner_terms`）は session-watch の返事の見張りも直に呼ぶ（`ask_term_allow` と `ask_inner_terms_extra` は両方に効く。返事では file 名・path・版・英字の識別子を数えない）。 |
| ask_shape の notice（推奨の印の知らせ・判断を頼む理由の知らせ＝部品 ask_basis） | PostToolUse | 推奨の印が付いた選択肢の画面の問いの文が、済んだかの確認（「終わりましたか」「送りましたか」「済んでいますか」「反映されましたか」等）か意図・考えを聞く形（「なぜ」「どういう意図」「意図は」「どう思い」「お好み」等）に見えたら、画面の後に知らせる（止めない・形は `ask_rec_notice_kinds` で替える）。もう 1 つ: AskUserQuestion の画面が出た後に、会話ログでその画面の前（最後の頼みか 1 つ前の画面より後）に AI が書いた文に、行の頭の `判断を頼む理由:`（「：」も可）が在るかを見て、無ければ知らせる（止めない・`具体例:` は `premise` が画面の前に照らすので見ない）。済んだかの確かめだけの画面・助手の中・会話ログが読めない時は黙る。理由の中身が線に当たるかは読まない | 答えが印に引かれて寄っていないかを確かめ（済んだかは AI が確かめられる所を先に確かめる）、次から印を外す。字の形だけ当たった誤りは値の表の `ask_rec_notice_exempt`（問いの文）に足す。値の表の正規表現が壊れていると、その形を照らせていないと知らせる（他の形は照らす）。判断を頼む理由: 答えを待つ間にチャットで `判断を頼む理由:` の行を足す＝オーナーだけの情報・言葉の解釈・戻せない・お金・社外のどれか。理由が書けない問いだったなら、答えを待たず AI が決めて進め、そう書く（細目 §4「見せてから聞く」） |
| pick_one（1 つだけ選ばせる問い） | PreToolUse | 選択肢の画面（AskUserQuestion）で、1 つだけ選ぶ問い（multiSelect が偽）の文が、これからやる物・手を付ける順を選ばせる意志の形（どれを進めますか・何から始めますか・どの論点を先に詰めますか・どれを優先しますか）か、原因の見立てを選ばせる形（原因はどれだと思いますか・どれが原因に近いですか）なら止める。全部を選べる問い・選択肢に全部やる道（全部・すべて・両方・同時・並行）が在る問いは通す。過去（〜しましたか）・受け身（〜されますか）・「が」を挟む形・意味や事実の問い（どちらの意味ですか・原因はどの資料に書いてありますか）は当てない。画面はまだ人に出ていない＝止まるのは AI の問いだけ | 相談で出た事は全部やる。①順と窓の分け方は AI が決めて進める（問わない）②全部を選べる形にする（multiSelect か「全部」）③原因は AI が見立てて示し（合意した全体の絵があれば絵の上で）、合っているかを問う ④調べれば決まる順は問わずに AI が決めて全部進める。推奨の印は作り方の分かれ道の問いだけ（細目 §4「推奨の印」）で、やり方・全部やるかを問う選択肢には付けない。誤って止まった（意図・事実・意味の問い）時は問いの文を「どちらが正しいか／どの意味か／どちらにするか」の形に直して出し直し、同じ形で何度も止まるなら値の表の `ask_pick_one_exempt` に足す（PR とレビューを通す） |

| spec_gate（設計書の型の gate を直に呼ぶ手） | PreToolUse | Bash の命令に設計書の型の gate `check_spec_doc.py` と `--lock` の両方が在れば止める（封の入口 `seal.py` は 15 §6 の決定照合が済むまで gate を呼ばない。直に呼ぶとその照合を飛ばせた）。AI の道具の呼び出しだけを止める（人の手の命令は止めない）。`--lock` の無い呼び出し（各 step の機械チェック・`--verify-receipt`・`--stamp`）は通す | spec-doc の入口から封をする: `python3 <spec-doc の skill の dir>/seal.py <設計書dir>`（照合だけなら `--match-only`）。照合で止まったら 15 §6 の行を直す（seal.py の直し方の文） |

| pick_one の check_fix_window（聞かずに立てる直す窓） | PreToolUse | create_session の頼みの文か題に「直す窓」が在る時、頼みの文の `オーナーの答え: 「…」` の行の引用（4 字以上）が、この窓の会話ログのオーナーの打った行か選択肢の画面の答えに、そのままの字で在るかを見る。行が無い・字が無ければ AI だけを止める（窓はまだ立っていない）。会話ログが読めない時と助手の中は通す | 目標の外の穴なら立てずに、終わりの報告の後に穴ごとに「どうしますか」と聞く（細目 §7「報告の書き方」）。オーナーが「直して」と答えた穴か合意した目標の中の行なら、その言葉をそのまま引いて立て直す（細目 §3 原因の台帳） |
| unanswered（未回答の台帳） | PostToolUse・SessionStart | モーダルが答えのないまま閉じた問いを台帳に積み、24 時間の間、次の窓の冒頭に全部を渡す（頭の何件かで切らない）。寿命を過ぎた問いと文面の無い行は冒頭で一度知らせてから降ろす（控えは expired_recent）。人のいない窓では知らせず控えへ移すだけで、次の人のいる窓が一度知らせる。`list` は寿命切れ・文面の無い行・控えへ移した行に印を付ける。答えが返れば降ろす（同じ問いの見分けは文面の一致か含有だけ。字の形で別の問いを結ばない）。子の窓の問いも同じ | 1 件ずつ、今の窓の流れで扱う: ①答え済み・もう要らない → 出さずに `python3 <unanswered.py> drop <key> --why <訳>` で降ろす（渡された文に path が出る・`list` で一覧）②今の頼みと関わる → チャットで前提を 1〜2 文添えてから出し直す（問いの文は短く言い直してよい。言い直した問いに答えが返ったら、元の問いを drop で降ろす＝機械は結ばない）③関わらない → 冒頭で画面に出さず、締めの「あなたがやること」に 1 行で知らせ、求められたら出す。出す問いが 4 を越えたら 4 問ずつ続けて出す。言い方だけ変えて何度も出さない |

強制 push・main への push・本番への出荷・sudo は、オーナーが居ても居なくても settings の `permissions.deny` の受け持ち（ここでは重ねない）。

## 値の表

repo の根の `config/skill-values.json` の `"guard"`（無ければ既定で動く）。鍵・型・既定の正本は土台の `skill-values/schema.json`（plugin の `lib/` へ symlink で届く）。知らない鍵・畳んだ鍵・型の違う値は、その鍵だけ既定で動き（守りは止めない）、窓の起動の時に values_keys が表全体を名指しで知らせる。表を直したら `python3 "${CLAUDE_PLUGIN_ROOT}/lib/skill_values.py" check` で確かめる。

```json
{
  "guard": {
    "unattended_env": ["AF_UNATTENDED"],
    "state_dir": "~/.claude/af-guard",
    "paid_markers_extra": ["api.example-paid.com"],
    "irreversible_bash_extra": [{"pattern": "\\bmy-db\\s+--wipe\\b", "why": "DB の破棄"}],
    "irreversible_tools_extra": ["^mcp__[^ ]*__delete_item$"],
    "qa_page_exempt": ["^quiz/[^/]+\\.html$"],
    "ask_question_max_chars": 60,
    "ask_question_max_sentences": 1,
    "ask_inner_terms_extra": ["例の関所"],
    "ask_term_allow": ["^ISO\\d+$"],
    "ask_topic_stopwords_extra": [],
    "ask_shape_exempt": [],
    "ask_rec_notice_kinds": {"済んだかの確認": ["終わりましたか"]},
    "ask_rec_notice_exempt": [],
    "ask_pick_one_exempt": ["^作り物の試しの順"],
    "ask_prior_lookup": ["^mcp__[^ ]*__notion-(?:search|fetch|query-data-sources) \\{.*決定.*\\}$", "^Grep \\{.*問いの表.*\\}$"],
    "ask_prior_exempt": ["終わりましたか|済みましたか"],
    "outbound_secret_allow": ["^作り物の見本の字$"],
    "number_request_exempt": [],
    "pr_cleanup_exempt_repos": [],
    "pr_words_exempt_repos": [],
    "public_repos_extra": ["^my-owner/far-public$"]
  }
}
```

- `unattended_env`: 真なら人のいない窓とみなす環境変数の名（夜の自走などの印）。人のいない窓では、離席の止めと台帳は働かない。返し先が別の窓の子の窓（最初の頼みの文に `（親窓 session_… の子）` か `返し先=session_…` が在り、かつその頼みの行の記録が人の打った物でない＝別の窓や仕組みから来た頼み）は、問う窓として離席の止めと台帳が働く。
- `pr_cleanup_exempt_repos`・`pr_words_exempt_repos`・`public_repos_extra`: owner/repo の名の全体に当てる正規表現の並び（型 `repo_names`・大小を問わない）。各行を `^` で始め `$` で終える（repo 1 つなら `^owner/repo$`・owner ごとなら `^owner/.*$`）。頭だけ（`^owner/`）・錨なし（`owner/repo`）の行は名の一部に当てる読み方と取り違えるので、値の表の照らしが型の違いとして名指し（起動の知らせ・`values_keys.py`・AI の書き込みは止まる）、外す側の鍵では外さず照らし、`public_repos_extra` では公開の照らしを外さない。
- 字・正規表現の鍵の当て方（何に・全体か一部か）の正本は型の正本 `skill-values/schema.json` の鍵の spec（`against`＝当てる相手・`match`＝`whole` は相手の全体・`part` は相手の一部）。道具は値の表の口（`skill_values.py` の `compile_patterns`・`hit`・`words_in`）だけで当てる。全体に当てる鍵（各行を `^` で始め `$` で終える）: `irreversible_tools_extra`（道具の名）・`qa_page_exempt`（問いのページの file の path を repo の根から `/` 区切りで。repo の上の dir の名には当たらない）・`ask_term_allow`（中の言葉と見つけた字の塊）・`outbound_secret_allow`（鍵の形に当たった字の塊）・`ask_prior_lookup`（道具の呼び出し 1 つ＝道具の名・空白 1 つ・入力の JSON〔鍵の順に並べた 1 行・区切りは「, 」と「: 」〕。道具の名から書くので、Bash の echo や別の道具の入力に語が在っても当たらない）。`^…$` でない行は前の形（一部に当てる読み方）で、今は前の読み方のまま効かせて値の表の照らしが名指す（起動の知らせ・`values_keys.py`）。一部に当てる鍵: `irreversible_bash_extra`（Bash の命令の全文）・`ask_inner_terms_extra`（問いの文・返事の本文）・`ask_shape_exempt`・`ask_pick_one_exempt`・`ask_rec_notice_exempt`・`ask_prior_exempt`（問いの文）・`number_request_exempt`（外へ送る文の 1 文）。`paid_markers_extra` は字のまま一部に当てる（型 `words`・正規表現でない。`\` を含む行は正規表現のつもりの書き違いとして名指す）。
- `state_dir`: 未回答の台帳の置き場（repo ごとに 1 冊）。窓の中だけで閉じる印（離席の印）は一時の箱に置く。

## 射程の外

- 戻せない操作の判定は列挙であって証明ではない（`find … -delete`・再帰なしの `rm -f`・`git restore .` などは素通り）。足したい形は値の表へ。
- 試験から有料の上流の見張りは、自分のサーバを経た中継を見ない。Bash は書く的と命令の文の推し量りで、書く中身が命令の外にある形（`cp`・`mv`・別の script の中で書く・`python -c` の中の `open`）は見ない。
- 選択肢の画面の問いの形の見張りは字の形の推し量り（意味は読まない）。日常の言葉で書いた内輪の呼び名（「例の関所」など）は値の表の `ask_inner_terms_extra` に足すまで素通り。日常の英数字の名のうち、頭が 1〜2 字の英大文字に数の続く物（`B202` の部屋など）と file 名の形（`見積書.xlsx`・`Node.js`）は字の形で止まる（`ask_term_allow` で外す）。頭が 3 字以上の名（`COVID19`・`SHA256`）は番号と数えない（代わりに 3 字以上の頭の番号〔`ABC123`〕は `ask_inner_terms_extra` に足すまで素通り）。話題の見分けは語の重なりなので、別の話題でも同じ語（「検査」など）を共にすれば通り、同じ話題でも語を共にしなければ止まる（見出しに話題の語を入れて直す）。案や前提をチャットで先に見せたかと、オーナーが決めなくてよい事を聞いていないかは見ない。推奨の印は見出しの推奨の語（上の並び）の形・数・位置・「分からない」だけを見て（並びの外の言い回し〔「一押し」「ベスト」など〕は素通り・見出しの中身として推奨の語を使う「推奨環境に合わせる」も止まるので言い換える）、その問いが印を付けてよい作り方の分かれ道かは止めては見ず、済んだか・意図の形の字が在る時だけ画面の後に知らせる（字の形の推し量り＝言い回しを変えれば素通り・作り方の問いが「〜しましたか」で知らされることもある）。
- 値の表の知らない鍵の見張りは Write・Edit・MultiEdit だけを止める（Bash の書き換えは起動の時の知らせで拾う）。入れていない土台の plugin の頭は照らせない（手で回す口がその頭を名指す）。
- 未回答の台帳の扱い（降ろす・前提を添えて出す・締めで知らせる）は AI の判断で、答え済みかを機械は確かめない。降ろした問いは台帳の `dropped_recent` に訳と一緒に残る。
- 1 つだけ選ばせる問いの見張りは、問いの文の語の形による推し量り（意味は読まない）。「AとBのどちらにしますか」のように作業の名を選択肢にだけ並べ、問いの文に進める・優先・原因の語が無い形は素通りする。言い換えでも抜けられる（残る穴・別の目のレビューと手で回す点検で拾う）。
- 聞く前に引いた跡の見張りは、引く道具を呼んだかだけを見る（何を引いたか・問いと同じ言葉で引いたか・答え済みの問いを外したかは見ない）。引く先は会社ごとに違うので値の表に書く（`ask_prior_lookup` の例の道具の名は作り物）。値の無い repo では窓ごとに 1 回止めるだけ。
- PR の文の見張りは、GitHub の MCP の道具の文だけを見る（Bash の `gh pr create --body` や git で打つ commit の説明は見ない。git の commit の説明は CI の公開の検査が拾う・MCP から出す commit の説明は `public` が照らす）。判定のコメントは、出す先の PR の先端と PR の commit 全部の `Claude-Session:` の窓（書いた窓の組・本文の `書いた窓:` の写しは読まない）を gh で引き、出す窓の本物の id を窓の環境の記録（`CLAUDE_CODE_REMOTE_SESSION_ID`）から読んで verdict_form.py に渡す（見た先端の古い判定・書いた窓の組の窓が出す判定・名乗りの字が出す窓と違う判定も止める・どれかが引けなければ止める＝判定はクラウドの窓で出す）。判定の形の道具と雛形は、窓の repo に在ればその版を、無ければ入れた plugin の版を使う（見る点の表を変える PR の判定は、その枝を取り出した窓で出す）。言葉は窓の id だけを見る（番号・file 名・commit の印・`#31` の PR の指しは、過去の PR 本文 41 本に当てると 37 本が当たり、ほとんどが正しい指し＝当て所が無い）。公開かの見分けは窓の repo の取り出しの workflow か値の表で、手元に取り出しが無く値の表にも無い公開の repo は照らさない（CI の公開の検査が出した後に拾う）。
- 問いのページの見張りは、Artifact の道具の publish の `file_path` と `files` の手元の元を見る（`files` で別の Artifact から写す物・型から作る Artifact のデータの store・Artifact の外で配るページは見ない）。問いのページの見分けは印による推し量りで、印を持たない問いのページ（radio を使わずボタンだけで答えるページなど）は素通りする。
- 外へ渡す道具の入力の見張りの `secret` は公開の検査と同じ鍵の形だけ（パスワード・接続文字列・JWT など形の決まらない秘密は素通り）。返事の本文・Bash で外へ出す形（`curl`・`gh`）は見ない。`number` は字の形の推し量りで、番号の横に中身と関係ない語（「main に入れて」の main など）があれば通る。`title` は題の形だけで、種類が窓の返し先と合っているか（会話ログの最初の頼み）は見ない（session-watch の点検と Stop の見張りの受け持ち）。
- Artifact の文（報告・マインドマップ・理論モック）の言葉は照らさない。オーナーに出した報告 4 枚に中の言葉の見分けを当てると 4 枚とも止まり、当たったのはオーナーに要る本当の file 名・path が主だった（核 §2「物は本当の名で呼ぶ」と食い違う）ため。
