# 守りの hook（guard）

1 本の入口（`${CLAUDE_PLUGIN_ROOT}/scripts/guard.py`）を、プラグインの `hooks/hooks.json` が 3 つの出来事で回す。止めるのは PreToolUse だけで、他は隣に文を出すだけ。どれも壊れた時は黙って通す。止められた・知らされた時は下の直し方でその場を出し直すだけで済ませず、その形が出た原因を細目 §3「まず構造を疑う」で探して直す。

| 見張り | 出来事 | する事 | 止められた・知らされた時の直し方 |
|---|---|---|---|
| irreversible（離席中の戻せない操作） | PreToolUse | この窓で選択肢モーダルが答えのないまま閉じ、オーナーがまだ戻っていない間だけ、DB の破棄・メールの送信・Notion の物理削除・git で戻せない rm -r を止める（作業場〔一時の置き場〕と変更の無い作業部屋の掃除は通す） | 戻せる作業を先に進める。その操作が要るなら同じ問いをモーダルで出し直し、答えが返ってから行う（答えが返るかオーナーが打てば解ける） |
| paid_upstream（試験から有料の上流） | PreToolUse | 試験らしい path へ書く中身に、AI の API の鍵名・公式のエンドポイントがあれば止める。Bash で試験らしい path へ書く形（`>`・`>>`・`tee`・`sed -i`／`perl -i` の的）も、命令の文全体（heredoc の中身を含む）に印があれば止める | 既定を録画の再生か偽物にする。本物が要るなら環境変数 1 本で切り替える関所を通し、その file に `PAID_UPSTREAM_GUARD` を書く |
| qa_page（問いのページの検査） | PreToolUse | Artifact の publish（file_path と `files` で足す file のうち .html・.json）の前に、そのページが問いのページ（型の印 `<body data-dest>`・`CustomEvent('qa:submit')`／`<script>` の JSON に `questions`・`qs` と選択肢／radio と答えを外へ出す仕組み〔form・sendPrompt・window.claude の書く呼び出し・POST 等の fetch・clipboard への書き込み〕の両方／問いのデータの JSON。読むだけの fetch や表示の切り替えの radio は数えない）なら qa-html の `check.mjs` をかけ、赤なら止める。検査が見つからない・node が無い・検査が壊れた時も止める（緑を確かめられない物は出さない） | ①聞く前に引き（細目 §4）、答え済み・資料で決まる・道具の都合の問いを消す ②オーナーへの問いなら選択肢の画面で聞く ③ページで出すなら skill `docs-kit:qa-html` の型を写して作り直し、止めた文に出る `node <check.mjs> <file>` が緑になってから出し直す。検査が無いなら plugin docs-kit と node を入れる（`AF_QA_CHECK` で path を渡せる）。問いのページでないのに止まった時だけ、値の表の `qa_page_exempt` で外す（PR とレビューを通す） |
| ask_shape（選択肢の画面の問いの形） | PreToolUse | AskUserQuestion の画面が人に出る前に問いを照らし、崩れていれば AI だけを止める（人の操作は止めない）。`long`＝問いの文が `ask_question_max_chars` 字（既定 60）か `ask_question_max_sentences` 文（既定 1）を越える／`inner`＝問い・見出し・選択肢に AI の中の言葉らしい字（`E02`・`Q202611-67` のような番号・`#616`・`v0.21.0` のような版・file 名・path・snake_case や `直し_0020` のような識別子・窓の id・commit の印・`` ` `` で囲んだ字。URL は数えない）／`topic`＝2 問以上の画面で、問いと見出しの語（漢字・カタカナ・英字の 2 字の並び・送り仮名は詰める）を共にしない組に分かれる／`rec`＝推奨の印の付け方: 選択肢の見出しに推奨の語（推奨・おすすめ・お勧め・お薦め・オススメ・イチオシ・recommend・suggested）が決まりの形（見出しの末の `(推奨)`・`（推奨）`・`(Recommended)`）以外で在る（「非推奨」「推奨なし」「推奨どおり」も見出しでは止まる・説明の文の中は数えない）・1 問に 2 つ以上・1 つ目でない選択肢・「分からない」の選択肢（見出しの頭が分からない・分かりません・知らない・不明・Unknown・I don't know）に在る | `long`: 問いの文は何を決めるかの 1 文。背景と材料は先にチャットで見せ、違いと選ぶとどうなるかは選択肢の説明へ（細目 §4）。`inner`: それが何かを日常の言葉で言い換える。`topic`: 話題ごとに画面を分けて続けて出す（捨てない）。同じ話題なら問いか見出しにその語を入れる。字の形だけ当たった誤りは値の表の `ask_term_allow`（字）か `ask_shape_exempt`（問いの文）に足す（PR とレビューを通す）。`rec`: 印は作り方の分かれ道の問いだけに 1 つ、1 つ目の見出しの末に `(推奨)` の形で付け、推奨しない訳などは説明へ書き、理由はその選択肢の説明へ（細目 §4「推奨の印」）。推せる案が 2 つなら問いを分けるか印を外す。意図・考えを聞く問いと済んだかの確認には付けない |
| outbound（外へ渡す道具の入力） | PreToolUse | 人や他の窓へ渡る道具の入力を出る前に照らし、崩れていれば AI だけを止める（人の操作は止めない）。`secret`＝MCP の道具（`mcp__…`）・Artifact・SendMessage の入力の全部の字と Artifact で出す file の中身に、鍵・トークンの形（正本は公開の検査 `public-guard/guard.py` の `SECRET_PATTERNS` を直に読む。見つからない時は止める）／`number`＝send_message・SendMessage の文と create_session の頼みの文に、番号（`E02`・`#3` の形）だけで中身の名の無い文（番号の見分けは ask_shape の中の言葉、中身の語は ask_shape の話題の語を直に呼ぶ）／`title`＝set_session_title と create_session の title が `<種類><状態> <作業名>` でない・手の窓（`🙋⏳ 手: <何を>`）を立てる頼みの文に目的・手順・済んだ目印・済んだ後が揃わない（正本は session-watch の `title_shape`・`HAND_PARTS`） | `secret`: 鍵の値を文から抜き、名だけ書く。鍵が要る相手には環境の秘密（request_credential）で渡す。正本が無いと出たら土台の plugin を市場から入れ直す（`AF_PUBLIC_GUARD` で path を渡せる）。作り物の見本だけ値の表の `outbound_secret_allow` で外す。`number`: 番号にそれが何か（物の名と中身）を同じ文で添える。誤りは `number_request_exempt`。`title`: skill `session-watch:title-mark` の形に直す。手の窓は頼みの文に 4 欄を書く |
| context_size（文脈の量） | PostToolUse | 文脈が目安を越えた最初の 1 回だけ知らせる | 人のいる窓は区切りで引き継ぎを書き後継の窓へ替える。人のいない窓は今の段を終えて引き継ぎを書き止まる |
| unanswered（未回答の台帳） | PostToolUse・SessionStart | モーダルが答えのないまま閉じた問いを台帳に積み、24 時間の間、次の窓の冒頭に渡す。答えが返れば降ろす（同じ問いの見分けは文面の一致か含有だけ。字の形で別の問いを結ばない）。子の窓の問いも同じ | 1 件ずつ、今の窓の流れで扱う: ①答え済み・もう要らない → 出さずに `python3 <unanswered.py> drop <key> --why <訳>` で降ろす（渡された文に path が出る・`list` で一覧）②今の頼みと関わる → チャットで前提を 1〜2 文添えてから出し直す（問いの文は短く言い直してよい。言い直した問いに答えが返ったら、元の問いを drop で降ろす＝機械は結ばない）③関わらない → 冒頭で画面に出さず、締めの「あなたがやること」に 1 行で知らせ、求められたら出す。言い方だけ変えて何度も出さない |

強制 push・main への push・本番への出荷・sudo は、オーナーが居ても居なくても settings の `permissions.deny` の受け持ち（ここでは重ねない）。

## 値の表

repo の根の `config/skill-values.json` の `"guard"`（無ければ既定で動く）。

```json
{
  "guard": {
    "context_limit": 300000,
    "unattended_env": ["AF_UNATTENDED"],
    "state_dir": "~/.claude/af-guard",
    "paid_markers_extra": [],
    "irreversible_bash_extra": [{"pattern": "\\bmy-db\\s+--wipe\\b", "why": "DB の破棄"}],
    "irreversible_tools_extra": [],
    "qa_page_exempt": ["/quiz/[^/]+\\.html$"],
    "ask_question_max_chars": 60,
    "ask_question_max_sentences": 1,
    "ask_inner_terms_extra": ["例の関所"],
    "ask_term_allow": ["^ISO\\d+$"],
    "ask_topic_stopwords_extra": [],
    "ask_shape_exempt": [],
    "outbound_secret_allow": ["^作り物の見本の字$"],
    "number_request_exempt": []
  }
}
```

- `unattended_env`: 真なら人のいない窓とみなす環境変数の名（夜の自走などの印）。人のいない窓では、離席の止めと台帳は働かず、文脈の知らせは「止まる」側になる。返し先が別の窓の子の窓（最初の頼みの文に `（親窓 session_… の子）` か `返し先=session_…`）は、問う窓として離席の止めと台帳が働き、文脈の知らせだけ「止まる」側。
- `state_dir`: 未回答の台帳の置き場（repo ごとに 1 冊）。窓の中だけで閉じる印（離席の印・文脈の知らせた印）は一時の箱に置く。

## 射程の外

- 戻せない操作の判定は列挙であって証明ではない（`find … -delete`・再帰なしの `rm -f`・`git restore .` などは素通り）。足したい形は値の表へ。
- 試験から有料の上流の見張りは、自分のサーバを経た中継を見ない。Bash は書く的と命令の文の推し量りで、書く中身が命令の外にある形（`cp`・`mv`・別の script の中で書く・`python -c` の中の `open`）は見ない。
- 選択肢の画面の問いの形の見張りは字の形の推し量り（意味は読まない）。日常の言葉で書いた内輪の呼び名（「例の関所」など）は値の表の `ask_inner_terms_extra` に足すまで素通り。日常の英数字の名（`B202` の部屋・`COVID19`・`見積書.xlsx`・`Node.js`・`Wi-Fi/LAN/USB` など）も字の形で止まる（`ask_term_allow` で外す）。話題の見分けは語の重なりなので、別の話題でも同じ語（「検査」など）を共にすれば通り、同じ話題でも語を共にしなければ止まる（見出しに話題の語を入れて直す）。案や前提をチャットで先に見せたかと、オーナーが決めなくてよい事を聞いていないかは見ない。推奨の印は見出しの推奨の語（上の並び）の形・数・位置・「分からない」だけを見て（並びの外の言い回し〔「一押し」「ベスト」など〕は素通り・見出しの中身として推奨の語を使う「推奨環境に合わせる」も止まるので言い換える）、その問いが印を付けてよい作り方の分かれ道か（意図・考えを聞く問いや済んだかの確認でないか）は見ない。
- 未回答の台帳の扱い（降ろす・前提を添えて出す・締めで知らせる）は AI の判断で、答え済みかを機械は確かめない。降ろした問いは台帳の `dropped_recent` に訳と一緒に残る。
- 問いのページの見張りは、Artifact の道具の publish の `file_path` と `files` の手元の元を見る（`files` で別の Artifact から写す物・型から作る Artifact のデータの store・Artifact の外で配るページは見ない）。問いのページの見分けは印による推し量りで、印を持たない問いのページ（radio を使わずボタンだけで答えるページなど）は素通りする。
- 外へ渡す道具の入力の見張りの `secret` は公開の検査と同じ鍵の形だけ（パスワード・接続文字列・JWT など形の決まらない秘密は素通り）。返事の本文・Bash で外へ出す形（`curl`・`gh`）は見ない。`number` は字の形の推し量りで、番号の横に中身と関係ない語（「main に入れて」の main など）があれば通る。`title` は題の形だけで、種類が窓の返し先と合っているか（会話ログの最初の頼み）は見ない（session-watch の点検と Stop の差し戻しの受け持ち）。
- Artifact の文（報告・マインドマップ・理論モック）の言葉は照らさない。オーナーに出した報告 4 枚に中の言葉の見分けを当てると 4 枚とも止まり、当たったのはオーナーに要る本当の file 名・path が主だった（核 §2「物は本当の名で呼ぶ」と食い違う）ため。
