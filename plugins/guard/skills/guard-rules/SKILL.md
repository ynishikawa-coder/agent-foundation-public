# 守りの hook（guard）

1 本の入口（`${CLAUDE_PLUGIN_ROOT}/scripts/guard.py`）を、プラグインの `hooks/hooks.json` が 4 つの出来事で回す。止めるのは PreToolUse（AI の道具の呼び出し）と Stop（AI の締めの差し戻し・上限つき）だけで、他は隣に文を出すだけ。どれも壊れた時は黙って通す。止められた・知らされた時は下の直し方でその場を出し直すだけで済ませず、その形が出た原因を細目 §3「まず構造を疑う」で探して直す。

| 見張り | 出来事 | する事 | 止められた・知らされた時の直し方 |
|---|---|---|---|
| irreversible（離席中の戻せない操作） | PreToolUse | この窓で選択肢モーダルが答えのないまま閉じ、オーナーがまだ戻っていない間だけ、DB の破棄・メールの送信・Notion の物理削除・git で戻せない rm -r を止める（作業場〔一時の置き場〕と変更の無い作業部屋の掃除は通す） | 戻せる作業を先に進める。その操作が要るなら同じ問いをモーダルで出し直し、答えが返ってから行う（答えが返るかオーナーが打てば解ける） |
| paid_upstream（試験から有料の上流） | PreToolUse | 試験らしい path へ書く中身に、AI の API の鍵名・公式のエンドポイントがあれば止める。Bash で試験らしい path へ書く形（`>`・`>>`・`tee`・`sed -i`／`perl -i` の的）も、命令の文全体（heredoc の中身を含む）に印があれば止める | 既定を録画の再生か偽物にする。本物が要るなら環境変数 1 本で切り替える関所を通し、その file に `PAID_UPSTREAM_GUARD` を書く |
| qa_page（問いのページの検査） | PreToolUse | Artifact の publish（file_path と `files` で足す file のうち .html・.json）の前に、そのページが問いのページ（型の印 `<body data-dest>`・`CustomEvent('qa:submit')`／`<script>` の JSON に `questions`・`qs` と選択肢／radio と答えを外へ出す仕組み〔form・sendPrompt・window.claude の書く呼び出し・POST 等の fetch・clipboard への書き込み〕の両方／問いのデータの JSON。読むだけの fetch や表示の切り替えの radio は数えない）なら qa-html の `check.mjs` をかけ、赤なら止める。検査が見つからない・node が無い・検査が壊れた時も止める（緑を確かめられない物は出さない） | ①聞く前に引き（細目 §4）、答え済み・資料で決まる・道具の都合の問いを消す ②オーナーへの問いなら選択肢の画面で聞く ③ページで出すなら skill `docs-kit:qa-html` の型を写して作り直し、止めた文に出る `node <check.mjs> <file>` が緑になってから出し直す。検査が無いなら plugin docs-kit と node を入れる（`AF_QA_CHECK` で path を渡せる）。問いのページでないのに止まった時だけ、値の表の `qa_page_exempt` で外す（PR とレビューを通す） |

| ask_shape の notice（推奨の印の知らせ） | PostToolUse | 推奨の印が付いた選択肢の画面の問いの文が、済んだかの確認（「終わりましたか」「送りましたか」「済んでいますか」「反映されましたか」等）か意図・考えを聞く形（「なぜ」「どういう意図」「意図は」「どう思い」「お好み」等）に見えたら、画面の後に知らせる（止めない・形は `ask_rec_notice_kinds` で替える） | 答えが印に引かれて寄っていないかを確かめ（済んだかは AI が確かめられる所を先に確かめる）、次から印を外す。字の形だけ当たった誤りは値の表の `ask_rec_notice_exempt`（問いの文）に足す。値の表の正規表現が壊れていると、その形を照らせていないと知らせる（他の形は照らす） |
| pick_one（1 つだけ選ばせる問い） | PreToolUse | 選択肢の画面（AskUserQuestion）で、1 つだけ選ぶ問い（multiSelect が偽）の文が、これからやる物・手を付ける順を選ばせる意志の形（どれを進めますか・何から始めますか・どの論点を先に詰めますか・どれを優先しますか）か、原因の見立てを選ばせる形（原因はどれだと思いますか・どれが原因に近いですか）なら止める。全部を選べる問い・選択肢に全部やる道（全部・すべて・両方・同時・並行）が在る問いは通す。過去（〜しましたか）・受け身（〜されますか）・「が」を挟む形・意味や事実の問い（どちらの意味ですか・原因はどの資料に書いてありますか）は当てない。画面はまだ人に出ていない＝止まるのは AI の問いだけ | 相談で出た事は全部やる（オーナー決定 2026-11-19）。①聞くならやり方を問う（「全部この窓で順に」「それぞれ別の窓で同時に」）②全部を選べる形にする（multiSelect か「全部」）③原因は AI が全体の絵の上で見立てて示し、合っているかを問う ④調べれば決まる順は問わずに AI が決めて全部進める。推奨の印は作り方の分かれ道の問いだけ（細目 §4「推奨の印」）で、やり方・全部やるかを問う選択肢には付けない。誤って止まった（意図・事実・意味の問い）時は問いの文を「どちらが正しいか／どの意味か／どちらにするか」の形に直して出し直し、同じ形で何度も止まるなら値の表の `ask_pick_one_exempt` に足す（PR とレビューを通す） |
| outbound（外へ渡す道具の入力） | PreToolUse | 人や他の窓へ渡る道具の入力を出る前に照らし、崩れていれば AI だけを止める（人の操作は止めない）。`secret`＝MCP の道具（`mcp__…`）・Artifact・SendMessage の入力の全部の字と Artifact で出す file の中身に、鍵・トークンの形（正本は公開の検査 `public-guard/guard.py` の `SECRET_PATTERNS` を直に読む。見つからない時は止める）／`number`＝send_message・SendMessage の文と create_session の頼みの文に、番号（`E02`・`#3` の形）だけで中身の名の無い文（番号の見分けは ask_shape の中の言葉、中身の語は ask_shape の話題の語を直に呼ぶ）／`title`＝set_session_title と create_session の title が `<種類><状態> <作業名>` でない・手の窓（`🙋⏳ 手: <何を>`）を立てる頼みの文に目的・手順・済んだ目印・済んだ後が揃わない（正本は session-watch の `title_shape`・`HAND_PARTS`） | `secret`: 鍵の値を文から抜き、名だけ書く。鍵が要る相手には環境の秘密（request_credential）で渡す。正本が無いと出たら土台の plugin を市場から入れ直す（`AF_PUBLIC_GUARD` で path を渡せる）。作り物の見本だけ値の表の `outbound_secret_allow` で外す。`number`: 番号にそれが何か（物の名と中身）を同じ文で添える。誤りは `number_request_exempt`。`title`: skill `session-watch:title-mark` の形に直す。手の窓は頼みの文に 4 欄を書く |
| spec_gate（設計書の型の gate を直に呼ぶ手） | PreToolUse | Bash の命令に設計書の型の gate `check_spec_doc.py` と `--lock` の両方が在れば止める（封の入口 `seal.py` は 15 §6 の決定照合が済むまで gate を呼ばない。直に呼ぶとその照合を飛ばせた）。AI の道具の呼び出しだけを止める（人の手の命令は止めない）。`--lock` の無い呼び出し（各 step の機械チェック・`--verify-receipt`・`--stamp`）は通す | spec-doc の入口から封をする: `python3 <spec-doc の skill の dir>/seal.py <設計書dir>`（照合だけなら `--match-only`）。照合で止まったら 15 §6 の行を直す（seal.py の直し方の文） |
| values_keys（値の表の知らない鍵） | PreToolUse・SessionStart | 使う側の repo の `config/skill-values.json` を Write・Edit・MultiEdit で書いた後に、土台が読まない鍵（土台が畳んだ・名を変えた鍵か書き違い）が残り、書く前より減っていなければ止める（AI の書き込みだけ・人の手は止めない）。起動の時に在れば知らせる。知っている鍵の正本は各 skill の SKILL.md の「repo ごとの値」の表と guard の値（照らすのは頭が土台の plugin の名か `common` の所だけ・`_` で始まる注は通す） | 名指しされた鍵を消すか今の名の鍵へ移し、その repo の PR で直す。repo が自分で持つ値なら土台の plugin の名と `common` の外の頭へ移す。土台の道具が今も読む鍵なのに表に行が無いだけなら、土台の SKILL.md の表に行を足す PR を出す。手で照らす口: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/values_keys.py" config/skill-values.json`（知らない鍵が在れば exit 1） |

| context_size（文脈の量） | PostToolUse・Stop | 文脈が目安を越えた最初の 1 回だけ知らせる。越えた後、引き継ぎの跡（値の表 `context_handoff` の正規表現に当たる道具の呼び出し。既定は後継の窓を立てる `create_session`・返し先へ送る `send_message`・名に「引き継ぎ」か handoff を含む file を書く）が無いまま AI が締めようとしたら、締めを差し戻す（同じターンで `context_stop_max` 回〔既定 2〕まで・越えたら通して届ける）。引き継いだ後と、まとめ直して目安の手前に縮んだ後は差し戻さない | 人のいる窓は区切りで引き継ぎを書き、後継の窓を立てて渡し、返事で続きをどの窓で見るかを書く。返し先が別の窓の窓・人のいない窓は今の段を終えて引き継ぎを書き、返し先へ送って止まる。別の道で引き継いだのに差し戻されたら、その道の形を `context_handoff` に足す。差し戻しそのものは `context_stop_max` を 0 で外す（PR とレビューを通す） |
| unanswered（未回答の台帳） | PostToolUse・SessionStart | モーダルが答えのないまま閉じた問いを台帳に積み、24 時間の間、次の窓の冒頭に全部を渡す（頭の何件かで切らない）。寿命を過ぎた問いと文面の無い行は冒頭で一度知らせてから降ろす（控えは expired_recent）。人のいない窓では知らせず控えへ移すだけで、次の人のいる窓が一度知らせる。`list` は寿命切れ・文面の無い行・控えへ移した行に印を付ける。答えが返れば降ろす（同じ問いの見分けは文面の一致か含有だけ。字の形で別の問いを結ばない）。子の窓の問いも同じ | 1 件ずつ、今の窓の流れで扱う: ①答え済み・もう要らない → 出さずに `python3 <unanswered.py> drop <key> --why <訳>` で降ろす（渡された文に path が出る・`list` で一覧）②今の頼みと関わる → チャットで前提を 1〜2 文添えてから出し直す（問いの文は短く言い直してよい。言い直した問いに答えが返ったら、元の問いを drop で降ろす＝機械は結ばない）③関わらない → 冒頭で画面に出さず、締めの「あなたがやること」に 1 行で知らせ、求められたら出す。出す問いが 4 を越えたら 4 問ずつ続けて出す。言い方だけ変えて何度も出さない |

強制 push・main への push・本番への出荷・sudo は、オーナーが居ても居なくても settings の `permissions.deny` の受け持ち（ここでは重ねない）。

## 値の表

repo の根の `config/skill-values.json` の `"guard"`（無ければ既定で動く）。

```json
{
  "guard": {
    "context_limit": 300000,
    "context_stop_max": 2,
    "context_handoff": ["create_session\\b", "send_message\\b", "\"file_path\": \"[^\"]*(?:引き継ぎ|handoff)[^\"]*\""],
    "unattended_env": ["AF_UNATTENDED"],
    "state_dir": "~/.claude/af-guard",
    "paid_markers_extra": [],
    "irreversible_bash_extra": [{"pattern": "\\bmy-db\\s+--wipe\\b", "why": "DB の破棄"}],
    "irreversible_tools_extra": [],
    "qa_page_exempt": ["/quiz/[^/]+\\.html$"],
    "ask_question_max_chars": 60,
    "ask_question_max_sentences": 1,
    "ask_inner_terms_extra": ["例の関所"],
    "ask_term_allow": ["^ISO\\d+$"],
    "ask_topic_stopwords_extra": [],
    "ask_shape_exempt": [],
    "ask_rec_notice_kinds": {"済んだかの確認": ["終わりましたか"]},
    "ask_rec_notice_exempt": [],
    "ask_pick_one_exempt": ["^作り物の試しの順"],
    "ask_prior_lookup": ["notion-(?:search|fetch|query-data-sources).*決定", "\\bGrep\\b.*問いの表"],
    "ask_prior_exempt": ["終わりましたか|済みましたか"],
    "outbound_secret_allow": ["^作り物の見本の字$"],
    "number_request_exempt": []
  }
}
```

- `unattended_env`: 真なら人のいない窓とみなす環境変数の名（夜の自走などの印）。人のいない窓では、離席の止めと台帳は働かず、文脈の知らせは「止まる」側になる。返し先が別の窓の子の窓（最初の頼みの文に `（親窓 session_… の子）` か `返し先=session_…`）は、問う窓として離席の止めと台帳が働き、文脈の知らせだけ「止まる」側。
- `state_dir`: 未回答の台帳の置き場（repo ごとに 1 冊）。窓の中だけで閉じる印（離席の印・文脈の知らせた印）は一時の箱に置く。

## 射程の外

- 戻せない操作の判定は列挙であって証明ではない（`find … -delete`・再帰なしの `rm -f`・`git restore .` などは素通り）。足したい形は値の表へ。
- 試験から有料の上流の見張りは、自分のサーバを経た中継を見ない。Bash は書く的と命令の文の推し量りで、書く中身が命令の外にある形（`cp`・`mv`・別の script の中で書く・`python -c` の中の `open`）は見ない。
- 選択肢の画面の問いの形の見張りは字の形の推し量り（意味は読まない）。日常の言葉で書いた内輪の呼び名（「例の関所」など）は値の表の `ask_inner_terms_extra` に足すまで素通り。日常の英数字の名（`B202` の部屋・`COVID19`・`見積書.xlsx`・`Node.js`・`Wi-Fi/LAN/USB` など）も字の形で止まる（`ask_term_allow` で外す）。話題の見分けは語の重なりなので、別の話題でも同じ語（「検査」など）を共にすれば通り、同じ話題でも語を共にしなければ止まる（見出しに話題の語を入れて直す）。案や前提をチャットで先に見せたかと、オーナーが決めなくてよい事を聞いていないかは見ない。推奨の印は見出しの推奨の語（上の並び）の形・数・位置・「分からない」だけを見て（並びの外の言い回し〔「一押し」「ベスト」など〕は素通り・見出しの中身として推奨の語を使う「推奨環境に合わせる」も止まるので言い換える）、その問いが印を付けてよい作り方の分かれ道かは止めては見ず、済んだか・意図の形の字が在る時だけ画面の後に知らせる（字の形の推し量り＝言い回しを変えれば素通り・作り方の問いが「〜しましたか」で知らされることもある）。
- 値の表の知らない鍵の見張りは Write・Edit・MultiEdit だけを止める（Bash の書き換えは起動の時の知らせで拾う）。入れていない土台の plugin の頭は照らせない（手で回す口がその頭を名指す）。
- 未回答の台帳の扱い（降ろす・前提を添えて出す・締めで知らせる）は AI の判断で、答え済みかを機械は確かめない。降ろした問いは台帳の `dropped_recent` に訳と一緒に残る。
- 1 つだけ選ばせる問いの見張りは、問いの文の語の形による推し量り（意味は読まない）。「AとBのどちらにしますか」のように作業の名を選択肢にだけ並べ、問いの文に進める・優先・原因の語が無い形は素通りする。言い換えでも抜けられる（残る穴・別の目のレビューと手で回す点検で拾う）。
- 聞く前に引いた跡の見張りは、引く道具を呼んだかだけを見る（何を引いたか・問いと同じ言葉で引いたか・答え済みの問いを外したかは見ない）。引く先は会社ごとに違うので値の表に書く（`ask_prior_lookup` の例の道具の名は作り物）。値の無い repo では窓ごとに 1 回止めるだけ。
- 文脈の差し戻しは、引き継ぎらしい道具を呼んだかだけを見る（引き継ぎの中身・後継の窓の最初の出し方は見ない）。上限を越えたターンは通して届く。
- 問いのページの見張りは、Artifact の道具の publish の `file_path` だけを見る（`files` で足す別のページ・型から作る Artifact のデータの store・Artifact の外で配るページは見ない）。問いのページの見分けは印による推し量りで、印を持たない問いのページ（radio を使わずボタンだけで答えるページなど）は素通りする。
- 問いのページの見張りは、Artifact の道具の publish の `file_path` と `files` の手元の元を見る（`files` で別の Artifact から写す物・型から作る Artifact のデータの store・Artifact の外で配るページは見ない）。問いのページの見分けは印による推し量りで、印を持たない問いのページ（radio を使わずボタンだけで答えるページなど）は素通りする。
- 外へ渡す道具の入力の見張りの `secret` は公開の検査と同じ鍵の形だけ（パスワード・接続文字列・JWT など形の決まらない秘密は素通り）。返事の本文・Bash で外へ出す形（`curl`・`gh`）は見ない。`number` は字の形の推し量りで、番号の横に中身と関係ない語（「main に入れて」の main など）があれば通る。`title` は題の形だけで、種類が窓の返し先と合っているか（会話ログの最初の頼み）は見ない（session-watch の点検と Stop の差し戻しの受け持ち）。
- Artifact の文（報告・マインドマップ・理論モック）の言葉は照らさない。オーナーに出した報告 4 枚に中の言葉の見分けを当てると 4 枚とも止まり、当たったのはオーナーに要る本当の file 名・path が主だった（核 §2「物は本当の名で呼ぶ」と食い違う）ため。
