# 射程の外（guard）

見張りの見分けが届かない所。

- 戻せない操作の判定は列挙であって証明ではない（`find … -delete`・再帰なしの `rm -f`・`git restore .` などは素通り）。足したい形は値の表へ。
- 試験から有料の上流の見張りは、自分のサーバを経た中継を見ない。Bash は書く的と命令の文の推し量りで、書く中身が命令の外にある形（`cp`・`mv`・別の script の中で書く・`python -c` の中の `open`）は見ない。
- 選択肢の画面の問いの形の見張りは字の形の推し量り（意味は読まない）。日常の言葉で書いた内輪の呼び名（「例の関所」など）は値の表の `ask_inner_terms_extra` に足すまで素通り。日常の英数字の名のうち、頭が 1〜2 字の英大文字に数の続く物（`B202` の部屋など）と file 名の形（`見積書.xlsx`・`Node.js`）は字の形で止まる（`ask_term_allow` で外す）。頭が 3 字以上の名（`COVID19`・`SHA256`）は番号と数えない（代わりに 3 字以上の頭の番号〔`ABC123`〕は `ask_inner_terms_extra` に足すまで素通り）。話題の見分けは語の重なりなので、別の話題でも同じ語（「検査」など）を共にすれば通り、同じ話題でも語を共にしなければ止まる（見出しに話題の語を入れて直す）。案や前提をチャットで先に見せたかと、オーナーが決めなくてよい事を聞いていないかは見ない。推奨の印は見出しの推奨の語（上の並び）の形・数・位置・「分からない」だけを見て（並びの外の言い回し〔「一押し」「ベスト」など〕は素通り・見出しの中身として推奨の語を使う「推奨環境に合わせる」も止まるので言い換える）、その問いが印を付けてよい作り方の分かれ道かは止めては見ず、済んだか・意図の形の字が在る時だけ画面の後に知らせる（字の形の推し量り＝言い回しを変えれば素通り・作り方の問いが「〜しましたか」で知らされることもある）。
- 値の表の知らない鍵の見張りは Write・Edit・MultiEdit だけを止める（Bash の書き換えは起動の時の知らせで拾う）。入れていない土台の plugin の頭は照らせない（手で回す口がその頭を名指す）。
- 未回答の台帳の扱い（降ろす・前提を添えて出す・締めで知らせる）は AI の判断で、答え済みかを機械は確かめない。降ろした問いは台帳の `dropped_recent` に訳と一緒に残る。
- 1 つだけ選ばせる問いの見張りは、問いの文の語の形による推し量り（意味は読まない）。「AとBのどちらにしますか」のように作業の名を選択肢にだけ並べ、問いの文に進める・優先・原因の語が無い形は素通りする。言い換えでも抜けられる（残る穴・別の目のレビューと手で回す点検で拾う）。
- 聞く前に引いた跡の見張りは、引く道具を呼んだかだけを見る（何を引いたか・問いと同じ言葉で引いたか・答え済みの問いを外したかは見ない）。引く先は会社ごとに違うので値の表に書く（`ask_prior_lookup` の例の道具の名は作り物）。値の無い repo では窓ごとに 1 回止めるだけ。
- PR の文の見張りは、GitHub の MCP の道具の文だけを見る（Bash の `gh pr create --body` や git で打つ commit の説明は見ない。git の commit の説明は CI の公開の検査が拾う・MCP から出す commit の説明は `public` が照らす）。判定のコメントは、出す先の PR の先端と PR の commit 全部の `Claude-Session:` の窓（書いた窓の組・本文の `書いた窓:` の写しは読まない）を gh で引き、出す窓の本物の id を窓の環境の記録（`CLAUDE_CODE_REMOTE_SESSION_ID`）から読んで verdict_form.py に渡す（見た先端の古い判定・書いた窓の組の窓が出す判定・名乗りの字が出す窓と違う判定も止める・どれかが引けなければ止める＝判定はクラウドの窓で出す）。判定の形の道具と雛形は、窓の repo に在ればその版を、無ければ入れた plugin の版を使う（見る点の表を変える PR の判定は、その枝を取り出した窓で出す）。言葉は窓の id だけを見る（番号・file 名・commit の印・`#31` の PR の指しは、過去の PR 本文 41 本に当てると 37 本が当たり、ほとんどが正しい指し＝当て所が無い）。公開かの見分けは窓の repo の取り出しの workflow か値の表で、手元に取り出しが無く値の表にも無い公開の repo は照らさない（CI の公開の検査が出した後に拾う）。
- 問いのページの見張りは、Artifact の道具の publish の `file_path` と `files` の手元の元を見る（`files` で別の Artifact から写す物・型から作る Artifact のデータの store・Artifact の外で配るページは見ない）。問いのページの見分けは印による推し量りで、印を持たない問いのページ（radio を使わずボタンだけで答えるページなど）は素通りする。
- 外へ渡す道具の入力の見張りの `secret` は公開の検査と同じ鍵の形だけ（パスワード・接続文字列・JWT など形の決まらない秘密は素通り）。返事の本文・Bash で外へ出す形（`curl`・`gh`）は見ない。`number` は字の形の推し量りで、番号の横に中身と関係ない語（「main に入れて」の main など）があれば通る。`title` は題の形だけで、種類が窓の返し先と合っているか（会話ログの最初の頼み）は見ない（session-watch の点検と Stop の見張りの受け持ち）。
- Artifact の文（報告・マインドマップ・理論モック）の言葉は照らさない。オーナーに出した報告 4 枚に中の言葉の見分けを当てると 4 枚とも止まり、当たったのはオーナーに要る本当の file 名・path が主だった（核 §2「物は本当の名で呼ぶ」と食い違う）ため。
