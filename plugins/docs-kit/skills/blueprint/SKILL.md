# /blueprint — データの行き先を洗い出す System Blueprint

## 大原則

Blueprint は **理論モックとは別物**。理論モックは「何を作るか」の合意を取る道具。Blueprint は、それとは別に **データの行き先を洗い出す** 道具で、画面の操作ごとに「どのデータを・いつ・どう加工し・どの表のどの棚へ書くか・それが保存されるか消えるか」を並べる（目的が違うので別々に作る）。

左に画面のワイヤー、右に段（表／処理）を置く。左のボタンを押すと、右の行き先が開いて光る。

**決まっていない所は埋めない**。設計版では、根拠（basis）か書き先（where）が空の段に、**枠が「未定」の札を付けて赤く描く**。中身に書いた札（fate）が何であっても、枠が上書きする。それらしく埋めた書き先でも、根拠が無ければ赤く出る＝作り話が構造的に出せない。

## 所属モード

トリガを受けたら**宣言も確認もなしで単一操作として**作って渡す（「作りますか？」「これでOK？」を出さない・会社の規律は表の `common.rules.no_confirm`）。

## 2 つの使い方（`META.mode` 1 つで切り替える）

| | 現状版 `mode:'current'` | 設計版 `mode:'design'` |
|---|---|---|
| 何から起こす | 動いているシステムの **本番コード** を読む | **理論モックで前提ができた後に**、理論モック・要件カード・設計書から起こす |
| 段の根拠 `basis` | コードの行 `path:行`（例 `app/lib/x.ts:120`）。空か形違いは selftest NG | 要件・決定の番号（例 `REQ-12`・`D-12`） |
| 見つかる物 | 実装の穴（消える・二重・効かない）→ `HOLES` | 決め忘れ（書き先・根拠が決まっていない操作）→ 枠が「未定」の札 |
| 見出し | 現状版（本番コードから） | 設計版（要件・決定から） |

- **設計版で決まっていない所は、埋めずに `basis` / `where` を空のまま置く**。枠が「未定」の札にし、「穴・未定の一覧」タブに並べる。推測で書き先を書かない。
- 設計版では、その場で計算する段（書き先の無い処理）にも `where` を書く（例 `書かない（画面に出すだけ）`）。空だと「未定」になる＝「書かない」と決めたこと自体を明示させる。

## 作り方（skip 禁止）

1. **`references/template.html` を写して始める**＝枠（CSS・描画・札の決定・一覧・コピー・selftest・dump）の正本。**枠は変えない**。差し替えるのは `/* ==== CONTENT START ==== */` 〜 `/* ==== CONTENT END ==== */` の 1 区画だけ（下の §中身の区画の schema）。見本の中身（架空の備品の貸出帳）は全部消して、題材で置き換える。
2. **現状版はコードを読んで起こす**。段ごとに書き先（どのファイル・どのキー・メモリか localStorage か）を確かめ、`basis` にその行を `path:行` で書く。読んでいない段は作らない。
3. **設計版は理論モック・要件カード・設計書から起こす**。段ごとに `basis` へ要件・決定の番号を書く。番号が引けない段は `basis` を空のまま置く。
4. **名前は画面の言葉に合わせる**。段の `name` は理論モック・本番画面で使っている言葉にする（`compare` の突き合わせの鍵＝現状版と設計版で同じ物は同じ `name`）。段 id とタブ id は作り直しでも変えない。
5. **表の中の値は形を見せる作り値**（人名・金額は架空）。列名・置き場所・書く順番は実物どおり。
6. **保存**＝`Blueprint_<件名>_<現状版｜設計版>_<YYYYMMDD>.html`。置き場は表の `common.save_dir`（無ければ窓の scratchpad＝git の外・PR に載せない）。`common.save_dir_avoid` には置かない。
7. **検査してから渡す**＝`python3 <この skill>/scripts/check_blueprint.py <保存した html>` で `SELFTEST OK <n> tabs <m> steps`（exit 0）を取る。NG 行（`<タブid>/<段id>: <理由>`）が出たら直してから渡す。NG になるのは、例外・console.error、飛び先の無い `data-go`／`data-tab-go`、`HOLES` に無い穴番号、現状版で根拠が空か `path:行` の形でない段、段 id の重複。exit 2 は Chrome が無い・起動できない＝検査できていない（OK と言わない）。
8. **渡す**＝検査を通した html を表の `common.delivery` で渡す（無ければ Artifact で publish し非公開のまま・共有しない／`file:///…` の絶対パスでもよい）。チャットには URL 1 行と「見どころ」数行（大きい穴・未定の数）だけ。HTML の中身をチャットに再展開しない。

## 比較（設計版を作ったら、現状版と並べる）

```
python3 <この skill>/scripts/check_blueprint.py compare <現状版.html> <設計版.html>
```

両方を `?dump` で開き、段の `name` で突き合わせて Markdown を出す。①片方にしか無い段 ②書き先の違い ③札の違い ④設計版で未定のまま。**食い違いは設計からのずれ**（作り直しで消える保存・新しく足す書き先）として読む。差があっても exit 0（差分を見せる道具で、関所ではない）。

## 「穴・未定の一覧」タブ（枠が末尾に自動で足す）

現状版＝`HOLES` と、それを指している段の一覧。設計版＝未定の段（タブ名・段名・欠けている物）＋`HOLES`。「一覧をコピー」で次の形の Markdown になる（形を変えない）:

```
# <題> — 穴・未定（<日時>）

## 未定
- <タブ> › <段名>: 欠け=<根拠｜書き先>

## 穴
- 穴<番号> <題>: <一言>（<段名…>）
```

## 中身の区画の schema（CONTENT START〜END）

| 名前 | 形 | 意味 |
|---|---|---|
| `META.title` / `META.by` / `META.date` | 文字列 | 見出し（コピーの見出しにもなる）／見出しの下の一行／起こした日 |
| `META.mode` | `'current'｜'design'` | 現状版／設計版。見出しの札と「未定」の判定が変わる |
| `META.source` | 文字列 | 何から起こしたか 1 行（下に出る） |
| `STORE` | `{intro, tree, name, d, fate, shelves:[[キー, 中身, 表]], note}` | 置き場タブ（フォルダの木と棚の表）。`tree` も `shelves` も空なら出さない |
| `HOLES` | `{番号:[題, 一言]}` | 穴。段の `holes:[番号]` か本文の `hole(番号)` で指す。番号の代わりに `'その他'` 等の文字キーも可 |
| `tab({…})` | タブ 1 枚 | `id`（不変）・`t`（タブの題）・`bar?`（ワイヤーの上の題＝既定 `t`）・`intro`（上の一言）・`wf:()=>HTML`（左のワイヤー）・`steps:[段…]` |
| 段 | `{id, kind, label?, name, t?, d, fate, ft?, where, basis, holes, body}` | `kind`＝`'table'`（表・番号 T1…）｜`'calc'`（処理・番号 1,2…）。`label` で番号を上書き。`name`＝画面の言葉の名（比較の鍵）・`t`＝表示の題（既定 `name`）・`d`＝一言。`fate`＝`'keep'`（保存される）｜`'lost'`（消える）｜`'calc'`（その場で計算）｜`'gap'`（未定）。`ft`＝札の文言の上書き（例 `この端末だけ`・未定には効かない）。`where`＝書き先・`basis`＝根拠・`holes`＝穴番号・`body:()=>HTML` |

枠の部品（中身から呼ぶ）: `tbl(head, rows, {num:[列], mono:[列], wrap:[列], bad:[[行,列]]})`（rows は `[セル…]` の配列。文字列の行は「… 続く」の行）／`go(段id, label, cls)`（cls＝`''`｜`'pri'`｜`'fld'`）／`tabgo(タブid, label, cls)`／`hole(番号)`／`frow(html)`／`box(html)`。HTML の口: `data-go="段id"`・`data-tab-go="タブid"`。

## 枠の鉄則（触らない）

- **札は枠が決める**（設計版で `basis` か `where` が空 → 未定。`fate:'gap'` → 未定）。未定の見た目＝赤の破線の枠＋斜線の地（塗りの赤＝消える、と見分ける）。凡例・見出しの版の札・「穴・未定の一覧」タブ・コピーの形・`?selftest`・`?dump` は **変えない**。
- **外部リソース禁止**（CDN・外部フォント・画像 URL・fetch）。CSS/JS は全部 inline。`file://` でオフライン完動。
