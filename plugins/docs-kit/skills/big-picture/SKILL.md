# 全体の絵（big-picture）

全体の絵は使い捨ての HTML でなく **設計の正**。設計の時に掘り下げる元の図として、設計の初めの合意・問題が起きた時・仕組みを変える時に使う。合流（main へ入れる）は止めない。必ず載せる物は 4 つ（照らす時の 4 欄も同じ）:

1. **意図・課題と完成像**（`meta.intent`＝何のために在るか・`meta.problem`＝意図と今のずれ・`meta.goal`。根治の 5 段＝細目 §3 の意図・課題・未来）
2. **部品と流れ**（箱 `boxes` と矢印 `arrows`）
3. **共通と個別の境**（箱ごとの `side`＝`共通`／`個別`／`外`）
4. **人が見る所・決める所**（箱ごとの `role`＝`決める`／`見る`。人の箱は必ず持つ）

**上下**: 全体の絵が上。設計書の型（dev-flow の skill `spec-doc`）は全体の絵の下で、1 つの箱（部品）の細部を書く物。設計書は絵の箱・流れ・共通と個別の境・人が決める所を変えない（変えるなら先に絵を直して合意の版を上げる）。

## 道具（scripts/big_picture.py・標準ライブラリだけ）

```
python3 <この skill>/scripts/big_picture.py check   <絵.json>                 # 形の誤り＝exit 1／赤い点は警告（exit 0）
python3 <この skill>/scripts/big_picture.py render  <絵.json> -o <出す.html>  # check を通った絵だけ描く
python3 <この skill>/scripts/big_picture.py compare <合意した絵.json> <実物の絵.json>  # 差なし 0／差あり 1／照らせない 2
python3 <この skill>/scripts/big_picture.py explain <絵.json> <問題 id>        # 説明のチャットの文
python3 <この skill>/scripts/big_picture.py pick    <repo の根> <触った file>...   # 照らす絵を選ぶ（覆わない file があれば exit 2）
```

HTML の型は `references/template.html`（手で直さない・外の物を読まない・`file://` で動く）。URL の `?tab=flow&layer=explain&p=<問題 id>` で開く所を指せる。

## 絵の JSON（form `big-picture/1`）

| 欄 | 形 | 意味 |
|---|---|---|
| `meta.title`・`meta.intent`・`meta.problem`・`meta.goal` | 文字列 | 題・意図（オーナーに聞いた物だけ。合意の絵で空なら赤い点）・課題（意図と今のずれ。「なぜ」は書かず原因は `problems` の `cause` へ）・完成像 |
| `meta.kind` | `合意`／`実物` | オーナーと合意した版か、レビューの窓がコードから描いた実物か |
| `meta.version` | `YYYY-MM-DD.n` | 版。合意した絵を変える時は必ず上げる（同じ日の 2 本目は `.2`）。実物の絵には書かない（どの先端から描いたかは `drawn_from`） |
| `meta.agreed` | `{by:"owner", date, record}` | 合意の印（`合意` に要る）。`record` はオーナーの決定の在り処を名で書く（公開の repo では URL を書かない） |
| `meta.drawn_from`・`meta.drawn_by` | 文字列 | 実物を描いた元（`<repo>@<SHA12>`）と描いた窓（`実物` に要る） |
| `tabs.<ctx｜flow｜arch>` | `{w, h, lanes?, areas?}` | 1. 全体の文脈／2. ワークフロー／3. 仕組みの構成。4. 決めた事と意図 は箱から自動で表にする。`lanes`＝`[{t, y, h}]`（流れの帯）・`areas`＝`[{t, k, x, y, w, h}]`（共通と個別の点線の枠） |
| `boxes[]` | `{id, tab, t, k, side, role?, in?, see?, x, y, w, h, what, why, intent}` | `k`＝`owner`（人）・`ai`（AI の窓）・`part`（部品）・`store`（置き場・記録）・`ext`（外の物）。`what`＝何か・`why`＝記録にある理由（AI の文・出所つき）・`intent`＝**オーナーの意図（聞いた物だけ・聞いていなければ `null`）**。`in`＝中に入る箱の id（同じタブ・輪にしない。照らしの欄 2 で比べる）・`see`＝別のタブで関わる箱の id の並び（同じタブの関わりは矢印で描く）。**箱どうしの関わりを `what` の文に id や中身で写さない**（欄で持てば検査が指す先を確かめ、HTML が押せる印にする） |
| `arrows[]` | `{from, to, label?}` | 同じタブの箱どうし。箱の間でコードが実際に配る・呼ぶ・読む流れは全部描く（代表の 1 本で済ませない＝照らす時に実物の絵と同じ粗さにするため） |
| `problems[]` | `{id, title, date, at[], cause, via[], origin, why_here}` | 起きた問題の層（意図とは分ける）。`title`＝課題（起きた所の箱の意図とのずれ・なぜは書かない）・`at`＝起きた所の箱（`explain` はその箱の `intent` を直に読んで意図として出す＝問題へ写さない）・`cause`＝原因の箱・`via`＝原因から起きた所までの間の箱・`origin`＝`構造`／`単発`・`why_here`＝なぜここから起きたか |

- **意図は作らない**: 意図はオーナーに問うしか得られない。記録から拾った理由は `why` に置き、`intent` は `null` のまま＝**赤い点**（check が「意図をまだ聞いていない」と 1 行ずつ出す）。記録の解決策を意図として書かない。意図を問う時は核 §4 の選択肢の画面で、前提を 1〜2 文・選択肢は短く・推奨の印なし・1 画面 2〜3 問。
- **単発と書くのは**、絵の上で構造に原因が無いと示せた時だけ（`why_here` にその根拠を書く）。

## 使い方

1. **設計の初め**: 頼まれた仕組みの絵を描く（新しい仕組みは要件から・在る仕組みは先にコードから実物の絵を描く）。赤い点の意図を問うて埋め、`render` した HTML をオーナーに見せて OK を取る。OK が出たら `meta.kind: 合意`・`meta.agreed`・`meta.version` を付けて固定する。
2. **置き場**: 合意した絵の正は案件のページ（Javis は Notion の案件ページ）。土台（この repo）の絵だけは土台の repo の `docs/全体の絵.json`（UTC のレビューの窓も読むため）。repo ごとの置き場は値の表で指す（下）。HTML は毎回 JSON から描き直す写しで、正にしない。
3. **設計の仕事が終わった時（と「絵どおりか照らして」と頼まれた時）**: 合意した設計の仕事（案件・段の区切り）が全部終わった時に 1 回、コードから実物の絵を **自分で** 描いて（書いた窓の申告・PR 本文の絵は使わない）`compare` で合意した版と照らし、箱ごとに設計どおりかを完了の報告に 1 か所書く（「設計図どおり」か「差とその扱い」）。PR ごとには照らさず、合意した絵の無い仕事は照らさない。作り方のずれは AI が設計どおりに直す（聞かない）。設計そのものを変える必要が出た時だけ、絵に戻ってオーナーと合意し直す。合流の条件ではないので、差があっても絵が無くても main へ入れるのを止めない。
4. **「なんでこうなるの？」と聞かれた時**: 3 つの形を全部出す。①`problems` に問題を足して `render` した絵を `?layer=explain&p=<id>` で渡す（起きた所・原因の箱が印つきになり、間の流れが光る）②`explain` の文をチャットに貼る（箱の名を挙げる）③原因の箱を押すと、その箱の意図と「なぜここから起きたか」が並ぶ（型がする）。足した問題は絵に残し、同じ箱で何度起きたかを「起きた問題」の層で見せる。
5. **仕組みを変える時**: 設計の時に合意した絵から掘り下げて考える。途中の細部の変化は AI が絵を直して最新に保つ（聞かない）。箱・流れ・意図が変わる時だけオーナーの OK を取って版を上げる。絵の直しを合流の前提にしない。

## repo ごとの値（config/skill-values.json）

| 鍵 | 使う所 | 無い時の既定 |
|---|---|---|
| `docs-kit.big-picture.agreed` | 合意した絵の在り処。repo 全体で 1 枚なら文字列（repo の中の path か、案件のページの名）。1 repo に製品が複数あるなら製品ごとの並び `[{"name": "<製品>", "path": "<在り処>", "covers": ["<その製品の path の頭>", …]}]`（全体を覆うのは `"/"`）。照らしを頼まれた時は `big_picture.py pick` で触った file を覆う絵だけを選ぶ（覆わない file は照らせないと名指す。合流は止めない） | repo の根の `docs/全体の絵.json`。それも無ければ「絵が無い」と名指す（合流は止めない） |
| `common.delivery` | HTML の渡し方 | Artifact で publish（非公開のまま）か `file:///…` の絶対パスを 1 行 |

## 渡す前に

- `check` が `CHECK OK`（exit 0）。赤い点の数を見どころに 1 行で書く（埋まっていないと言う）。
- 渡す HTML は `render` で描き直した物だけ。チャットには URL 1 行と見どころ（赤い点の数・起きた問題の数）だけ。
