# /mindmap — 組み替え＋コメントできるマインドマップ

## 大原則

構造のある情報（工程・分類・論点・企画の骨子など）を **箇条書きの文章で並べない**。代わりに **1枚のマインドマップHTML** を作って渡す。Claude が題材を **たたき台のツリー** に組み、オーナーは **⠿ドラッグで組み替え・🎨色替え/メモ化・💬コメント・タイトル/説明をその場で書き換え** て加工し、**「この形をコピー」で並び・#id・コメント・タグごとチャットに貼り戻す**。作り手は貼り戻された1本のテキストを読めば、オーナーが情報をどう構造化し直したか・どこに指示/相談を付けたかが全部分かる。

これは qa-html（回答型HTML）の姉妹＝**「往復パターン」の“情報整理・組み替え”版**。qa-html が「A/B の判断を仰ぐ」道具なのに対し、mindmap は「**情報の構造そのものをオーナーと合わせる**」道具。認識合わせ・工程の設計・分類の詰めに使う。

## 所属モード

トリガを受けたら**宣言も確認もなしで単一操作として実行**する（「作りますか？」「これでOK？」を出さない・会社の規律は表の `common.rules.no_confirm`）。作った後は下の 6 の渡し方で渡す。

## repo ごとの値（config/skill-values.json）

repo ごとに違う値は、repo の根（`git rev-parse --show-toplevel`）の `config/skill-values.json` の `docs-kit.mindmap.<鍵>` と `common.<鍵>` から読む（skill の鍵が common に勝つ）。**鍵が無い・値が空なら右の既定で動く**。

| 鍵 | 使う所 | 無い時の既定 |
|---|---|---|
| `docs-kit.mindmap.save_dir`（無ければ `common.save_dir`）/ `common.save_dir_avoid` | 作り方 5 の置き場・置かない所 | 窓の scratchpad（git の外・作業中の repo に置かない） |
| `docs-kit.mindmap.delivery`（無ければ `common.delivery`） | 作り方 6 の渡し方 | `file:///…` の絶対パスを 1 行 |
| `common.rules` | 確認装置禁止・二重出力禁止の会社の正本 | この SKILL の本文の規則だけで動く |
| `common.glossary` | 本文の語（オーナー 等）の意味 | 語の一般の意味 |

## いつ使うか（判断）

| 状況 | 使う？ |
|---|---|
| 工程・手順・パイプラインを「背骨（STEP）＋枝」で見せて組み替えてもらう | ◎ この skill |
| 分類・論点・企画骨子など、**入れ子の構造**をオーナーと合わせたい | ◎ この skill |
| 各要素に「これは指示／これは相談」「自動でできる／人が要る」の印を付けて返してほしい | ◎ この skill |
| A/B の方針・設計・スコープを1つ選んで決めてもらう | 核 §4 の聞き方（1 つを選ぶ＝選択肢の画面・論点が幾つも＝qa-html） |
| 画面を見ながら決めたいことに答えてもらう（全画面の触れるモック） | theory-mock（理論モック） |
| 単なる報告・現在地の可視化（加工させない） | 使わない |

## 作り方（skip 禁止）

1. **`references/template.html` を読む** = engine（骨格・CSS・描画/ドラッグ/コメント/ズーム/貼り戻しJS）の正本。**CSS と JS は変えない**（オーナー承認済みの動作＝ドラッグ組み替え・#id 固定・貼り戻し）。差し替えるのは **`const SEED`（ツリー本体）／`const PREMISE`（前提ドロワー）／ヘッダー文言／凡例** だけ。
2. **`const SEED` を題材のツリーに組む**（下の§ノード schema）。root は1つ、背骨は `step:true` の STEP カード、その下に子カードをぶら下げる。**たたき台として8割方組む**（空白キャンバスを渡さない＝オーナーは「直す」方が速い）。
3. **`const PREMISE` を埋める**（前提＝ステップの外側でずっと効く土台。goal/verify/work/cross の4欄。不要な欄は1項目で薄く）。
4. **ヘッダー**（`.eyebrow`/`h1`/`.lead`）と **凡例（`.legend`）** を題材に合わせて書き換え（凡例は色→段名の対応。SEED の STEP 色と合わせる）。`.hint`（操作説明）は触らない。
5. **保存** = 表の `docs-kit.mindmap.save_dir`（無ければ `common.save_dir`・それも無ければ窓の scratchpad＝git の外）。`common.save_dir_avoid` には置かない。名前は `確認_<件名>_マインドマップ_<YYYYMMDD>.html`。
6. **渡す** = 表の `docs-kit.mindmap.delivery`（無ければ `common.delivery`・それも無ければ `file:///…` の絶対パスをチャットに1行）+ 「どういう背骨で組んだか・特に見てほしい枝」を数行だけ添える（HTML本文をチャットに再展開しない＝二重出力禁止）。

## ノード schema（`const SEED` = 入れ子オブジェクト。engine が読む欄）

```js
const SEED = {
  id:"c1", root:true, t:"テーマ", sub:"入口の一言", col:"#172b3a",
  children:[
    { id:"c10", step:true, no:"STEP ①", t:"段の名前", sub:"この段の説明", col:"#6a4a8a",
      children:[
        { id:"c11", kind:"memo", t:"補足メモ", sub:"本筋でない注記＝グレーの点線カード" },
        { id:"c12", tags:["auto"], badge:"ok", t:"確定項目", sub:"…",
          children:[ { id:"c13", tags:["human"], badge:"warn", t:"要判断", sub:"…", memoS:"壁打ちの問い" } ] }
      ] }
  ]
};
```

| 欄 | 意味 |
|---|---|
| `id` | `"c1"` 形式。**#id は組み替えても不変**＝貼り戻しで枝を指す鍵。空なら engine が自動採番 |
| `root:true` | 入口カード（濃紺）。1つだけ |
| `step:true` + `no` | 背骨カード。`no:"STEP ①"` の見出しが付く。`col` で段の色 |
| `t` / `sub` | タイトル / 説明メモ（どちらもクリックで書き換え可） |
| `col` | 色（hex）。パレット: teal `#176b87`／purple `#6a4a8a`／blue `#2f5aa8`／green `#2e7d46`／amber `#9a6a00`／rose `#b3261e`／slate `#5f6368`／navy `#172b3a` |
| `kind:"memo"` | グレーの点線＝メモカード（流れの本筋でない注記） |
| `badge` | カードの状態バッジ。`ok`=✓確定／`warn`=⚠未確定／`scope`=スコープ外／`goal`=🎯出力／`ans`=🔎調べた答え／`memo`=📝メモ |
| `tags` | `["auto"]`=🤖自動でできる／`["human"]`=👤人が要る／自由文字列=🏷自由タグ（両方付け可＝候補は自動・確定は人） |
| `acts` | 動作チップ（任意）。`計算`/`逆算`/`判断`/`加工` を色付きチップで表示 |
| `memoI` / `memoS` | 初期コメント。`memoI`=📌指示（実行してほしい）／`memoS`=💬相談メモ（壁打ち・質問） |
| `children` | 子カードの配列 |

## 前提ドロワー（`const PREMISE`）

右上「▤ 前提」で開く引き出し。ステップの外側で効く土台をここに畳む。4欄すべて配列で置く（各要素 `{t, sub?}`、入れ子可）:

```js
const PREMISE={
  goal:[{t:"作業のゴール", sub:"何が満たされたら完成か"}],   // 🎯 ゴール
  verify:[{t:"守るべき約束・前提"}],                          // 🧮 検算の約束
  work:[{t:"繰り返す動作", sub:"どの段にも付きまとうループ"}], // ♺ 作業の正体
  cross:[{t:"横断の未確定", sub:"背骨に乗らない論点"}],        // ⚠ 横断の未確定
};
```

## 貼り戻しの読み方

オーナーが「📋 この形をコピー」で貼り戻すテキストには、**組み替え後のツリー（インデント＋#id）・各カードの 📌指示／💬相談・🤖/👤/🏷 タグ・色/メモ化の変更** が1本にまとまっている。**#id で元カードと突き合わせ**、📌指示は実行対象、💬相談は答える対象として扱う。オーナーが動かした構造そのものが「オーナーの認識」＝それを正として次へ進む。

## engine 不変の鉄則（触らない）

- CSS / JS / 貼り戻しJS は**変えない**（描画・SVGコネクタ・ドラッグ&ドロップ・#id固定・折り畳み・ズーム・undo・PDF保存・コピーの契約）。差し替えは SEED / PREMISE / ヘッダー文言 / 凡例のみ。
- ボタン群（全部ひらく／背骨＋主要／最初に戻す／↩もどす／▤前提／📄PDF保存／📋この形をコピー）はそのまま使う。

## 自己完結の鉄則

- **外部リソース禁止**（CDN・外部フォント・画像URL・fetch）。CSS/JS は全部 inline。`file://` で開いてオフラインで完動すること。
- 画像が要る時のみ data URI で埋め込む。
