# /theory-mock — 画面を見ながら要件をすり合わせる理論モック

## 大原則

要件を **文章の箇条書きで詰めない**。代わりに **全画面を触れる 1 枚の HTML（理論モック）** を作って渡す。オーナーは左の目次で画面を巡り、**その画面に関わる「決めたいこと」に ○×△＋一言** を付け、画面そのものにもコメントし、最後に **下の帯の「回答とコメントをコピー」1 回で全部をチャットへ貼り戻す**。作り手は貼り戻しの Q 番号・画面番号で突き合わせれば、どこが推奨どおりで、どこが違うかが全部分かる。

理論モックは **要件すり合わせ用の触れる絵** であって **本番の UI ではない**（見た目の磨き込み・実装は別工程）。

**作っている製品の本物の画面の ○ には使わない**（本物の画面の ○ は本物の画面で取る）。

## 所属モード

トリガを受けたら**宣言も確認もなしで単一操作として**作って渡す（「作りますか？」「これでOK？」を出さない・会社の規律は表の `common.rules.no_confirm`）。

## 作り方（skip 禁止）

1. **`references/template.html` を写して始める** = 枠（CSS・描画・保存・コピー・selftest）の正本。**枠は変えない**。差し替えるのは `/* ==== CONTENT START ==== */` 〜 `/* ==== CONTENT END ==== */` の 1 区画だけ（下の §中身の区画の schema）。見本の中身（架空の会議室予約）は全部消して題材で置き換える。
2. **最初の画面は「要件の整理」**（`id:'req'`）＝目的（1 行）・使う人・範囲（やる／やらない／後で）・守る約束・完成の定義・流れ（戻りも）・画面の地図（`screenMap()`）・DB/原本の一覧（`linkList()`）。ここが合えば、あとの画面は「この要件をどの画面で満たすか」の話になる。
3. **画面をグループ（`grp`）で並べる**。各画面に `lead`（何の画面か 1〜2 文）・`does`（できること）・`links`（入る/見る DB・原本）・`qs`（関わる質問の番号）を必ず埋める。本体 `body` は枠の部品（`app`／`tbl`／`go`／`lk` ほか）で偽アプリの画面を描く。
4. **質問（`Q`）は必ず推奨と「なぜ決めるか」を埋める**＝たたき台を 8 割まで作る（空欄の質問を渡さない＝オーナーは○を付けるか直す方が速い）。「すり合わせ（全質問）」画面は枠が末尾に自動で足す＝中身に書かない。
5. **ダミーデータは実名・実額にしない**（従業員A・サンプル会社・丸めた架空の額）。会社名・人名・Drive/Sheet の ID を中身に書かない（リンクが要る時も共有前提のものだけ）。
6. **Q 番号と画面 id は作り直しでも変えない**（貼り戻しと保存済み回答の鍵）。消す時は欠番にし、詰め直さない。`META.storageKey` も同じ題材なら変えない（前の回答が残る）。
7. **保存** = `確認_<件名>_理論モック_<YYYYMMDD>.html`。置き場は表の `common.save_dir`（無ければ窓の scratchpad＝git の外・PR に載せない）。`common.save_dir_avoid` には置かない。
8. **検査してから渡す** = `python3 <この skill>/scripts/check_theory_mock.py <保存した html>` で `SELFTEST OK <n> screens`（exit 0）を取る。NG なら直してから（NG 行＝画面 id と例外。飛び先の無い `data-go`・`Q` に無い番号・`LINKS` に無いキーも NG）。exit 2 は Chrome が無い／起動できない＝検査できていない（OK と言わない）。
9. **渡す** = 検査を通した html を表の `common.delivery` で渡す（無ければ Artifact で publish し非公開のまま・共有しない／`file:///…` の絶対パスでもよい）。チャットには URL 1 行と「見どころ」数行（特に答えてほしい Q・迷った画面）だけ。HTML の中身をチャットに再展開しない。

## 貼り戻しの受け方

貼り戻しは次の形で届く（枠が作る・形を変えない）:

```
# <題> — 回答（<日時>）

## 決めたいこと
- Q<n> <題>: ○ / × / △ / — （一言があれば「 ／ 一言」）

## 画面へのコメント
- <画面番号> <画面の題>: 一言
```

- **Q 番号・画面番号で元と突き合わせる**。○＝推奨で確定。×・△と一言は要件に反映（× は一言の方向へ直す、△ は論点として残す）。一言やコメントの中の疑問には答える。
- 反映したら同じ HTML の中身を直して作り直す（Q 番号・画面 id・storageKey は据え置き＝オーナー側の回答は残る）。

## 中身の区画の schema（CONTENT START〜END）

| 名前 | 形 | 意味 |
|---|---|---|
| `META.title` / `META.by` | 文字列 | 左上の題（コピーの見出しにもなる）／その下の一行 |
| `META.storageKey` | 文字列 | 回答の保存名（localStorage）。空なら題から作る。作り直しでも変えない |
| `META.home` | 画面 id | 最初に開く画面（空なら先頭） |
| `META.app` | `{logo, selects:[[選択肢…],…], user}` | 偽アプリの上部（ロゴ文言・選択欄・利用者表示）。画面側で `app(…,{noselect:1})` なら選択欄を出さない |
| `META.flow` | `{steps:[[id,label],…], state:{id:'done'｜'wait'｜''}}` | 工程バー。`steps` の id は画面 id。空配列なら出さない。画面の `step` がここの id を指すと、上の工程リンクと窓の中の段バーが出る |
| `LINKS` | `{キー:{label, url｜null, note, icon?}}` | DB 見本・原本へのリンク。`url:null` は黄の「見本なし」＝要件で中身を決める物。`icon` 既定 🗄（原本は 📄 など） |
| `Q` | `{番号:[題, 推奨, なぜ決める]}` | 決めたいこと。番号は変えない |
| ダミーデータ | 任意の `const` | 画面の body から使う（実名・実額にしない） |
| `ACTS` | `{名前:(el, ev)=>{…}}` | 題材固有の動き。HTML に `data-act="名前"` と書くと押した時に呼ばれる。無い名前は何もしない。トーストだけなら `data-toast="文言"` で足りる |
| `def({…})` | 画面 1 枚 | `id`（不変）・`grp`（目次のグループ）・`n`（画面番号＝貼り戻しに出る）・`t`（題）・`lead`・`does:[]`・`links:[LINKS のキー]`・`qs:[Q 番号]`・`step?`（工程 id）・`body:()=>HTML` |

枠の部品（body から呼ぶ）: `app(crumb, body, opt)`／`go(id, label, cls)`／`tbl(head, rows, {num:[列]})`／`cc(v)`・`yen(n)`／`lk(key)`／`linkList(keys?)`／`screenMap()`／`toast(text)`。HTML の口: `data-go="画面id"`・`data-act`・`data-toast`・`data-tabs`（ボタン `data-t` と `.pane` の `data-p` で切替）。

## 枠の鉄則（触らない）

- 左の目次（グループ・質問数バッジ）・右の欄（できること・DB・この画面の質問・コメント）・社内すり合わせ／先方に見せる の切替（`.internal` は先方モードで隠れる）・○×△＋一言・下の帯（件数・コピー・消去）・コピーの形・`?selftest` は **変えない**。
- **外部リソース禁止**（CDN・外部フォント・画像 URL・fetch）。CSS/JS は全部 inline。`file://` でオフライン完動。
