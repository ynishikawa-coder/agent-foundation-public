# /qa-html — 確認ページ（1 つの型）

## 大原則

お客さんなど選択肢の画面を使えない相手に聞く時と、オーナーが確認 HTML を頼んだ時は、**1 枚の確認ページ**を作って渡す（道具の選び方は核 §4）。どの宛先も、事務所や会社を問わず**同じ 1 つの型**（`references/template.html`）で作る。

- **流れ**: はじめ（宛名・件名・全 N 問・目安の分・期限）→ **1 画面 1 問** → 送る前の確認（全部の答えと「変える」）→ 受付（受付番号・この後のこと・控え）。JS が切られた端末では全問を縦に並べ、そのまま送れる。
- **見た目**: 明るい色で固定（相手の端末が暗い設定でも明るく出す）・本文 18px・行間 1.6・選択肢は行ぜんぶが押せて高さ 48px 以上。
- **宛先で変えてよいのは 2 つだけ**: 宛名（`.to`）・会社の色 1 つ（`<body style="--brand:#rrggbb">`）。ほかの見た目と動きは型のまま（検査が `qa:css`・`qa:js`・`qa:foot` を型と突き合わせる）。**差出人・連絡先の欄は置かない**（ページは配る人が自分の送る文と一緒に渡す＝名乗りと問い合わせ先は送る文に書く・2026-11-14 オーナー決定。`.from`・`.contact` が残っていると検査が赤）。
- **未回答があると送れない**。全問に「分からない・社内で確かめてから答える」を置き、どう答えても次へ進める。
- **何のための・どんな前提の問いかを、3 段で必ず見せる**（§前提の 3 段）。前提が書けない問いは出さない（検査が赤）。

宛先の印 `<body data-dest="…">` は 3 つ:

| 印 | いつ | 送った時 |
|---|---|---|
| `send`（送る） | 配る口のある会社がお客さんに聞く | 素のフォームの送信で配る口へ。受付の画面は配る口が出す |
| `copy`（写す） | オーナーが確認 HTML を頼んだ | 受付の画面に貼り戻しのテキストが出る＝チャットに貼る |
| `artifact`（確認のページ） | 確認を Artifact（claude.ai の非公開のページ）で渡す | 受付の画面を出し、`document` に `qa:submit` を投げる＝ページの仕組みが答えを持つ |

## 所属モード

トリガを受けたら**宣言も確認もなしで単一操作として実行**する（「作りますか？」「これでOK？」を出さない・会社の規律は表の `common.rules.no_confirm`）。作った後は作り方 7 の渡し方で渡す。

## 前提の 3 段（どこに何を書くか）

説明を 1 か所に積まず、3 段に分ける。どの段に何を書くかが決まっていれば、前提が抜けず、長くもならない。

1. **ページ全体（はじめの画面）**: 何の仕事の確認か（件名・前書き）／**読んだ資料の一覧**（`.docs` の `<li data-doc="鍵">`＝資料名・期間・受け取った日。「この中から聞いています」）／**答えるまでの扱い**（`.hold`・例「答えが届くまで、この点は確定せずにお待ちします。」）／期限。
2. **まとまり**: 見出し（`data-group`・`data-glabel`）＋ **1 行だけ**（`.glead`・各まとまりの最初の問いに 1 つ・例「規程に書いていない・法律と合わない所です」）。説明の画面は挟まない。
3. **1 問＝固定の 4 欄**（どの問いも同じ所に同じ事を書く）:

| 欄 | 書く所 | 中身 | 上限 |
|---|---|---|---|
| 何について | `.about` の `<span>`（人の名は `<span class="who">`） | 誰・いつ・何の札 | 3 つまで |
| 見つけた事 | `.known`（`data-docs="読んだ資料の鍵…"`） | 資料名・場所・値。食い違いは両方。書いてない時は**探した資料**と、こちらの見込み | 2 行・1 行 60 字＋数字の表 5 行 |
| 　＋資料の切り抜き | `.clips` の `figure.clip`（`data-doc`・`data-shows`・`img` は data URI・`alt`・`figcaption`） | 該当の所に黄の印。押すと大きく。食い違いは 2 枚を横に並べる | 1 問 2 枚まで |
| なぜ聞くか | `.why`（`data-why`） | 決まった 4 文のどれか（下の表） | 1 行 |
| くわしく | `details.more`（資料の原文は中の `.orig`） | 決まり・計算の元・語の説明 | 3 行＋原文 |

なぜ聞くかの決まった 4 文（`check.mjs` の `RULES.why`・会社の表の `docs-kit.qa-html.why` で文だけ替えられる）:

| `data-why` | 文 | 見つけた事に書く物 | 選択肢の形 |
|---|---|---|---|
| `mismatch` | 資料どうしで食い違っています | 2 つの資料の名・場所・値（切り抜きを横並び）。`data-kind="mismatch"` はこれ | どちらか＋ほかの答え |
| `missing` | 資料に書いてありません | 探した資料の名と、こちらの見込み | 見込みのとおり／違う（ひとこと）／資料を送る |
| `law` | 今の決まりが法律の決まりと合っていません | 今の決まりの抜粋と、法律の決まりの言い換え 1 行 | 直す時期の候補／今のまま |
| `once` | 今回だけの事を確かめます | 読んだ事と、無いと読んだ事の一覧 | このとおり／足りない・違う |

- **切り抜きの守り**: 写すのは問いの人の行だけ。ほかの人の名前と額は塗りつぶしてから埋め込む。`data-shows` に切り抜きに写っている人の名を書く（問いの `span.who` の人だけ・誰も写らなければ `data-shows=""`・属性が無ければ赤）。4 欄の箱（`.about`・`.why`・`.known`・`.more`・`.clips`）は 1 問に 1 つずつ。人ごとの事実（`person`）の問いには `span.who` が要る。食い違い（`mismatch`）の切り抜きは 0 枚か 2 枚。`.glead` は問いの箱の中だけ。検査は、ほかの問いの人の名が `data-shows`・`alt`・`figcaption` に出たら赤にする。画像はページに埋め込む（外へ読みに行かない）。
- **選択肢ごとに「この答えで変わる事」**（`<small class="chg">`・誰の・何が・いくら・1 行）。画面には「変わる事: …」と出る。書かなくてよいのは逃げ道だけ（鍵と見出しの両方が `other`＝「ほかの答え」「別の決め方」・`none`＝「当てはまらない」の時と「分からない」・表は `RULES.free_options`）。
- **前置きで寄せない**: 前提の文はどちらにも寄せず事実だけ。おすすめは選択肢の印（`tag-rec`）だけ、理由は「くわしく」に。
- **「こう読みました」の一覧はこのページに載せない**（読んで決めた事は、結果を送る時の案内に添える）。
- **前提が書けない問いは出さない**: 何について・見つけた事（と読んだ資料の鍵）・なぜ聞くか・くわしく・選択肢ごとの変わる事 のどれかが空なら検査が赤。書けないのは、こちらの読み不足か要らない問い。

## 問いの形（3 つだけ）

聞く前に、届いた物の全部を読み、こちらで計算・判断できる事は問いにしない。聞くのは次の 3 つだけ:

| 形（`data-kind`） | いつ | 選択肢 |
|---|---|---|
| (a) `choose`「どちらが正しいですか」 | こちらで候補ごとに計算した結果が分かれる | 候補を並べ、それぞれの変わる事を 1 行（例「10 月の請求が合計 1,200 円」）＋「ほかの答え（ひとことに）」 |
| (b) `fact` 資料の外にしか無い事実 | 入社日・納品日など、資料の中に無い事 | 分かる範囲の候補＋「当てはまらない」 |
| (c) `judge` 読んでも決まりが分からない時の判断 | 決まりが資料に無い・読めない | 候補 2 つ以上（おすすめ `tag-rec` は 1 つまで）＋「別の決め方（ひとことに）」 |

どの形も、最後に「または」で区切って **「分からない・社内で確かめてから答える」**（`value="__unknown__"`）を置く。選ぶと、ひとことの欄が「誰に聞けば分かりますか」に変わる。

- **ひとことに書かせる選択肢**（「ほかの答え」「別の決め方」や、見出し・添え書き・変わる事で「ひとことに」「補足に書く」と頼む物）は、その `input` に `data-supp="need"`（JSON は選択肢に `"supp": "need"`・値は `need` だけ）を付ける。選ぶと欄の名が「ひとこと（この答えでは書いてください）」に変わり、空のままでは次へ進めず送れない（「分からない」も選んでいる時は任意の欄のまま）。「ほかの答え」「別の決め方」と、字に「ひとこと」「補足に書く」「補足欄」「下の欄」がある選択肢で印が無い物は `check.mjs` が赤。

- **選択肢に A・B などの記号を付けない**。中身が分かる見出し（`<b>`）と、この答えで変わる事 1 行（`<small class="chg">`）で書く。問いや見つけた事でも「A なら」と記号で指さない。
- **「合っていますか」は資料どうしが食い違う時だけ**（`data-kind="mismatch"`＝(a) の仲間・食い違う 2 つを見つけた事に書き、候補に両方を置く）。
- **数を書かせる問いにしない**。数はこちらで計算して候補に出す。数字は見つけた事の小さな表（今の計算／直した場合／差）で比べられるようにする。
- **1 問に 1 つ**。「〇〇と△△を教えてください」「、また」で 2 つ聞かない。
- **先方の言葉で書く**。専門の語は日常の言葉に言い換え、どうしても使う語は「くわしく」に一言の説明を置く。こちらの作り方や内部の言葉を書かない。過去の問いを番号で指さない。
- **問いの頭に番号を付けない**（進み具合「3 / 12 問」は型が出す）。

## 並べ方

問いは次の順に並べる（`data-group`）。同じ事が何人かに起きていれば 1 問にまとめて表で並べる。

1. `rule` 会社の決まり（全員に効く・判断が要る）
2. `person` 人ごとの事実（入社日・休んだ日など）
3. `once` 今回だけの事（その月だけの事など。見出しを替える時は `data-glabel="10 月だけの事"`）

## 長さの上限（会社の表の `limits` で変えられる）

| 所 | 上限 |
|---|---|
| 問い（legend） | 1 行・40 字 |
| まとまりの 1 行（`.glead`） | 1 行・40 字 |
| 何について（`.about`） | 札 3 つ |
| 見つけた事（`.known`） | 文 2 行・1 行 60 字＋数字の表 5 行（見出しを入れて）。残りは `details.more`（くわしく）へ |
| 切り抜き（`figure.clip`） | 1 問 2 枚 |
| くわしく（`details.more`） | 3 行（原文は `.orig` に別で） |
| 選択肢の見出し（`<b>`） | 30 字 |
| この答えで変わる事（`small.chg`） | 1 行・40 字 |
| 選択肢の添え書き（`<small>`・逃げ道の「下のひとことに…」など） | 1 行・40 字 |
| 1 枚の問いの数 | 12 問（目安 10 分・超えるなら 2 枚に分ける） |

## 悪い例とこう直す

| 悪い例 | こう直す |
|---|---|
| 選択肢が「A 承知のうえ今のまま」「B 1 分単位に直す」 | 「今のままにする／差額は毎月のお知らせに残す」「10 月分から直す／差額は次の支払いで払う」のように見出し＋結果 1 行 |
| 1 問に 3 つ詰めた | 1 問 1 つに分ける。分けて要らなくなった問いは消す |
| ある 1 日だけ聞いて、ほかの日を聞かなかった | 同じ事が起きている所を全部並べて 1 問にする |
| 長い文で計算の違いを説明した | 今の計算／直した場合／差 の小さな表にし、決まりの文は「くわしく」へ |
| 「確認したい事があります」とだけ書き、どの資料のどこを見て聞いているかが無い | 何について（誰・いつ・何）／見つけた事（資料名・場所・値＋切り抜き）／なぜ聞くか（決まった文）を埋める。埋まらないなら聞かない |
| 資料の写真に、ほかの人の名前と額が写っている | 問いの人の行だけを切り抜き、ほかの人は塗りつぶす。`data-shows` は問いの人だけ |
| 選択肢を選んで何が変わるのかが分からない | 選択肢ごとに「この答えで変わる事」（誰の・何が・いくら）を 1 行 |
| 選択肢が「決まったら連絡」1 つだけ | 候補を 2 つ以上と「分からない」。どう答えても次に進める形にする |
| 会社の決まりと人ごとの事実が混ざって並ぶ | 会社の決まり → 人ごとの事実 → 今回だけの事 の順に並べ替える |

## 作り方（skip 禁止）

1. **`references/template.html` を丸ごと複製**する。`<body data-dest>` を `send`・`copy`・`artifact` のどれかにし、`{{…}}` と問いの箱だけ差し替える。`qa:css`・`qa:js` の間は**1 字も変えない**。`qa:foot` の間は `{{この後のこと}}` だけ差す（字と `<br>` だけ）。型の外に書けるのは `check.mjs` の許す物の表 `ALLOW` の要素と属性だけ（`style`・`script`・`iframe`・`on…` の属性・`javascript:` などは赤・リンクは https・mailto・tel・# だけ・写真は img の `data:image/` だけ・会社の色は body の `--brand` だけ）。
2. **header（前提の 1 段目）**: 宛名（`.to`）・件名（`h1`）・前書き 1 文・**読んだ資料の一覧**（`.docs` の `li[data-doc]`）・**答えるまでの扱い**（`.hold`）・期限。差出人・連絡先の欄は書かない。全 N 問・目安の分は型が出す。
3. **版**: `<input type="hidden" name="__版__" value="…">` に版（例 `2026-11-13.1`）を入れる。**問いを直したら版を上げる**（どの問いの形への答えかを後から辿るため）。
4. **問いの箱を組む**（1 問＝1 つの `fieldset.q`・前提の 2・3 段目）: `data-qkey`＝問いの鍵（半角英数字と `_`・答えの `name` と同じ・元の表の行の鍵と同じにする）／`data-qlabel`＝一言の見出し／`data-kind`＝上の形／`data-group`＝並べ方／まとまりの最初の問いだけ `.glead`＝まとまりの 1 行／`.about`＝何について／`legend`＝問い 1 行／`.why`＝なぜ聞くか／`.known`＝見つけた事（`data-docs`・数字は `<table>`）／`.clips`＝切り抜き／`details.more`＝くわしく／選択肢 `label.opt`（`value`＝選択肢の鍵・半角英数字と `_`・最初の 1 つに `required`・`small.chg`＝この答えで変わる事）／「または」と「分からない」／ひとこと `name="supp_鍵"`。前提は問いの元の表（対象・理由・資料・探した資料・選択肢ごとの変わる事）から写す＝ページの側で作文しない。最後に `name="__自由記入__"` の箱を 1 つ。選択肢は radio を使う（checkbox は required を付けられず、JS が切られた端末では答えずに送れる＝幾つも選ばせる時だけ）。
5. **検査**: `node <この skill の dir>/check.mjs <file.html>`（Artifact 型に問いをデータで渡す時は `<file.json>`。送る形は表の `customer.check_cmd`＝この検査に配る口の契約と画面の写真を足した物）。**緑でなければ渡さない**。
6. **送る前の別の目**: 窓の中の助手（Agent ツール）に、作った文脈を渡さず **HTML だけ**を渡し、答える人の立場で 1 問ずつ読ませる。見る点は 4 つ: ①**ほかの資料を開かずに、何を聞かれているか分かるか**（前提の 4 欄と切り抜きだけで足りるか） ②どう答えても聞き直さずに済むか ③選択肢とひとことで答えが 1 つに決まるか ④既に知っている事・要らない事を聞いていないか。直したら 5 からやり直す。
7. **保存と渡し方**: 置き場は表の `save_dir`（無ければ窓の scratchpad・`common.save_dir_avoid` には置かない）、名前は `確認_<件名>_<YYYYMMDD>.html`。写す形は表の `delivery` で 1 行＋「おすすめと、特に判断が要る点」を数行（HTML の中身をチャットに再展開しない）。送る形は表の `customer.publish_cmd` で配る URL を作り、お客さんにその URL だけを渡す。

## 型の約束（受け手が合わせる所・触ると壊れる所）

業務のパックの起こし方と、配る口（答えを受ける側）は、この約束に合わせる。

### HTML の data の鍵

| 所 | 鍵 | 中身 |
|---|---|---|
| `<body>` | `data-dest` | `send`・`copy`・`artifact` |
| `<body>` | `style="--brand:#rrggbb"` | 会社の色 1 つ（白地に 4.5 以上の濃さ） |
| header | `.to` | 宛名（差出人 `.from`・連絡先 `.contact` の欄は外した＝在れば赤） |
| header | `.docs` の `li[data-doc]`・`.hold` | 読んだ資料の一覧（鍵は半角英数字と `_`）・答えるまでの扱い |
| form の中 | `input[name="__版__"]` | 版（半角英数字と `. _ -`） |
| form の中 | `input[name="__受付番号__"]` | 受付番号（送る時に型の JS が入れる。空で届いたら受ける側が出す） |
| `fieldset.q` | `data-qkey`・`data-qlabel`・`data-kind`・`data-group`・`data-glabel` | 問いの鍵・見出し・形・まとまり・まとまりの見出し |
| `fieldset.q` の中（4 欄） | `.glead`・`.about`（`span.who`）・`.why[data-why]`・`.known[data-docs]`・`details.more`（`.orig`） | まとまりの 1 行・何について（問いの人）・なぜ聞くか・見つけた事と読んだ資料の鍵・くわしく（原文） |
| 切り抜き | `.clips` の `figure.clip[data-doc][data-shows]`＞`img[src=data:image/…][alt]`・`figcaption` | 資料の鍵・写っている人の名（問いの人だけ）・画像・写っている事・資料名と場所 |
| 選択肢 | `input[name=<問いの鍵>][value=<選択肢の鍵>]`・`small.chg` | 「分からない」は `value="__unknown__"`・この答えで変わる事 |
| ひとこと・全体 | `supp_<問いの鍵>`・`__自由記入__` | 任意の文 |
| 受付 | `#qa-done`・`#qa-rno`・`.next` | 受付の画面・受付番号・この後のこと |

`form` は 1 つで `method`・`action` を書かない（配る口が書き込む）。送るボタンは `<button type="submit" id="sendbtn">` 1 つで、送る前の確認の中にある。写真は data URI。

### 送る形（素のフォーム）の項目

`<問いの鍵>=<選択肢の鍵>`（入力の欄の時は打った文）・`supp_<問いの鍵>`・`__自由記入__`・`__版__`・`__受付番号__`。配る口はこれに自分の印（シート・トークン・答えた方の名）を足して受ける。

### 答えの形（qa-html/2・機械で戻す JSON）

型の JS が作る形。写す形では貼り戻しの最後の行 `qa-json: {…}` に、確認のページでは `qa:submit` の `detail` に入る。配る口が JSON で受ける時もこの形にそろえる。

```json
{
  "form": "qa-html/2",
  "title": "件名",
  "version": "2026-11-13.1",
  "receipt": "R261113-7KQ4",
  "answered_at": "2026-11-13T22:41:00+09:00",
  "answers": { "q1": ["down"], "q2": ["__unknown__"] },
  "labels":  { "q1": ["切り捨てる"], "q2": ["分からない・社内で確かめてから答える"] },
  "supp":    { "q2": "店長に聞けば分かります" },
  "free": ""
}
```

- 1 送信＝1 行。**送り直しは新しい受付番号の新しい行**として足し、前の行は消さない。表へ戻す時は、問いの鍵ごとに一番新しい送信を正とし、版が今の版と違う答えには「古い版」の印を付ける。
- 受付番号は `R<YYMMDD>-<英数 4 字>`。型の JS が送る時に作る（JS が切られて空なら受ける側が同じ形で出す）。

### 貼り戻しのテキスト（写す形）

1 行目 `# <title> — 回答`、2 行目 `版: … ／ 受付番号: …`、問いごとに `■ 問N [鍵]: <data-qlabel>` と `   → 回答: …`（ひとことがあれば `   → 補足: …`）、`■ その他・全体の意向:`、最後に `qa-json: {…}`。貼り戻しを拾う仕組みがこの形を読む＝変えない。

## 問いのデータ（Artifact 型に渡す時）

確認を Artifact 型（中身をデータで受ける型）で作る時は、問いを次の JSON にして `check.mjs` にかけてから型に渡す。問いの中身はこの JSON が正本。**「分からない」と「ほかに伝えたい事」は型の側が足す**（データに書かない）。

```json
{
  "dest": "artifact", "version": "2026-11-13.1", "brand": "#0f6e66",
  "to": "宛名", "title": "件名", "lead": "前書き 1 文", "due": "期限", "next": "この後のこと",
  "hold": "答えるまでの扱い",
  "docs": [{ "key": "d1", "name": "読んだ資料の名・期間", "received": "受け取った日" }],
  "questions": [
    { "key": "q1", "label": "一言の見出し", "kind": "choose|mismatch|fact|judge", "group": "rule|person|once", "glabel": "まとまりの見出し（任意）",
      "glead": "まとまりの 1 行（まとまりの最初の問いだけ）",
      "about": ["誰", "いつ", "何"], "who": "問いの人の名（人の問いの時）", "why": "mismatch|missing|law|once",
      "question": "問い 1 行", "known": ["見つけた事（資料名・場所・値・2 行まで）"], "docs": ["d1"],
      "table": [["", "今の計算", "直した場合"], ["合計", "1,200 円", "1,300 円"]],
      "clips": [{ "doc": "d1", "src": "data:image/png;base64,…", "alt": "写っている事", "caption": "資料名と場所", "shows": ["問いの人の名"] }],
      "options": [{ "value": "down", "label": "中身の見出し", "change": "この答えで変わる事 1 行", "recommended": true },
                  { "value": "other", "label": "別の決め方", "detail": "下のひとことに書いてください", "supp": "need" }],
      "input": "text|date|month|number（選ばせない時だけ）",
      "more": "くわしく", "supp": true }
  ]
}
```

- 選択肢は `{"value","label","change"}` の形（文字だけは赤＝機械で戻せない）。逃げ道（`other`・`none`）は `change` の代わりに `detail`（添え書き）。`supp` は省けば有り（`false` にすると赤）。なぜ聞くかの文は型の側が `why` から出す。
- 見る決まりは HTML と同じ（宛先の印・宛名・版〔`from`・`contact` の鍵は外した＝在れば赤〕・前提の 3 段と 4 欄・切り抜き・変わる事・形・並び・内部の言葉・長さ・記号・選択肢・1 問 1 つ・事実の問いの「当てはまらない」・ひとこと・鍵の重なり）。

## 自己完結の鉄則

- **外部リソース禁止**（CDN・外部フォント・画像 URL・fetch）。CSS/JS は型の中の 1 つずつだけ。`file://` で開いてオフラインで完動すること。画像が要る時は data URI。
- 途中の保存はその端末のブラウザにだけ残す（保存が使えない端末でも答えて送れる）。
