# /qa-html — 回答型HTML（1 つの形）

## 大原則

お客さんなど選択肢の画面を使えない相手に聞く時と、オーナーが確認 HTML を頼んだ時は、**1 枚の回答型 HTML** を作って渡す（道具の選び方は核 §4）。どの相手にも**同じ 1 つの形**で、違うのは 2 つだけ:

| | 宛名（header の 1 行目） | 最後のボタン（`<body data-dest="…">` の 1 つの印で切り替える） |
|---|---|---|
| 写す（`copy`） | 例「オーナーへの確認」 | 「回答を写す」＝答えが貼り戻しのテキストにたまり、チャットに貼る |
| 送る（`send`） | 例「〇〇様 ご確認のお願い」 | 「回答を送る」＝素のフォーム送信で回答の置き場へ（配る口が要る） |
| 確認のページ（`artifact`） | 例「オーナーへの確認」 | 確認のページ（Artifact）が答えを持つ＝ページの仕組みが答えをためる（下の §確認のページ） |

オーナーへの問いは選択肢の画面で聞く（核 §4）。この skill は、お客さんなど選択肢の画面を使えない相手に聞く時と、オーナーが確認 HTML を頼んだ時に使う。

## 所属モード

トリガを受けたら**宣言も確認もなしで単一操作として実行**する（「作りますか？」「これでOK？」を出さない・会社の規律は表の `common.rules.no_confirm`）。作った後は作り方 7 の渡し方で渡す。

## repo ごとの値（config/skill-values.json）

repo の根（`git rev-parse --show-toplevel`）の `config/skill-values.json` の `docs-kit.qa-html.<鍵>` と `common.<鍵>` から読む（skill の鍵が common に勝つ）。**鍵が無い・値が空なら右の既定で動く**。

| 鍵 | 使う所 | 無い時の既定 |
|---|---|---|
| `docs-kit.qa-html.save_dir`（無ければ `common.save_dir`）/ `common.save_dir_avoid` | 作り方 6 の置き場・置かない所 | 窓の scratchpad（git の外） |
| `docs-kit.qa-html.delivery`（無ければ `common.delivery`） | 写す形の渡し方 | `file:///…` の絶対パスを 1 行 |
| `docs-kit.qa-html.customer.*` | 送る形の口（設計 `design_doc`・配る口 `service`・回答の置き場 `answers_to`・検査 `check_cmd`・出す道具 `publish_cmd`/`publish_does`） | 送る形は使えない（写す形だけ） |
| `docs-kit.qa-html.internal_words` | 検査が赤にする内部の言葉に会社の語を足す（文字列か `{語, 正規表現, 言い換え}`） | `check.mjs` の頭の表 `RULES` の語だけ |
| `docs-kit.qa-html.limits` | 長さ・問いの数の上限を上書き | 下の §長さの上限 |
| `common.rules` / `common.glossary` | 確認装置禁止・喋り方・根治・二重出力禁止の正本／本文の語の意味 | この本文の規則だけ・語の一般の意味 |
| `docs-kit.qa-html.distribution` | この skill の配り方 | 無し |

## 問いの形（3 つだけ）

聞く前に、届いた物の全部を読み、こちらで計算・判断できる事は問いにしない。聞くのは次の 3 つだけ:

| 形（`data-kind`） | いつ | 選択肢 |
|---|---|---|
| (a) `choose`「どちらが正しいですか」 | こちらで候補ごとに計算した結果が分かれる | 候補を並べ、それぞれの結果（例「A なら 合計 X 円」）を添える＋「どちらでもない（補足に）」 |
| (b) `fact` 資料の外にしか無い事実 | 納品日など、資料の中に無い事 | 必ず「まだ分からない」「該当しない」を置く＝どう答えても聞き直さずに済む |
| (c) `judge` 読んでも決まりが分からない時の判断 | 決まりが資料に無い・読めない | 候補 2 つ以上（推奨に `tag-rec` を 1 つ）＋「別の決め方（補足に）」 |

- **「合っていますか」は資料どうしが食い違う時だけ**（`data-kind="mismatch"`＝(a) の仲間・食い違う 2 つを「分かっている事」に書き、候補に両方を置く）。読めて決まった事を「合っていますか」で確かめない。
- **数を書かせる問いにしない**（「〇〇の日数を書いてください」）。数はこちらで計算して候補に出す。数を打ち込む欄は禁じないが、問いの文を「数を書いて」の形にしない。
- **1 問に 1 つ**。「〇〇と△△を教えてください」「、また」で 2 つ聞かない。
- **先方の言葉で書く**。こちらの作り方（どう読んだか・どの道具で計算したか）や内部の言葉を書かない。過去の問いを番号で指さず、言葉で書き直してリンクを付ける。
- **自由記述の補足は全問に残す**（`supp_鍵`）。

## 長さの上限（推奨で決めた値・会社の表の `limits` で変えられる）

| 所 | 上限 |
|---|---|
| 問い（legend） | 1 行・40 字 |
| 分かっている事（`.known`） | 2 行・120 字（残りは `details.more` へたたむ） |
| この答えで決まる事（`.decides`） | 1 行・40 字 |
| 選択肢の見出し（`<b>`） | 50 字（中身は `<small>` に 1 行） |
| 1 枚の問いの数 | 12 問（超えるなら要らない問いを外すか 2 枚に分ける） |

## 悪い例とこう直す

| 悪い例 | こう直す |
|---|---|
| 1 問に 3 つ詰めた | 1 問 1 つに分ける。分けて要らなくなった問いは消す |
| ある 1 日だけ聞いて、ほかの日を聞かなかった | 同じ事が起きている所を全部並べて 1 問にする（「この 3 日は、どちらで計算しますか」） |
| 日数だけ聞いて、時間が残った | 決めたい事（請求額）まで届く候補を並べる（「A なら 合計 X 円」） |
| 「予定表では止まっている」という事実を書かずに聞いた | 分かっている事に資料の事実を書いてから聞く |
| 選択肢が「決まったら連絡」1 つだけ | 「まだ分からない」「該当しない」を置き、どう答えても次に進める形にする |

## 作り方（skip 禁止）

1. **`references/template.html` を丸ごと複製**する。`<body data-dest>` を `copy`（写す）か `send`（送る・配る口がある会社だけ）にし、`{{…}}` と問いの箱だけ差し替える。`qa:css`・`qa:toc`・`qa:foot`・`qa:js` の印の間は**変えない**（ほかの道具がこの 4 か所を写して使う）。
2. **問いの箱を組む**（1 問＝1 つの `fieldset.q`）: `data-qkey`＝鍵（半角英数字と `_`・`name` と同じ）／`data-qlabel`＝一言の見出し（貼り戻しと回答の置き場に出る）／`data-kind`＝上の形／`legend`＝問い 1 行／`.known`＝分かっている事／答える欄（`label.opt` の radio・checkbox・select・日付など）／`details.more`＝たたんだ補足（根拠の資料へのリンク・写真）／`.decides`＝この答えで決まる事／`.supp` の `textarea name="supp_鍵"`。最後に `name="__自由記入__"` の箱を 1 つ。
3. **header**＝宛名 / 題 / 前書き 1 文（「〇〇で確かめたい事が N 件あります。」だけ・作り方や前提を書かない）。
4. **検査**: `node <この skill の dir>/check.mjs <file.html>`（確認のページを Artifact 型で作り、問いをデータで渡す時は `<file.json>`。送る形は表の `customer.check_cmd`＝この検査に配る口の契約と画面の写真を足した物）。**緑でなければ渡さない**。
5. **送る前の別の目**: 窓の中の助手（Agent ツール）に、作った文脈を渡さず **HTML だけ**を渡し、答える人の立場で読ませる。見る点は 3 つ: ①どう答えても聞き直さずに済むか ②選択肢と補足で答えが 1 つに決まるか ③既に知っている事・要らない事を聞いていないか。直したら 4 からやり直す。
6. **保存**＝表の `save_dir`（無ければ窓の scratchpad）。`common.save_dir_avoid` には置かない。名前は `確認_<件名>_<YYYYMMDD>.html`。
7. **渡す**: 写す形は表の `delivery` で 1 行＋「推奨と、特に判断が要る点」を数行（HTML の中身をチャットに再展開しない＝二重出力禁止）。送る形は表の `customer.publish_cmd`（`customer.publish_does` の通りに置いて配る URL を返す）でお客さんにその URL だけを渡す。

## 型の契約（触ると壊れる所）

- **写す形の貼り戻しテキスト**: 1 行目 `# <title> — 回答`、問いごとに `■ 問N: <data-qlabel>` と `   → 回答: …`（補足があれば `   → 補足: …`）、最後に `■ その他・全体の意向:`。貼り戻しを拾う仕組みがこの形を読む＝変えない。
- **送る形（配る口の前提）**: `<form>` は 1 つ・`method`/`action` を書かない（配る口が書き込む）・鍵は半角英数字と `_`・補足は `supp_鍵`・全体は `__自由記入__`・`<button type="submit">` を消さない・写真は data URI・送信の JS（fetch 等）を書かない。
- 一覧の ✓・「N / M 問 答えました」・写すボタンは `qa:js` が描く（JS が切られていても送る形は素のフォームで届く）。

## 確認のページ（Artifact）に当てる

確認を Artifact（claude.ai の非公開のページ）で渡す時も、**問いの決まりは同じ `check.mjs` 1 本が見る**（決まりの表 `RULES` を写さない）。形は 2 つ:

- **ページの HTML を自分で書く時**: 公開の時に骨組み（`<body>`）が包まれるので、宛先の印は **ページの根の要素** に付ける（例 `<main data-dest="artifact">`）。`<body data-dest>` があればそちらが正。問いの箱（`fieldset.q` 以下）は上の作り方 2 と同じ。答えをためる仕組みはページの側（Artifact の仕組み）が持つ＝この skill は問いの中身だけを見る。
- **Artifact 型（中身をデータで受ける型）に渡す時**: 問いを次の JSON にして、その JSON を `check.mjs` にかけてから型に渡す。型が別の形を求める時は、この JSON から写す（問いの中身はこの JSON が正本）。

```json
{
  "dest": "artifact",
  "to": "宛名", "title": "題", "lead": "前書き 1 文",
  "questions": [
    { "key": "q1", "label": "一言の見出し", "kind": "choose|mismatch|fact|judge",
      "question": "問い 1 行", "known": ["分かっている事（2 行まで）"],
      "options": ["見出しだけの選択肢", {"label": "見出し", "detail": "中身 1 行", "recommended": true}],
      "input": "text|date|month|number（選ばせない時だけ）",
      "more": "たたんだ補足", "decides": "この答えで決まる事 1 行", "supp": true }
  ]
}
```

- `supp` は省けば有り（補足の欄を出す）。`false` にすると赤。`__自由記入__` の箱は型の側が足す（questions に書かない）。
- 見る決まりは HTML と同じ（宛先の印・形・内部の言葉・長さ・選択肢・1 問 1 つ・事実の問いの「まだ分からない」「該当しない」・補足・鍵の重なり）。

## 自己完結の鉄則

- **外部リソース禁止**（CDN・外部フォント・画像 URL・fetch）。CSS/JS は全部 inline。`file://` で開いてオフラインで完動すること。画像が要る時は data URI。

## 配り方（単一ソース）

- **正本** = この skill の dir（plugin の中）。直す時はここだけ直す。SKILL.md・`references/template.html`・`check.mjs` は常に 1 組で運ぶ。
- repo の中での配り方は表の `docs-kit.qa-html.distribution`。repo ごとの値はこの dir に書かない。

## 関連

- `references/template.html` — 1 つの形の正本（骨格・CSS・一覧と貼り戻しの JS）
- `check.mjs` — 検査（node だけで動く・HTML と問いの JSON の両方を読む・`import { checkQa, checkQaJson, checkFile }` でほかの検査からも呼べる）。頭の `RULES` が問いの決まりの表（形・上限・内部の言葉・数を書かせる形など）の 1 か所
- theory-mock（画面を見ながら決める時）・mindmap（構造そのものを組み替える時）
