# /qa-html — 確認ページ（1 つの型）

## 大原則

お客さんなど選択肢の画面を使えない相手に聞く時と、オーナーが確認 HTML を頼んだ時は、**1 枚の確認ページ**を作って渡す（道具の選び方は核 §4＝オーナーへの問いはまず選択肢の画面）。**宛先がオーナーでも、ページ（Artifact を含む）で聞くなら、この型・前提の 3 段・検査（`check.mjs`）を外さない**。独自の道具で作った問いのページを Artifact で出そうとすると、守りの hook（plugin guard の `qa_page`）が検査をかけ、赤なら止める。どの宛先も、事務所や会社を問わず**同じ 1 つの型**（`references/template.html`）で作る。

- **流れ**: はじめ（宛名・件名・全 N 問・目安の分・期限）→ **1 画面 1 問** → 送る前の確認（全部の答えと「変える」）→ 受付（受付番号・この後のこと・控え）。JS が切られた端末では全問を縦に並べ、そのまま送れる。
- **見た目**: 明るい色で固定（相手の端末が暗い設定でも明るく出す）・本文 18px・行間 1.6・選択肢は行ぜんぶが押せて高さ 48px 以上。
- **宛先で変えてよいのは 2 つだけ**: 宛名（`.to`）・会社の色 1 つ（`<body style="--brand:#rrggbb">`）。問いの文・見つけた事・AI の読みは、ページごとに相手の言葉で書く（§問いの形の「先方の言葉で書く」）。ほかの見た目と動きは型のまま（検査が `qa:css`・`qa:js`・`qa:foot` を型と突き合わせる）。**差出人・連絡先の欄は置かない**（ページは配る人が自分の送る文と一緒に渡す＝名乗りと問い合わせ先は送る文に書く・2026-11-14 オーナー決定。`.from`・`.contact` が残っていると検査が赤）。
- **未回答があると送れない**。全問に「分からない・確かめてから答える」を置き、どう答えても次へ進める。
- **何のための・どんな前提の問いかを、3 段で必ず見せる**（§前提の 3 段）。前提が書けない問いは出さない（検査が赤）。
- **答える人が、ほかの資料を開かずに「どの資料のどこを見て、AI が何をどう読み、何が決まらないから聞いているか」が分かる**ようにする（§根拠と読みと見込み）。AI の見込みに引っ張られず、事実で答えられるようにする＝選択肢に推奨の印を付けない。

宛先の印 `<body data-dest="…">` は 3 つ:

| 印 | いつ | 送った時 |
|---|---|---|
| `send`（送る） | 配る口のある会社がお客さんに聞く | 素のフォームの送信で配る口へ。受付の画面は配る口が出す |
| `copy`（写す） | オーナーが確認 HTML を頼んだ | 受付の画面に貼り戻しのテキストが出る＝チャットに貼る |
| `artifact`（確認のページ） | 確認を Artifact（claude.ai の非公開のページ）で渡す | 受付の画面を出し、`document` に `qa:submit` を投げる＝ページの仕組みが答えを持つ |

## 所属モード

トリガを受けたら**宣言も確認もなしで単一操作として実行**する（「作りますか？」「これでOK？」を出さない・途中確認をしない＝核 §4）。作った後は作り方 7 の渡し方で渡す。

## 前提の 3 段（どこに何を書くか）

説明を 1 か所に積まず、3 段に分ける。どの段に何を書くかが決まっていれば、前提が抜けず、長くもならない。

1. **ページ全体（はじめの画面）**: 何の仕事の確認か（件名・前書き）／**読んだ資料の一覧**（`.docs` の `<li data-doc="鍵" data-url="資料のリンク">`＝資料名・期間・受け取った日。li の中に同じ URL の `<a href>` を置き、型が新しいタブで開く。リンクが無い資料は `data-url=""` と `data-no-url="訳"`。「この中から聞いています」）／**答えるまでの扱い**（`.hold`・例「答えが届くまで、この点は確定せずにお待ちします。」）／期限。はじめの画面で見込みの数字を前提に見せない（「今の見込みで計算し」の類は検査が赤）。
2. **まとまり**: 見出し（`data-group`・`data-glabel`）＋ **1 行だけ**（`.glead`・各まとまりの最初の問いに 1 つ・例「規程に書いていない・法律と合わない所です」）。説明の画面は挟まない。
3. **1 問＝固定の 4 欄＋根拠と読み**（どの問いも同じ所に同じ事を書く）:

| 欄 | 書く所 | 中身 | 上限 |
|---|---|---|---|
| 何について | `.about` の `<span>`（人の名は `<span class="who">`） | 誰・いつ・何の札 | 3 つまで |
| 見つけた事 | `.known`（`data-docs="読んだ資料の鍵…"`） | 資料名・場所・値。食い違いは両方。書いてない時は**探した資料**と、どこにも書いていない事（見込みは書かない） | 2 行・1 行 60 字＋数字の表 5 行 |
| 　＋資料の切り抜き | `.clips` の `figure.clip`（`data-doc`・`data-shows`・`img` は data URI・`alt`・`figcaption`） | 該当の所に黄の印。押すと大きく。食い違いは 2 枚を横に並べる | 1 問 2 枚まで |
| なぜ聞くか | `.why`（`data-why`） | 決まった 5 文のどれか（下の表） | 1 行 |
| 　＋AI の読み | `.reading`（`.why` の下） | 「こう読んだ → ここが合わない／決まらない」 | 1〜3 行・1 行 80 字 |
| 根拠 | `.evidence` の `li[data-doc][data-where]`（原文の引用は中の `.quote`） | どの資料（一覧の鍵）のどこ（ページ・欄・行、シートならタブ名とセル範囲）。実物＝切り抜きか引用が 1 つ以上 | 3 つまで・場所 60 字・引用 80 字 |
| くわしく | `details.more`（資料の原文は中の `.orig`） | 決まり・計算の元・語の説明 | 3 行＋原文 |

なぜ聞くかの決まった 5 文（`check.mjs` の `RULES.why`・会社の表の `docs-kit.qa-html.why` で文だけ替えられる）:

| `data-why` | 文 | 見つけた事に書く物 | 選択肢の形 |
|---|---|---|---|
| `mismatch` | 資料どうしで食い違っています | 2 つの資料の名・場所・値（切り抜きを横並び）。`data-kind="mismatch"` はこれ | どちらか＋ほかの答え |
| `missing` | 資料に書いてありません | 探した資料の名と、どこにも書いていない事 | 候補 2 つ以上／資料を送る |
| `law` | 今の決まりが法律の決まりと合っていません | 今の決まりの抜粋と、法律の決まりの言い換え 1 行 | 直す時期の候補／今のまま |
| `once` | 今回だけの事を確かめます | 読んだ事と、無いと読んだ事の一覧 | このとおり／足りない・違う |
| `ambiguous` | 資料の書き方が 2 通りに読めます | その所の資料名・場所と原文（引用か切り抜き）。2 つの読み方は AI の読みに書く | 読み方ごとの候補＋別の決め方 |

- **切り抜きの守り**: 写すのは問いの人の行だけ。ほかの人の名前と額は塗りつぶしてから埋め込む。`data-shows` に切り抜きに写っている人の名を書く（問いの `span.who` の人だけ・誰も写らなければ `data-shows=""`・属性が無ければ赤）。4 欄の箱（`.about`・`.why`・`.known`・`.more`・`.clips`）は 1 問に 1 つずつ。人ごとの事実（`person`）の問いには `span.who` が要る。食い違い（`mismatch`）の切り抜きは 0 枚か 2 枚。`.glead` は問いの箱の中だけ。検査は、ほかの問いの人の名が `data-shows`・`alt`・`figcaption` に出たら赤にする。画像はページに埋め込む（外へ読みに行かない）。
- **選択肢ごとに「この答えで変わる事」**（`<small class="chg">`・誰の・何が・いくら・1 行）。画面には「変わる事: …」と出る。書かなくてよいのは逃げ道だけ（鍵と見出しの両方が `other`＝「ほかの答え」「別の決め方」・`none`＝「当てはまらない」の時と「分からない」・表は `RULES.free_options`）。
- **前置きで寄せない**: 前提の文はどちらにも寄せず事実だけ。選択肢に推奨の印を付けない（「おすすめ」「推奨」の字も・データの `recommended` も赤）。AI の見込みは §根拠と読みと見込み の別枠だけ。
- **「こう読みました」の一覧はこのページに載せない**（読んで決めた事は、結果を送る時の案内に添える）。
- **前提が書けない問いは出さない**: 何について・見つけた事（と読んだ資料の鍵）・なぜ聞くか・AI の読み・根拠（場所と実物）・くわしく・選択肢ごとの変わる事 のどれかが空なら検査が赤。書けないのは、こちらの読み不足か要らない問い。

## 根拠と読みと見込み

答える人は、AI がどの前提で・どこについて聞いているかを汲み取れない。だから 1 問ごとに、**見た所・読んだ事・決まらない所**をそのまま見せる。

- **根拠**（`.evidence`・1 つ以上）: `li[data-doc]` は一覧の資料の鍵、`data-where` はその資料の中の場所（例「2 ページ目・見本さんの欄・11/5 の行」、シートなら「10 月 タブ・B12:F12」）。li の字にも資料名と場所を書く。原文は `<span class="quote">` に引く（括弧は型が付ける）。
- **実物**: 切り抜き（`figure.clip`）か根拠の引用（`.quote`）のどちらかを 1 つ以上。会社の決まりの問いも、規程などの条文を引用で載せる。宛先がリンクを開けない時のため、実物が主でリンクは添え。
- **AI の読み**（`.reading`・`.why` の下）: 1〜3 行で「こう読んだ → ここが合わない／決まらない」。読みの中で答えを決めつけない。
- **AI の今の見込み**（任意・`<p class="estimate" data-basis="根拠 1 行">見込みの中身</p>`）: **根拠がある時だけ**、選択肢（`.opts`）の後に置く。型が灰色の別枠で「AI の今の見込み: 〇〇（根拠: …）。見込みに合わせず、事実で選んでください。」と出す。根拠が空なら赤・選択肢より前なら赤。「見込み」「予測」の字はこの枠の外に書かない（見つけた事・選択肢・はじめの画面にも書かない）。
- **1 画面 1 問＝ほかの問いに頼らない**: 「前の問いの答えで決まります」のように、ほかの問いを指さない（「前の問い」「前の質問」「上の問い」の類は赤）。要る事はその問いに書き、決まり方が答えで分かれるなら、それぞれの選択肢の変わる事に書く。

## 問いの形

聞く前に引き（作り方 0・細目 §4）、届いた物の全部を読み、こちらで計算・判断できる事は問いにしない。聞くのは次の形だけ（食い違い `mismatch` は (a) の仲間・下の箇条）:

| 形（`data-kind`） | いつ | 選択肢 |
|---|---|---|
| (a) `choose`「どちらが正しいですか」 | こちらで候補ごとに計算した結果が分かれる | 候補を並べ、それぞれの変わる事を 1 行（例「10 月の請求が合計 1,200 円」）＋「ほかの答え（ひとことに）」 |
| (b) `fact` 資料の外にしか無い事実 | 入社日・納品日など、資料の中に無い事 | 分かる範囲の候補＋「当てはまらない」 |
| (c) `judge` 読んでも決まりが分からない時の判断 | 決まりが資料に無い・読めない | 候補 2 つ以上（印を付けない）＋「別の決め方（ひとことに）」 |
| (d) `complete` 読んだ資料で全部か | 資料が欠けていると計算が変わる時 | 「これで全部」（変わる事つき）＋「ほかにもある」（足りない資料の名をひとことに・`data-supp="need"`＝無ければ赤）。「当てはまらない」は要らない |

どの形も、最後に「または」で区切って **「分からない・確かめてから答える」**（`value="__unknown__"`）を置く。選ぶと、ひとことの欄が「誰に聞けば分かりますか」に変わる。

- **ひとことに書かせる選択肢**（「ほかの答え」「別の決め方」や、見出し・添え書き・変わる事で「ひとことに」「補足に書く」と頼む物）は、その `input` に `data-supp="need"`（JSON は選択肢に `"supp": "need"`・値は `need` だけ）を付ける。選ぶと欄の名が「ひとこと（この答えでは書いてください）」に変わり、空のままでは次へ進めず送れない（「分からない」も選んでいる時は任意の欄のまま）。「ほかの答え」「別の決め方」と、字に「ひとこと」「補足に書く」「補足欄」「下の欄」がある選択肢で印が無い物は `check.mjs` が赤。

- **選択肢に A・B などの記号を付けない**。中身が分かる見出し（`<b>`）と、この答えで変わる事 1 行（`<small class="chg">`）で書く。問いや見つけた事でも「A なら」と記号で指さない。
- **「合っていますか」は資料どうしが食い違う時だけ**（`data-kind="mismatch"`＝(a) の仲間・食い違う 2 つを見つけた事に書き、候補に両方を置く）。
- **資料から計算できる数を書かせない**。数はこちらで計算して候補に出す。数字は見つけた事の小さな表（今の計算／直した場合／差）で比べられるようにする。**資料の外にしか無い数**（実際の残業時間など）だけは、資料の外の事実（`fact`）の問いで数を打つ欄（`type="number"`・JSON は `"input": "number"`）にして聞く。見つけた事に探した資料と、どこにも無い事を書き、選択肢は「当てはまらない」1 つでよい（ほかの形・欄で数を書かせる・選択肢 1 つにすると `check.mjs` が赤）。資料から計算できる数を資料の外の事実と偽る形は機械で見分けられない＝作り方 6 の別の目が見る。
- **1 問に 1 つ**。「〇〇と△△を教えてください」「、また」で 2 つ聞かない。
- **先方の言葉で書く**。専門の語は例え話に替えず、答えがその語に懸かる時は、この件で何を指すかを「くわしく」に具体で一言置く（核 §2・細目 §4 の問いの言葉）。こちらの作り方や内部の言葉を書かない。過去の問いを番号で指さない（資料のリンクは載せてよい・過去の問いの番号や ID で指すのは不可）。
- **問いの頭に番号を付けない**（進み具合「3 / 12 問」は型が出す）。

## 並べ方

問いは次の順に並べる（`data-group`）。同じ事が何人かに起きていれば 1 問にまとめて表で並べる。

1. `rule` 会社の決まり（全員に効く・判断が要る）
2. `person` 人ごとの事実（入社日・休んだ日など）
3. `once` 今回だけの事（その月だけの事など。見出しを替える時は `data-glabel="10 月だけの事"`）
4. `later` 先に決めておきたい事（まだ起きていない時の決め方。**いつも最後**・今回の計算と混ぜない）。見出しは「先に決めておきたい事」、まとまりの 1 行は決まった文「今月の計算には関係しません。起きた時の決め方を先に伺います。」（会社の表の `docs-kit.qa-html.later_lead` で文だけ替えられる）

## 長さの上限（会社の表の `limits` で変えられる）

| 所 | 上限 |
|---|---|
| 問い（legend） | 1 行・40 字 |
| まとまりの 1 行（`.glead`） | 1 行・40 字 |
| 何について（`.about`） | 札 3 つ |
| 見つけた事（`.known`） | 文 2 行・1 行 60 字＋数字の表 5 行（見出しを入れて）。残りは `details.more`（くわしく）へ |
| 切り抜き（`figure.clip`） | 1 問 2 枚 |
| 根拠（`.evidence` の li） | 1 問 3 つ・場所 60 字・引用 80 字 |
| AI の読み（`.reading`） | 1〜3 行・1 行 80 字 |
| AI の今の見込み（`.estimate`） | 中身 40 字・根拠 60 字 |
| くわしく（`details.more`） | 3 行（原文は `.orig` に別で） |
| 選択肢の見出し（`<b>`） | 30 字 |
| この答えで変わる事（`small.chg`） | 1 行・40 字 |
| 選択肢の添え書き（`<small>`・逃げ道の「下のひとことに…」など） | 1 行・40 字 |
| 1 枚の問いの数 | 12 問（目安 10 分・超えるなら 2 枚に分ける） |

## 悪い例とこう直す

| 悪い例 | こう直す |
|---|---|
| 選択肢が「A 承知のうえ今のまま」「B 1 分単位に直す」 | 「今のままにする／差額は毎月のお知らせに残す」「10 月分から直す／差額は次の支払いで払う」のように見出し＋結果 1 行 |
| 1 問に 3 つ詰めた | 1 問 1 つに分ける。分けて要らなくなった問いは消す |
| ある 1 日だけ聞いて、ほかの日を聞かなかった | 同じ事が起きている所を全部並べて 1 問にする |
| 長い文で計算の違いを説明した | 今の計算／直した場合／差 の小さな表にし、決まりの文は「くわしく」へ |
| 「確認したい事があります」とだけ書き、どの資料のどこを見て聞いているかが無い | 何について（誰・いつ・何）／見つけた事（資料名・場所・値＋切り抜き）／なぜ聞くか（決まった文）を埋める。埋まらないなら聞かない |
| 資料の写真に、ほかの人の名前と額が写っている | 問いの人の行だけを切り抜き、ほかの人は塗りつぶす。`data-shows` は問いの人だけ |
| 選択肢を選んで何が変わるのかが分からない | 選択肢ごとに「この答えで変わる事」（誰の・何が・いくら）を 1 行 |
| 選択肢が「決まったら連絡」1 つだけ | 候補を 2 つ以上と「分からない」。どう答えても次に進める形にする |
| 会社の決まりと人ごとの事実が混ざって並ぶ | 会社の決まり → 人ごとの事実 → 今回だけの事 → 先に決めておきたい事 の順に並べ替える |
| 選択肢の 1 つ目に「おすすめ」の印 | 印を外す。根拠があるなら選択肢の後の見込みの枠に「AI の今の見込み（根拠: …）」として置く |
| 「前の問いの答えで決まります」 | その問いに要る事を書き、答えで分かれる所は選択肢ごとの変わる事に書く |
| 資料の名だけで、どこを見たか・どう読んだかが無い | 根拠に資料の場所（ページ・欄・行・セル）と原文の引用か切り抜き、AI の読みに「こう読んだ → ここが決まらない」 |
| まだ起きていない場合の決め方を今回の問いに混ぜる | 先に決めておきたい事（`later`）のまとまりに分けて最後に置く |

## 作り方（skip 禁止）

0. **聞く前に引く**（細目 §4）: 問いの候補ごとに、各社の決定の記録と問いの表（前に聞いた問いと答えの表）を、問いと同じ言葉で引く。答え済みの問い・資料で決まる事（AI が決めて進める）・道具や仕組みの都合（値が足りず動かない等＝原因の台帳の行にする）は問いから外す。残す問いには**引いた結果**（照らした前の答えの ID か URL・無ければ引いた言葉）を、問いの元の表の列に持たせる（引いた結果はページに載せない＝過去の問いを番号で指さない）。値の表に `prior_check_cmd` がある repo は、ページを組んだ後に `node <この skill の dir>/check.mjs <file> --run-prior` で道具に引かせる（引いた結果はページの隣の `<名>.prior.json`＝git にも配る先にも出さない作業場の物。答え済みの問いが残っていれば赤＝外して版を上げ、引き直す）。**読んだ資料のリンク**（Drive などの URL）はページに載せる（はじめの画面の一覧の `data-url`）。
1. **`references/template.html` を丸ごと複製**する。`<body data-dest>` を `send`・`copy`・`artifact` のどれかにし、`{{…}}` と問いの箱だけ差し替える。`qa:css`・`qa:js` の間は**1 字も変えない**。`qa:foot` の間は `{{この後のこと}}` だけ差す（字と `<br>` だけ）。型の外に書けるのは `check.mjs` の許す物の表 `ALLOW` の要素と属性だけ（`style`・`script`・`iframe`・`on…` の属性・`javascript:` などは赤・リンクは https・mailto・tel・# だけ・写真は img の `data:image/` だけ・会社の色は body の `--brand` だけ）。
2. **header（前提の 1 段目）**: 宛名（`.to`）・件名（`h1`）・前書き 1 文・**読んだ資料の一覧**（`.docs` の `li[data-doc][data-url]`＋同じ URL の `<a href>`・リンクが無い資料は `data-no-url`）・**答えるまでの扱い**（`.hold`）・期限。差出人・連絡先の欄は書かない。全 N 問・目安の分は型が出す。

4. **問いの箱を組む**（1 問＝1 つの `fieldset.q`・前提の 2・3 段目）: `data-qkey`＝問いの鍵（半角英数字と `_`・答えの `name` と同じ・元の表の行の鍵と同じにする）／`data-qlabel`＝一言の見出し／`data-kind`＝上の形／`data-group`＝並べ方／まとまりの最初の問いだけ `.glead`＝まとまりの 1 行／`.about`＝何について／`legend`＝問い 1 行／`.why`＝なぜ聞くか／`.reading`＝AI の読み／`.known`＝見つけた事（`data-docs`・数字は `<table>`）／`.evidence`＝根拠（`li[data-doc][data-where]`・`.quote`）／`.clips`＝切り抜き／`details.more`＝くわしく／選択肢 `label.opt`（`value`＝選択肢の鍵・半角英数字と `_`・最初の 1 つに `required`・`small.chg`＝この答えで変わる事）／「または」と「分からない」／根拠がある時だけ `.estimate[data-basis]`＝AI の今の見込み／ひとこと `name="supp_鍵"`。前提は問いの元の表（対象・理由・資料・探した資料・選択肢ごとの変わる事）から写す＝ページの側で作文しない。最後に `name="__自由記入__"` の箱を 1 つ。選択肢は radio を使う（checkbox は required を付けられず、JS が切られた端末では答えずに送れる＝幾つも選ばせる時だけ）。
5. **検査**: `node <この skill の dir>/check.mjs <file.html>`（ページの隣の `<名>.prior.json` が在れば、前の答えも照らす。Artifact 型に問いをデータで渡す時は `<file.json>`。知らない印・同じ印の 2 度書きは exit 2 で止まる＝打ち間違えた印で頼んだ検査をせずに緑にしない。送る形は表の `customer.check_cmd`＝この検査を直に呼び、配る口の契約と画面の写真を足した物・検査を写して持たない）。**緑でなければ渡さない**。赤の行は 1 つずつ手で潰さず細目 §3「まず構造を疑う」で原因（問いの元の表・前提の写し方）から直す（Artifact の publish の前は guard の `qa_page` も同じ検査をかけて赤なら止める）。
6. **送る前の別の目**: 窓の中の助手（Agent ツール）に、作った文脈を渡さず **HTML と、問いごとの引いた結果（作り方 0）だけ**を渡し、答える人の立場で 1 問ずつ読ませる。見る点は 4 つ: ①**ほかの資料を開かずに、何を聞かれているか分かるか**（前提の 4 欄・根拠の場所と実物・AI の読みだけで足りるか・見込みに引っ張られないか） ②どう答えても聞き直さずに済むか ③選択肢とひとことで答えが 1 つに決まるか ④既に答えた事・資料で決まる事（資料から計算できる数を、資料の外の事実として書かせていないか）・道具の都合を聞いていないか（引いた結果に照らす。引いた結果の無い問いは差し戻す）。直したら 5 からやり直す。
7. **保存と渡し方**: 置き場は表の `save_dir`（無ければ窓の scratchpad・`common.save_dir_avoid` には置かない）、名前は `確認_<件名>_<YYYYMMDD>.html`。写す形は表の `delivery` で 1 行＋「特に判断が要る点」を数行（HTML の中身をチャットに再展開しない）。送る形は表の `customer.publish_cmd` で配る URL を作り、お客さんにその URL だけを渡す。

### 答えの形（qa-html/2・機械で戻す JSON）

型の JS が作る形。正本は `check.mjs` の `ANSWER_FORM`・`ANSWER_KEYS`・`checkAnswer` の 1 か所（型の JS とこの例が合わなければ土台の試験が赤）。配る口・貼り戻しの道具は形を写して合わせず、自分が作る・受ける答えを `node check.mjs --answer <file|->`（配る口が足す自分の印の鍵は `--extra 鍵,鍵` で名指し）で照らす試験を持つ（知らない形・知らない鍵・欠けた鍵・形の違う値は赤＝写した古い形のままなら止まる）。写す形では貼り戻しの最後の行 `qa-json: {…}` に、確認のページでは `qa:submit` の `detail` に入る。配る口が JSON で受ける時もこの形にそろえる。

```json
{
  "form": "qa-html/2",
  "title": "件名",
  "version": "2026-11-13.1",
  "receipt": "R261113-7KQ4",
  "answered_at": "2026-11-13T22:41:00+09:00",
  "answers": { "q1": ["down"], "q2": ["__unknown__"] },
  "labels":  { "q1": ["切り捨てる"], "q2": ["分からない・確かめてから答える"] },
  "supp":    { "q2": "店長に聞けば分かります" },
  "free": ""
}
```

- 1 送信＝1 行。**送り直しは新しい受付番号の新しい行**として足し、前の行は消さない。表へ戻す時は、問いの鍵ごとに一番新しい送信を正とし、版が今の版と違う答えには「古い版」の印を付ける。
- 受付番号は `R<YYMMDD>-<英数 4 字>`。型の JS が送る時に作る（JS が切られて空なら受ける側が同じ形で出す）。

### 貼り戻しのテキスト（写す形）

1 行目 `# <title> — 回答`、2 行目 `版: … ／ 受付番号: …`、問いごとに `■ 問N [鍵]: <data-qlabel>` と `   → 回答: …`（ひとことがあれば `   → 補足: …`）、`■ その他・全体の意向:`、最後に `qa-json: {…}`。貼り戻しを拾う仕組みがこの形を読む＝変えない。

## 前の答えを照らす口（値の表の `prior_check_cmd`）

作り方 0 を repo の道具で機械にする口。どの repo も同じ口で使い、道具の中身（どの記録をどう引くか）は repo の側が持つ。

- **命令の約束**: 値の表の `docs-kit.qa-html.prior_check_cmd`（shell の 1 行・repo の根で走る）は、標準入力に問いの JSON を受け、標準出力に引いた結果の JSON を返し、0 で終わる。
  - 受ける物（`check.mjs <file> --prior-input` で同じ物が見られる）: `{"format": "qa-prior/1", "questions": [{"key", "label", "question", "about": [...], "known": [...], "group", "kind"}]}`
  - 返す物: `{"answered": {"問いの鍵": "前の答えの ID か URL"}, "checked": {"問いの鍵": "引いた結果（照らした前の答えの ID・URL・無ければ引いた言葉）"}}`。答え済みの問いは `answered`、引いて答えが無かった問いは `checked` に入れる。
- **走らせ方**: `node check.mjs <file> --run-prior` が命令を走らせ、返した物にページの版（`page_version`）を添えてページの隣の `<名>.prior.json`（`--prior <file>` で替える）に書いてから検査する。命令が落ちた・JSON を返さない時も `{"error": …}` で書き換える（前の回の結果を残さない）。手で引いた結果を同じ形で書いて `--prior <file>` で渡してもよい。
- **赤にする物**: 引いた結果の `answered` に在る鍵が問いに残っている・引いた結果が読めない・形が違う・命令が落ちた回の結果・別の版のページで引いた結果（問いを直して版を上げたら引き直す）・`--prior` に渡した file が無い。値の表に命令が在る時だけ、引いた結果が無い・引いた結果（`answered` か `checked`）の無い問いがある。
- **値の表に命令が無い時**: 引いた結果のファイルも無ければ前の答えは見ない＝今までどおり（作り方 0 は手で引く）。
- guard の `qa_page` はページの path だけで検査を呼ぶ＝隣の `<名>.prior.json` を同じく読む。値の表はページの dir・今の dir・窓の repo（`CLAUDE_PROJECT_DIR`）から上へ探す＝ページが窓の scratchpad に在っても見つかる。命令が在る repo は、publish の前に `--run-prior` を済ませておく。

## 自己完結の鉄則

- **外部リソース禁止**（CDN・外部フォント・画像 URL・fetch）。CSS/JS は型の中の 1 つずつだけ。`file://` で開いてオフラインで完動すること。画像が要る時は data URI。
- 途中の保存はその端末のブラウザにだけ残す（保存が使えない端末でも答えて送れる）。

## 配り方（単一ソース）

- **正本** = この skill の dir（plugin の中）。直す時はここだけ直す。SKILL.md・`references/template.html`・`check.mjs` は常に 1 組で運ぶ。
- **使う側（別の repo の作る道具・配る口・その検査）は型・検査・答えの形を写して持たない**。毎回この dir の物を直に読む:
  - 型 … `node <この dir>/check.mjs --template`（標準出力に型そのもの）。repo に雛形の写しを置かない
  - 検査 … `node <この dir>/check.mjs <file>`（`customer.check_cmd` もこれを呼んで足す・import してもよい）。repo に `check.mjs` の写しを置かない
  - 答えの形 … `node <この dir>/check.mjs --answer <file|->`
- **この dir の見つけ方**（別の版の dir を拾わない＝型と検査の版を食い違わせない）:
  - 窓の中: Claude Code の台帳 `~/.claude/plugins/installed_plugins.json` の `docs-kit@<市場>` の `installPath`（今入っている 1 つ）。plugin の cache の中の「新しい物」を探して拾わない。見つからなければ止まって、docs-kit を入れるよう名指しする
  - 同じ土台の plugin の中（guard の `qa_page`）: guard と同じ commit の docs-kit だけ（repo の形なら隣、入れた形なら同じ版の dir）
  - CI: 土台の公開の repo の main の先端を取り（`git clone --depth 1 https://github.com/ynishikawa-coder/agent-foundation-public`）、その `plugins/docs-kit/skills/qa-html`。版の印で止めない
- 写しを消せない所（業務の都合で置いた物）は、その repo の試験がこの dir の物と突き合わせ、食い違えば赤にする。
- repo の中での配り方は表の `docs-kit.qa-html.distribution`。repo ごとの値はこの dir に書かない。
