# /compose-message — 送る文面づくり

オーナーが「○○さんに△△の件で連絡したい」と言った時、コピペでそのまま送れる連絡文面を作って返す。媒体（LINE / メール / Chatwork / Slack 等）の決まりと、相手ごとの決まりを当て、毎回の品質の差と固有名の漏れを防ぐ。

## 起動の目安（文脈で判断する）

| 自然文の形 | 動作 |
|---|---|
| 「○○さんに△△の件で連絡」「○○へメッセージ」 | 新しい文面を作る |
| 「文面作って」「文案ちょうだい」「送る文章」 | 新しい文面を作る（相手・用件が文脈に無ければ聞く） |
| 「これに返信して」「返事の文案」（直前に相手の文がある） | 返信の文面を作る |
| 「もっと丁寧に / 砕けて / 短く」（直前に出した文面がある） | 調子を変えて作り直す |

明示の `/compose-message <相手> <用件>` でもよい。

## repo ごとの値（config/skill-values.json）

repo の根（`git rev-parse --show-toplevel`）の `config/skill-values.json` の `docs-kit.compose-message.<鍵>` と `common.<鍵>` から読む。**鍵が無い・値が空なら右の既定で動く**。

| 鍵 | 使う所 | 無い時の既定 |
|---|---|---|
| `docs-kit.compose-message.recipient_rules` | 相手ごとの決まり（配列: `{相手, 決まり, 伏せる語?}`） | 下の §相手ごとの決まり の一般の決まりだけ |
| `docs-kit.compose-message.send` | 送る口（`media`＝媒体の名・`send_cmd`＝送る命令・`credentials`＝鍵の置き場の説明・`consult_heading`＝相談の見出し） | 送らない（コピペの形で返す） |
| `docs-kit.compose-message.sources` | 外へ出す文面の前に読む、案件の最新の記録の置き場 | 会話と手元のファイルだけで書く |
| `common.rules` / `common.glossary` | 確認装置禁止・喋り方の正本／本文の語の意味 | この本文の規則だけ・語の一般の意味 |

## 入力に要る 3 つ

1. **相手** — 誰に送るか（名前 / 役割）。相手ごとの決まりの判定に使う
2. **用件** — 何を伝えるか（会話の文脈から取れることが多い）
3. **媒体** — LINE / メール / Chatwork / Slack、または表の `send.media`（送る口）

相手と用件は会話の文脈から取れれば聞かない。**取れない物だけを聞く**（聞き方は核 §4）。媒体が分からなければ、相手が外の人ならメール、内の人・普段やり取りする相手なら LINE/Chatwork を既定に置いて作り、冒頭 1 行で「LINE 想定で書きました、メールなら言ってください」と添える。

## 相手ごとの決まり

文面を作る前に、相手が表の `recipient_rules` のどれかに当たるかを見てから書く。表が無い時も、次の一般の決まりは必ず当てる:

| 相手 | 決まり |
|---|---|
| 外の人（取引先・お客さん・外注先） | 内部の呼び名・内部の固有名・内部の原価や取り分を書かない。見積りは「概算（確定の前に変わりうる）」と明記 |
| 上流の取引先の名を伏せたい相手 | 上流の名を名指しせず、役割の言葉（例「メーカー側」）にそろえる |

新しい「この相手にはこう書く」が出たら、使う repo の表の `recipient_rules` に 1 行足す（この skill の本文には足さない＝土台は相手の実名を持たない）。

## 共通の決まり（全文面に当てる）

1. **出力はコードブロック**（```）で囲む。blockquote（>）は縦棒が混ざるので使わない
2. **メールの時は件名も出す**（コードブロックの 1 行目に `件名: …`）。LINE / Chatwork / Slack は件名なし
3. **媒体に合わせた形** — メールは宛名 + 挨拶 + 本文 + 署名の余地、LINE/Chatwork は挨拶を軽く・改行を短め、Slack は宛名なしで用件を先に
4. **差出人の一人称・社名を勝手に決めない** — 署名や差出人が要る時は「（差出人ここ）」と空けるか、過去の文面が分かれば合わせる
5. **伏せる語の見直し** — 相手ごとの決まりに当たる時は、書き終えてから「伏せる語が本文に残っていないか」を 1 度見直してから出す
6. **二択や確認装置を末尾に付けない** — 文面を出したら「直したい所あれば言ってください」の 1 行で締める
7. **外へ出す文面は最新の記録と突き合わせる** — 依頼・報告・提案の文面は、表の `sources` にある案件の最新の記録を 1 度見て、前提が新しい決定で上書きされていないかを確かめてから書く（1 つの元だけで早合点しない）
8. **名乗り・固有名は実在を確かめる** — 差出人の名乗り・人名・社名・宛先は、案件のファイル・過去の文面で実在を確かめてから書く（書き起こしの誤記を広げない・名乗りを作らない）

## 出力の形

```
（媒体）<LINE / メール / Chatwork / Slack>・想定の相手: <相手>

———（ここからコピペ）———
（コードブロックで文面の本体。メールは件名の行から）
———（ここまで）———
```

文面のあと、相手ごとの決まりを当てた時だけ「※ メーカー側の表記に置き換えました」のように 1 行で何を伏せたかを添える（意図と違えば戻せるように）。それ以外は文面 + 「直したい所あれば言ってください」だけ。

## 送る口で送る（表の `send` がある時だけ）

表に `send` がある時、相手がその口の宛先（例: オーナーとの連絡のグループ）なら、出口が「コピペ」から **bot がその口へ投稿する** に変わる。文面づくり自体は上と同じ。**表に `send` が無い・空なら送らず、上の出力の形のコピペで返す**。

相談を送る時の形（タスクは立てない。関係する記録があれば URL を貼ってよい・読むだけ）:

```
オーナー 相談です

# <見出し（表の send.consult_heading・無ければ「相談」）> ／ <案件名>
（関係する記録があれば）<その URL>

<相談したいこと>
```

1. 通常どおり文面を出す（1 行目は `（媒体）<send.media>・想定の相手: <相手>（bot 投稿）`）
2. **送る前に go を取る**（「確認してから送る」＝ここだけは確認装置禁止の例外。go 無しで投稿しない）
3. go が出たら本文を一時ファイルへ書いてから送る（改行が多い文面は引数の直渡しで崩れやすい）:
   ```bash
   <send.send_cmd> --text-file <path>
   ```
4. 送る命令の出力で成功（送れた件数・送った物の id）を見てから「送りました」と言う（送ったつもりで届いていない、を潰す）

- 鍵（token など）は表の `send.credentials` の置き場（git の外）から送る命令が読む。**チャットに出さない・命令の引数で渡さない**
- **受け取る側は無い**＝返事は会話で拾う
- 送る前に文面だけ見たい時は、送る命令に試しの形（例 `--dry-run`）があればそれを使う

## 困った時

| 状況 | 対応 |
|---|---|
| 相手が分からない | 誰宛てかを聞く（用件は文脈から推して書いてよい） |
| 用件が薄くて書けない | 文脈から推した文面を出し「ここを埋めてください」と空欄を残す（白紙で止めない） |
| 相手ごとの決まりに当たるか曖昧 | 安全側に倒して固有名を伏せて書き、「伏せてあります、内向けなら戻します」と添える |
