# /design-mode — 作る前の相談

## 入る

オーナーが「設計モードで」「まだ実装しないで」「提案・調査・整理して」「相談」と言った時。

## 中でする事

- 調べる・読む・整理する・案を出す・問う。読むだけの調べは窓の中の助手（Agent）に並べて投げる。
- **論点の表** を持ち、返事のたびに直す:

  | 論点 | 意図（何のために決めるか） | 状態（決まった／未決／前提待ち） | 決まった中身・待っている前提 | 持つ窓 |
  |---|---|---|---|---|

- 未決の論点を 1 本の列にしない。互いに頼らない未決は論点ごとに窓を並べて同時に進める（各窓は自分の論点だけを調べ、問いは題に ❓ を付けて直に出す・同じ問いを 2 つの窓で出さない）。前提待ちの論点は、前提が決まった時にすぐ窓を立てる。この窓は表を持ち、各窓の返しで表を直す。
- オーナーに「どの論点から進めますか」と選ばせない（核 §4）。問いの形は核 §4・細目 §4。

## 中でしない事

- repo を直す・commit・PR・窓を立てて作らせる（論点を調べ・問う窓を並べるのはよい）。
- 作る段取り・試しの段取りを出す。「どうやりますか」「どこから作りますか」を聞く。

## 出る

次のどちらか。

1. **ほんまにできる表** が全部埋まったら、AI が「実装に移れます」と 1 回だけ聞く（選択肢の画面）。

   | 項目 | 中身 |
   |---|---|
   | 要件 | 何ができれば良いか |
   | 合否の物差し | 何を見れば出来たと言えるか |
   | 誰が作るか | どの窓・どの道具・人の手が要るか |
   | 触って確かめた | 使う道具・接続に、この窓から実際に触れて動いたか |
   | 費用 | お金・時間・オーナーの手 |
   | 届く先 | この変更が誰に・どの窓に・いつから効くか（土台なら Javis と UTC エージェントの両方に、合流の後に開く窓から） |
   | 写しの残り | 同じ決まりの写し・古い形を指す文がどこに残るか（土台の中と使う側の repo の両方を必ず洗い出す）。直すのは同じ仕事の中（細目 §7「土台の直しの終わり」） |

   届く先と写しの残りの洗い出しは、読むだけの助手（Agent）に任せてよい。

2. オーナーが「実装進めて」と言った時。

どちらで出る時も、論点の表に残った未決・前提待ちと、持つ窓の空いた論点は、全部原因の台帳の行にしてから出る（細目 §3。行き先は持つ窓の URL・前提が決まった時に立てる窓）。表はこの窓と一緒に消えるので、台帳に無い論点は残らない。

出た後（実装の段）は、核 §4 のとおり止まらず一気に進める。
