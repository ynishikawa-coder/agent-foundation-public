# /design-mode — 作る前の相談

## 入る

オーナーが「設計モードで」「まだ実装しないで」「提案・調査・整理して」「相談」と言った時。「やり始める前に先に教えて」等で着手を留保された時は、答えに必要な読み取りまで行い、答えを返してそのターンを終える。報告後そのまま進める指示が明示されていれば、許された範囲を再承認させない。

## 中でする事

- 調べる・読む・整理する・案を出す・問う・作る段取り（分け方と終わる時刻）を組む。共有の資料は一度調べ、別の目や分担が必要な時だけ、振る舞いの既定「並走」に従って範囲を分ける。
- **論点の表** を持ち、返事のたびに直す:

  | 論点 | 意図（何のために決めるか） | 状態（決まった／未決／前提待ち） | 決まった中身・待っている前提 | 持つ窓 |
  |---|---|---|---|---|

- 未決の論点を 1 本の列にしない。互いに頼らない未決で、立ち上げと取りまとめ込みで早くなるものは、論点ごとに窓を分けて進める（各窓は自分の論点だけを調べ、問いは題に ❓ を付けて直に出す・同じ問いを 2 つの窓で出さない）。前提待ちの論点は、決まり次第進める。窓を分けるかは同じ「並走」の条件で決める。この窓は表を持ち、各窓の返しで表を直す。
- 段取りは AI が組む。オーナーへの返しは現状と変わる結果を先に示し、同じ前提なら聞き直さない（核 §4・細目 §4「見せてから聞く」）。

## 中でしない事

- repo を直す・commit・PR・窓を立てて作らせる（論点を調べ・問う窓を並べるのはよい）。
- 「どうやりますか」「どこから作りますか」を聞く（段取りは AI が組んで出口の表に書く）。

## 出る

次のどちらか。

1. **ほんまにできる表** が全部埋まったら、何をどう使えるようにするか・今回触らない所を伝え、実装の許可が未確認なら 1 回だけ聞く（選択肢の画面）。意図が合っただけでは着手しない。

   | 項目 | 中身 |
   |---|---|
   | 要件 | 何ができれば良いか |
   | 合否の物差し | 何を見れば出来たと言えるか |
   | 誰が作るか | どの窓・どの道具・人の手が要るか |
   | 触って確かめた | 使う道具・接続に、この窓から実際に触れて動いたか |
   | 費用 | お金・時間・オーナーの手 |
   | 分け方と終わる時刻 | 分けるなら、独立して終えられる範囲・持つ file・PR・終わる時刻。分けないなら親だけ（振る舞いの既定「並走」・日本時間） |
   | 届く先 | この変更が誰に・どの窓に・いつから効くか（土台なら Javis と UTC エージェントの両方に、合流の後に開く窓から） |
   | 写しの残り | 同じ決まりの写し・古い形を指す文がどこに残るか（土台の中と使う側の repo の両方を必ず洗い出す）。直すのは同じ仕事の中（細目 §7「土台の直しの終わり」） |

   届く先と写しの残りの洗い出しは、読むだけの助手（Agent）に任せてよい。

2. オーナーが「実装進めて」と言った時。

どちらで出る時も、決定に頼る確定は正本が確かめられるまで保留。独立の仕事は続ける。残る論点は既存 Job か原因の台帳の担当へ渡す（細目 §3・§8）。台帳の書き込み待ちだけで無関係な成果を保留しない。

出た後（実装の段）は、核 §4 のとおり止まらず一気に進める。長い相談を経て実装に移る時は、相談窓とは別の実装窓に進行を渡す。その仕事の実装窓があれば使い、取りまとめが要る時は実装側の担当窓が持つ。渡すのは合意した目的・対象・いま許された段階・変えない条件・確認方法と出所を含む既存の確定文。会話全文や自動要約で代えず、追加の承認や中継の窓は作らない。短い相談は既存の進め方を変えない。
