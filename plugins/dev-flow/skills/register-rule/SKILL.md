# /register-rule — 規律を足す・直す前の関所

規律・skill・hook を書く前に通す（書いた後の点検ではない）。

## repo ごとの値（config/skill-values.json）

repo の根の `config/skill-values.json` の `dev-flow.register-rule.<鍵>` から読む。**鍵が無い・値が空なら右の既定で動く**。

| 鍵 | 使う所 | 無い時の既定 |
|---|---|---|
| `dup_check_cmd` | Step 2 の機械の重複検査の命令 | grep だけ |
| `desc_budget_bytes` | skill の description の合計の予算（Step 4） | 測って PR 本文に書くだけ |
| `decision_record` | 原文・経緯を書く決定の記録の口 | PR 本文に原文と経緯を書く |
| `learning_record` | 失敗・学びの書き先 | PR 本文の「学び:」の 1 行 |

## Step 1: これは止める物か（最初に問う）

| 足す物 | 誰が決める |
|---|---|
| 畳む・直す（死んだ参照・食い違い）・言い換え・止めずに知らせるだけの物 | AI が自分の判断で入れてよい |
| 新しく「止める」物（返事や道具を止める hook・必須の検査・確認の段・人の手が要る段）・核の原則の変更 | オーナーの同意を取る（選択肢の画面で聞く） |

- 安全の常設の守り（戻せない操作・秘密・deny）は畳まない。
- 守らせたい事は、止める前に「知らせるだけ」で足りないかを先に考える。

## Step 2: 重複

`dup_check_cmd` が在れば先に打つ。無ければ grep で見る:

```bash
grep -rn "<語 1>\|<語 2>" CLAUDE.md .claude/ plugins/ 2>/dev/null
```

0 件＝新規／1〜2 件＝既存の改訂として扱う（新しく足さない）／3 件以上＝散っている＝1 か所に寄せる。関連 skill と食い違えば skill 側も同じ PR で直す。

## Step 3: 置き場

| 効く先 | 置き場 |
|---|---|
| 土台（両方の AI） | 常時要る原則は `plugins/core/核.md`、形・例は `細目.md`、作業の手順は土台の skill |
| 各 repo の固有 | その repo の `CLAUDE.md`（常時）か、その repo の skill・文書（要る時） |

- 迷ったら skill に書く。正本は 1 か所、他は指すだけ（言い換えの写しも置かない）。
- 新しいファイル・skill は、既存の物の末尾に足すと座りが悪い時だけ。近い skill が在れば統合を先に考える。

## Step 4: 量と 1 入 1 出

- **1 つ足したら 1 つ以上畳む**（同じ PR で）。畳んだ物を PR 本文に書く。
- 核と各 repo の `CLAUDE.md` は `python3 plugins/core/scripts/kaku.py check [--claude <path>]` で照らす。越えるなら常時へ足さず、細目・skill へ移して常時からは指す 1 行にする。
- skill の description は「何を・いつ使うか」の 1〜2 行。合計は `desc_budget_bytes` で測る。

## Step 5: 規律の形

1. 中身は根治の 3 つの問い（核 §3）で決める。文を 1 本足すことを直しの中心にしない。今の前提に書き換え、古い文を残して例外や切り替えの文を足さない。
2. 規律の文は今の結論（振る舞い）だけ。オーナーの原文・日付・出所・経緯・覆された旧い形（墓標）・「何がどこに在る」の事実は書かない。原文と経緯は `decision_record`（無ければ PR 本文）へ。
3. 見張り（歯）を足す時は、窓の作業場で変異体を作って確かめる: 守る物を壊すと赤になるか（ならないなら空の歯）／外すと声が消えるか（消えないなら既に別の歯が守っている＝統合）。結果は PR 本文に 1 行。
4. 仕組みを消す時は、その試験と、消した物を指す文も同じ PR で消す。

## Step 6: 易化と書いた後の掃除

- 読み返して直す: 言い換えの無い専門用語・説明の無い ID・5 段以上の手順・80 字以上の文の連続。
- 書いた後、常時読む物（核・細目・`CLAUDE.md`・skill の description）を見て、重複は 1 か所に寄せ、死んだ参照は消す。食い違いで意味が変わる物はオーナーに聞く。
- 失敗・学びは `learning_record` へ（repo の md に積まない）。同じ種類の失敗が 2 度なら、文を足す前に構造を疑う。

## 出力の形

```
🔍 /register-rule
Step 1 止める物か: no（AI で入れる） / yes（オーナーの同意: <問いの窓>）
Step 2 重複: N 件（<path:line>）→ 新規 / 改訂 / 集約
Step 3 置き場: 土台 / 各 repo の固有 → <path>
Step 4 量: 核 <B>・CLAUDE.md <B> → 収まる／足した <物> ・畳んだ <物>
Step 5 形: 今の結論だけ／原文と経緯: <在処>
→ 書いてよい: yes / no
```
