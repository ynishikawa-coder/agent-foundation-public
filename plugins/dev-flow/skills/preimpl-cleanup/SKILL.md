# /preimpl-cleanup — 整地（書く側へ投げる前の棚卸し）

## 大原則（なぜ要るか）

目的は 1 つ: **改修で古くなる物を、本丸の作業を止めずに、片付け切る。** 書類を書くことは目的ではない。
**整地は、全部を分かっている頭（計画を出す側）が、直しを根治の段で見つめ直して計画を出す段。道具で書かせない＝頭が書く。**
欄は根治の段そのもの（下の「欄の中身」）。「畳む物」の行（`[同梱]`／`[後片付け]`）は、構造を変えたことで要らなくなる物（レビューする側が先端に残っていないかを見る）。
記録の置き場は PR 本文の欄（repo の決まりがあれば表の `dev-flow.preimpl-cleanup.record`）。

## repo ごとの値（config/skill-values.json）

`config/skill-values.json` の `dev-flow.preimpl-cleanup.<鍵>` と `common.<鍵>` から読む。**鍵が無い・値が空なら右の既定で動く**。表の探し方・既定・知らない鍵の扱いの正本は土台の `skill-values/skill_values.py` の冒頭（「探し方」「照らし」）。

| 鍵 | 使う所 | 無い時の既定 |
|---|---|---|
| `record` | 欄を置く所・照らす者 | PR 本文の欄・レビューする側が読む |
| `past_sources` | 手順 2 の出典 | 過去の PR の整地の欄・`git log --grep` |
| `request_template` | 手順 5 の依頼文の雛形 | 依頼文に欄をそのまま貼る |
| `ledger` | 見張り（試験・検査）を足す・畳む時の台帳の書き方 | 足す物と畳む物を PR 本文に 1 行ずつ |
| `local_steps` | repo だけの段（受領証の箱・段の刻み方など） | 無し（読まない） |
| `common.glossary` | 本文の語（頭・窓・job）の意味 | 語の一般の意味 |

## 欄の中身

根治の段（核 §3・細目 §3）: ①意図（その仕組み・作業が本来何のために在るか。意図そのものの誤りも疑う）②課題（意図と起きた事実のずれ。「なぜ」は書かない）③原因（仕組みや設計が悪い前提で、決まりの無理・無駄・重複／聞かせ方／仕組み／混じった文脈から探す。同じ原因の他の問題は別の目の助手が探した一覧を載せる）④解決（足す物＝誤りが入れない形・畳む物・注入の試験と残る穴＝手で写す所・選べる値の外が入る所・知らない値や欠けた材料で黙って進む所・正しい道を通らずに出る所・申告で済む確かめは残るか）⑤未来（直した後、意図が果たされ、同じ課題と同じ原因の他の問題が起きない姿＝何が無くなり何が変わるか。試験を足す段ではない）。根治の定義の正本は土台の核 §3・細目 §3 だけ（値の表に写さない・repo ごとに変えない）。

## 入力（走らせる前に握る）

| 入力 | 何を渡すか |
|---|---|
| `job_id` | この改修の仕事の名（PR 本文・枝の名と同じ字） |
| `change_kind` | `改修`（既存を直す）or `新規`（新しく作る） |
| この穴 | 何のための物で何が起きたか（段 ①意図・②課題で答える） |

## 手順

1. **意図を書く**（1 欄）: 段 ①。その仕組み・作業が本来何のために在るか（誰の・何を・どうしたいか）。意図そのものの誤りも疑う。
2. **課題を書く**（2 欄）: 段 ②。意図と起きた事実（何が・どこで・誰が何に困ったか）のずれ。「なぜ」は書かず 3 欄へ送る。渡された 1 件の症状を課題の幅にしない。
3. **原因を書き、同じ原因の他の問題を別の目に探させる**（3 欄）: 段 ③。原因を 1 文に書いたら、その 1 文だけを読むだけの助手（Agent・`subagent_type: Explore`。自分の読みや直し方は渡さない）に渡し、repo 全体と関わる repo から同じ原因で起きている・起きうる所を場所つきの一覧で返させる。出典は表の `past_sources` も足す（無ければ過去の PR の整地の欄の検索＝前に `[後片付け]` に回した行もここで拾う・`git log --grep`）。返った一覧はそのまま 3 欄に載せ、原因と合わせて 1 つ 1 行で原因の台帳に入れる（書いた窓が削らない）。
4. **解決を書く**（4 欄）: 段 ④＝「足す物」「畳む物」「注入の試験と残る穴」。足す物は誤りが入れない形（細目 §3: 写す工程を無くす／誤った物が入れない・既定で止まる／正しい道だけが証明付きで出す／防げない物は名指しで人の関所へ）のどれかで書き、3 欄の原因と一覧の全部に行き先（直す窓／直した／直さない＝オーナーが決めた理由つき）を付けて、各社の原因の台帳（細目 §3）の行と合わせる（直す物を選ばない）。畳む物は行頭 `[同梱]`（この PR で畳む）か `[後片付け]`（原因の台帳の行にする）で 1 行ずつ（path・名前は `` `…` `` で囲む）。既定は `[同梱]`＝新しい物を足して古い物を残す形にしない（核 §3）。`[後片付け]` にしてよいのは、畳む物がこの PR の触ってよい path の外にある時だけ（原因の台帳の行にし、行に直す窓を書く）。「念のため残す」「後で消す」は理由にならない。注入の試験は、直す誤りの類を作り物でわざと入れて仕組みが拒む試験の名と回す口（書けない直しは根治と書かず、細目 §3 の一時しのぎの 3 つを書く）。5 つの穴（手で写す所／選べる値の外が入る所／知らない値・欠けた材料・表せない決まりで黙って進む所／正しい道を通らずに出る所／申告で済む確かめ）を 1 行ずつ 無し／塞いだ（どこで）／残る（理由。原因の台帳の行にする）で書く。
   - 足す物の形の例（作り物）: 写す工程を無くす＝文で溜まった答えを設定の欄へ手で打ち直す代わりに、答えを例つきの表で受け、設定はその表を読む／誤った物が入れない＝区分の欄に一覧に無い字が来たら、空の扱いで数えずに止めて名指しする／正しい道だけが外へ出す＝計算の外で値を差し替えた物は証明が合わず出ない（直しも同じ道を通して作り直す）／防げない物は人の関所へ＝決まりの読み違いは決まりから作った例を相手が承認し、読めない原本は 2 つの読みを突き合わせて合わない所だけ人が見る。
5. **未来を書く**（5 欄）: 段 ⑤。直した後、1 欄の意図が果たされ、同じ課題と 3 欄の他の問題が起きない姿を、何が無くなり何が変わるか（作業する者の手順・オーナーの手・決まりの量）で書く。試験の名を並べる欄ではない。書けない時は 4 欄が足りていない。
6. **PR 本文に貼る**: 同じ dir の `整地受領証.template.md` の欄（frontmatter と注記を除いた `## 1.` から最後の番号の見出しまで）を `## 整地（根治の段）` の下に書く。書く側へ頼む時は依頼文（表の `request_template`）に貼り、書く側は PR 本文の「何をどう変えたか」の後にそのまま載せる（書く側が自分で書いてもよい）。振る舞いを変えない PR（誤字・記録だけ・版だけ等）は欄の代わりに本文へ `整地: 不要（<なぜ要らないか>）` の 1 行を書く（訳はレビューする側が照らす）。雛形の見出しが全部在るか・雛形の `〔…〕` が残っていないかは、PR を出す前に守りの hook（guard の `pr_text`）がこの雛形を直に読んで照らし、欠ければ止める。レビューする側が照らす（欄が全部在るか・雛形の `〔…〕` のままでないか・`[同梱]` 行の path が先端に残っていないか・4 欄の注入の試験が先端に在り通るか）。
7. **同梱の片付けの返し**: 書く側は PR 本文の 4 欄目の `[同梱]` 行ごとに 済／未（理由）を書く。「未」の行は `[後片付け]` に書き換え、原因の台帳の行にする（細目 §3）。

## 欄の掟（照らすのはここだけ）

- 雛形の見出し（意図／課題／原因と同じ原因の他の問題／解決／未来）が全部在り、雛形の `〔…〕` のままでない事。書式・鮮度は見ない（頭が自分の理解で書く）。
- 見張り（試験・検査）を足す・畳むなら、表の `ledger` の書き方で同じ PR に入れる（無ければ足す物と代わりに畳む物を PR 本文に 1 行ずつ＝1 入 1 出）。

## 受領証テンプレ

正本は同じ skill dir の `整地受領証.template.md` の 1 枚（欄を PR 本文へ写す）。ここに写しを置かない。

## repo だけの段

表の `dev-flow.preimpl-cleanup.local_steps` が在る時だけ、その行を上から読んで従う（受領証を仕事の箱に作る・段を刻む等）。無い repo では読まない＝上の手順 1〜7 だけで整地は終わる。
