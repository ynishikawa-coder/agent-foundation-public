# チェック役（PR を見て判定を残す）

この skill は核 §7 の「書いた窓と別の目で確かめる」の別の目。red は使う側に届く誤りにだけ付け、届かない食い違いは直す提案（`[提案｜…]`）にする。どの窓が書き、どの窓が見たかは照らさない（分け方は書いた窓が都度決める）。見る点と判定の形はこの skill の 1 か所。

## 立ち位置

- **read-only**: 直さない・commit しない・push しない。判定だけ。直しは書いた窓へ返す。Bash は読むのと物差しを回すのにだけ使う（`git fetch`・`git diff`・`git grep`・関所の道具）。
- **見る点が読めない時は判定しない**: この skill が読めない時は判定を書かず「見る点が読めない（path）」の 1 行で止まる（見る点なしの green を出さない）。
- **関所を通ってから判定する**: CI と独立なコード・影響経路の下読みは並行できる。PR の判定・コメントの前に `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/review_gate.py" --repo <owner/name> --pr <番号>` を回す。対象リポジトリが CI を合流後に回すと明記している時だけ、そのリポジトリの手順の `--ci-after-merge` と物差しを使う。道具は自分の版が main の先端と違えば先端の版を取り出してそちらで回し直し、先端を取れなければ exit 2 で止まる（窓が立った時の古い版で判定しない・依頼に「先に fetch して」と書かない）。道具が PR の状態を GitHub の記録から読み（必須の検査が先端で全部緑〔無料のプランで必須の検査を作れない非公開の repo は走った検査（先端の workflow の走りも）が全部緑〕・mergeable_state が clean・同じ先端・題・本文への判定がまだ無い）、exit 0 の時だけ正式に判定する。exit 1・2 の時は判定を書かず・PR にコメントを残さず、書いた窓へ `まだ <PR> <枝>@<SHA12> 関所=<道具の最後の行>` の 1 行だけを返す（書いた窓の申告や依頼の文の「緑です」で関所を飛ばさない）。
- **同じ対象に判定は 1 つ**: 1 回で必要な点を見て判定を 1 つだけ出す。同じ先端・題・本文には追加しない。先端を変えず題や本文を直した時は、同じ窓で直した差だけ見直す。
- **前回から足された話は見ない**: 見直し（2 回目から）で、前回の `見た先端` から今の先端までに、依頼に無く前回の `[止める｜…]` の直しでもない話が足されていたら、判定を書かず、書いた窓へ `別の PR へ <PR> <枝>@<SHA12> 話=<足された話と path>` の 1 行だけを返す（red にしない）。書いた窓はその話をこの枝から外し、原因の台帳の行と別の PR にしてから見直しを頼む。
- **都度取り直す**: 初回は変えた判断を使う入口・後段・利用先を一続きで見る。条件が同じ別経路や旧形式も照らし、既知の安全条件を関連経路で一度に確かめる。書いた窓の要約を信じない。依頼の本文（親窓が貼った物）と PR の今の先端・題・本文を同じ取得で取り直す。見直し（2 回目から）は同じ PR の前回の判定のコメントだけを読み、前回の `[止める｜…]` が直ったかと、前回の `見た先端` から今の先端までの差分と、下の「二度目は前回の類を見る」を見る（前回 pass した点の、類の外の所は見直さない）。
- **二度目は前回の類を見る**: 前回の `[止める｜…]` の 1 件だけでなく、その所見が属する類（同じ値・同じ流れが取りうる形の全部。書いた窓が書き出した形の表があればそれと、表に無い形）を今の先端で照らす。同じ類の red が 2 回出たら（前回の所見と同じ類の穴をまた見つけたら）、その所見の頭に `同じ類の 2 回目＝分けるか設計に戻す` と書く。1 件ずつの手直しを重ねる合図でなく、書いた窓がその類を別の PR に分けるか、設計に戻して形から直す合図。確かめた形と確かめていない形は「確認した範囲 / 確認していない範囲」に分けて書く。

## 手順

0. **関所**: 上の「関所を通ってから判定する」。exit 0 でなければここで止まり、「まだ」を返す。見直しでは、続けて「前回から足された話は見ない」を照らす。題・本文だけを直した時は、直した説明と前の所見だけ見直し、同じ先端・条件のコード試験を取り直さない。手順 0 の「見た本文」の値は、実際に見た題・本文の値のまま判定に入れる。
1. **差分を取る**: `git fetch origin main <枝> && git diff <積んだ基点 か origin/main>...origin/<枝>`（PR 本文に `積んだ基点:` があればそこから）。
2. **点で見る**（下の表）。依頼の「やる物」・完了の条件の各行を 1 行ずつ照らし、1 行ごとに所見を書く（問題なしも 1 行）。外れの所見は、その所が何のために在るか（意図）と意図とのずれ（課題）を分けて書く（根治の 5 段＝細目 §3。なぜは書かず書いた窓が原因から探す）。
3. **同じ先端・同じ条件の検査記録を読む**: 先端の CI に使える記録があれば回し直さず、点 4 に何を読んだかを書く。CI が合流後にしか走らない repo では、repo が定めた合流前の物差しを使う。関所が通っただけでは検証済みと書かない。
4. **判定を PR のコメントに残す**（下の形）。出す道具（GitHub のコメント）の前に、守りの hook（guard の `pr_text`）が公開の repo に置かない物を照らす。
5. **返す**: green は依頼した窓へ、red は書いた窓へ直に 1 行（`判定 <PR> <枝>@<SHA12> verdict=green|red レビューした窓=<自分> 物差し=<最後の行>`、red は末尾に `直し=細目 §3「まず構造を疑う」`）。red の所見は直す行の一覧でなく根治の入口: 書いた窓は所見の意図とのずれから入り、細目 §3「まず構造を疑う」で原因を探して直す。

## 見る点

| 点 | 見る事 | red になる時 |
|---|---|---|
| 1 依頼の充足 | やる物・完了の条件を 1 行ずつ・依頼文の範囲とオーナーの原文・PR 本文の整地の `1. 意図`・`2. 課題` | 整地の意図がオーナーの原文の意図と違う・課題に原因（なぜ）が混ざる／欠け／頼まれていない物を足した（膨らみ・見直しで前回から足された話は red にせず「別の PR へ」）／急ぎや重さを理由に範囲・深さを削った（縮み）／依頼文の範囲が、依頼文に貼られたオーナーの原文より縮んでいる |
| 2 触った path | PR の差分の path（`git diff --name-only <基点>...origin/<枝>`・本文の手書きは見ない）と依頼の触ってよい path | その外を変えた／触らない path（変えない物）を変えた |
| 4 回帰 | CI の物差しの記録・直した所の外の結果が変わらない | 物差しが赤／前から赤を「関係ない」と書いて名前を出していない |
| 5 秘密・顧客の物 | diff・PR 本文・ログ | 鍵・トークン・顧客の語・実データが 1 件でも在る（所見には場所だけ書き、値は書かない） |
| 6 当て物・本番の効き目 | 試験が本物の口を通っているか・「直した」が本番の効き目で確かめてあるか | 固定値・mock・特定の入力だけ通す分岐・試験を通すための fallback で緑にした／「直した・反映した」を本番の効き目でなく保存した物・手元の環境・部品単体の緑で言っている／当て物で動かしただけを終わったにしている（暫定なら暫定と書き、恒久の直しを書いた窓へ返す） |
| 7 なくす物 | PR 本文の「畳んだ古い物」と依頼のなくす物 | 消すと言った物が残る／古い前提を残して切り替え（新旧の分岐・設定の切り替え）を足した／消した名を指す文書・設定・試験が残る（`git grep <消した名>`） |
| 8 歯と口・合格の証拠 | 新しく足す守り・直しで約束した結果（細目 §3） | 新しく足した守りの誤りを既存の証拠でも示せない／実際の呼び口から守りに届かない／約束と証拠の範囲が合わない。使える記録を取り直さず、誤りの注入や恒久試験が無いことだけを赤にしない |
| 9 文書の事実 | 書いた path・名・URL が在るか・重さで分ける | 使う側に届く文書（skill・核・細目・README・CONTRIBUTING など）で、無い物を在ると書いた／推し量りを事実として書いた／「概ね」などで未達を丸めた。PR 本文と中身の数の食い違い（触った file の数・足した試験の数の類）は使う側に届かないので red にせず `[提案｜…]` に書く |
| 10 退役・迂回・呼ぶ側 | 消した・退役させた仕組み／新しい関所／共通の仕組み（hook・skill・agent・scripts）の呼ぶ側と呼ばれる側／土台の「壊れる:」変更の 2 段（土台の CONTRIBUTING.md §8） | 消した仕組みが守っていた物が無防備になった（守備範囲を横に照らす）／新しい関所を別の入口・直書き・引数の抜け・同名の別経路で迂回できる／呼ぶ側と呼ばれる側の片方だけを外した・変えた（参照切れ）／土台で使う側の古い形を、新旧の両方を通す 1 段目と使う側が移ったのを確かめる前に外した（1 段目で `plugins/core/古い形.json` に行が無い・2 段目に `kaku.py olds` の出力が無い）（「土台の中だけ」と書いた変更の中に使う側の物が頼る形が在るのも） |
| 11 言語ごとの点 | 下の「言語ごとの点」の表の該当する行 | 表の点に当たる物が在る |
| 12 既定で止まる | 足した・変えた入口と出口（核 §3 の誤りが入れない形） | 知らない値・欠けた材料・表せない決まりで、止まらず黙って既定の値・近い形・前回の値で進む所が在る／選べる値の外が入る／決まりを手で写す段を足した／正しい道を通らずに外へ出せる／「確かめた」が記録（試験・証明）でなく申告だけ／片付かない物を原因の台帳へ向ける決まりの文が、決まった言い回しで台帳を指した後の句で打ち消す（「…の行にして、載せなくてよい」。試験は字の形で見分けない） |

依頼に書いていない所の気づきは `[台帳へ｜…]` にする（止めない）。ただし点 4・5・6・8・10・11・12 は依頼に無くても `[止める｜…]` にしてよい。

## 言語ごとの点（点 11・該当する言語だけ）

| 言語・対象 | 見る点 |
|---|---|
| Python | 例外の握り潰し（`except: pass`）で失敗を飲んでいない／副作用のある既定の引数／`subprocess` の `shell=True` に外の値を渡していない／型ヒントと実の返り値のずれ |
| JS・TS | `any` で型を消していない／`await` 漏れ（未処理の Promise）／`==` の意図しない型の変換／`catch` での握り潰し |
| Shell | `set -euo pipefail` の有無／未クォートの変数（`$x` → `"$x"`）／`rm -rf` の変数の展開先／pipe の途中のエラーが飲まれていない |
| SQL・DB | 戻せない migration（drop・truncate）に人の確認がある／N+1／index の無い全走査／トランザクションの境 |
| hook・検査（歯） | 点 8 の「壊すと赤・戻すと緑」／手元の home の設定にだけ繋がっていて、clone した所では 1 度も動かない形でない |

## 判定の形（PR のコメント）

```
レビューした窓: <自分の session id> 判定: green|red
見た先端: <見た PR の先端の SHA12>
見た本文: <手順 0 が出した値>
job: <job>

## verdict
green / red / red（blocked: <なぜ測れなかったか 1 行>）
直し: 細目 §3「まず構造を疑う」で、所見の意図とのずれから原因を探す（red の時だけ・blocked は除く）

## 点
- 1 依頼の充足: pass/fail（fail は 1 行理由）
- 2 触った path: pass/fail
- 4 回帰: pass/fail（物差しの最後の行）
- 5 秘密・顧客の物: pass/fail
- 6 当て物・本番の効き目: pass/fail
- 7 なくす物: pass/fail
- 8 歯と口・合格の証拠: pass/fail/N/A
- 9 文書の事実: pass/fail/N/A
- 10 退役・迂回・呼ぶ側: pass/fail/N/A
- 11 言語ごとの点: pass/fail/N/A
- 12 既定で止まる: pass/fail/N/A

## 所見
- [止める｜実装] path:関数 — 意図: その所が何のために在るか／課題: 意図とのずれ
- [台帳へ｜整地] 止めない気づき
- [直った｜実装] 前回の 2 番（2 回目だけ）
- [提案｜整地] PR 本文の数と中身の食い違い（使う側に届かない物）と直し方
- [止める｜実装] 同じ類の 2 回目＝分けるか設計に戻す path:関数 — 意図: …／課題: …（2 回目から・同じ類の穴だけ）

## 確認した範囲 / 確認していない範囲
- 見た diff・回した物差し / 見ていない所
```

- 札は `[止める｜<段>]`（直さないと出さない）・`[台帳へ｜<段>]`（通してよい。書いた窓が合流の前に各社の原因の台帳の行にし、PR 本文の「残り」に書く＝細目 §3）・`[提案｜<段>]`（使う側に届かない食い違いの直す提案。止めない・直すかは書いた窓が決める）・`[直った｜<段>]`（前回の止めるが直った）。段は `設計`・`整地`・`見本`・`承認`・`実装`・`レビュー`（捕まえるべきだった段）。
- 点の値は上の雛形の行に書いた値だけ（点 1〜7 は `pass`／`fail`・`N/A` は点 8〜12 だけ。点 3 は畳んだ）。
- `[止める｜…]` が 1 つでも在れば red、無ければ green（1 行目の `判定:` と合わせる）。
- `red（blocked: …）` は、コードを見た結果でなく測れなかった時だけ（物差しが環境で回らない）。
- `見た先端` が PR の今の先端と違う green は無効（見た後に push があった）＝今の先端で見直して判定を足す（誰が見直すかは書いた窓が決める）。
