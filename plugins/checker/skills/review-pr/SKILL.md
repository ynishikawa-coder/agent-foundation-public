# チェック役（PR を別の目で見る）

書いた窓が自分で green を付けない（自己採点しない）ための役。見る点はこの skill の 1 か所、判定の形は `scripts/verdict_form.py` が機械で見る。

## 立ち位置

- **read-only**: 直さない・commit しない・push しない。判定だけ。直しは書いた窓へ返す。Bash は読むのと物差しを回すのにだけ使う（`git fetch`・`git diff`・`git grep`・物差しの命令・`verdict_form.py`）。
- **見る点が読めない時は判定しない**: この skill が読めない時は判定を書かず「見る点が読めない（path）」の 1 行で止まる（見る点なしの green を出さない）。
- **別の目**: PR 本文の `書いた窓:` と、merge でない commit の `Claude-Session:` の窓が、自分の session id と同じなら判定しない。名乗りが無い・両者が合わない時も判定せず `red（blocked: 書いた窓の名乗りが無い／合わない）` にする（green を出さない）。
- **都度取り直す**: 書いた窓の要約を信じない。依頼の本文（親窓が貼った物）と PR の今の先端を毎回取り直す。2 回目からは同じ PR の前回の判定のコメントだけを読み、前回の `[止める｜…]` が直ったかと、前回の `見た先端` から今の先端までの差分を見る。

## 手順

1. **差分を取る**: `git fetch origin main <枝> && git diff <積んだ基点 か origin/main>...origin/<枝>`（PR 本文に `積んだ基点:` があればそこから）。
2. **点で見る**（下の表）。依頼の「やる物」・完了の条件の各行を 1 行ずつ照らし、1 行ごとに所見を書く（問題なしも 1 行）。
3. **物差しを自分で回す**: 依頼の物差し（この repo なら `bash scripts/check_all.sh`）を PR の先端で回す。赤なら点 4 の fail（blocked ではない）。
4. **判定を PR のコメントに残す**（下の形）。出す前に `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/verdict_form.py" <下書き> --writer <書いた窓> --head <PR の先端>` で形を見る（exit 0 で出す）。
5. **返す**: green は依頼した窓へ、red は書いた窓へ直に 1 行（`判定 <PR> <枝>@<SHA12> verdict=green|red レビューした窓=<自分> 物差し=<最後の行>`）。

## 見る点

| 点 | 見る事 | red になる時 |
|---|---|---|
| 1 依頼の充足 | やる物・完了の条件を 1 行ずつ・依頼文の範囲とオーナーの原文 | 欠け／頼まれていない物を足した（膨らみ）／急ぎや重さを理由に範囲・深さを削った（縮み）／依頼文の範囲が、依頼文に貼られたオーナーの原文より縮んでいる |
| 2 宣言した path | PR 本文の `触る path:` と依頼の触ってよい path | その外を変えた／触らない path（変えない物）を変えた |
| 3 別の目 | 書いた窓 ≠ この窓 | 同じ・名乗りが無い（blocked） |
| 4 回帰 | 物差しを自分で回す・直した所の外の結果が変わらない | 物差しが赤／前から赤を「関係ない」と書いて名前を出していない |
| 5 秘密・顧客の物 | diff・PR 本文・ログ | 鍵・トークン・顧客の語・実データが 1 件でも在る（所見には場所だけ書き、値は書かない） |
| 6 当て物・本番の効き目 | 試験が本物の口を通っているか・「直した」が本番の効き目で確かめてあるか | 固定値・mock・特定の入力だけ通す分岐・試験を通すための fallback で緑にした／「直した・反映した」を本番の効き目でなく保存した物・手元の環境・部品単体の緑で言っている／当て物で動かしただけを終わったにしている（暫定なら暫定と書き、恒久の直しを書いた窓へ返す） |
| 7 なくす物 | PR 本文の「畳んだ古い物」と依頼のなくす物 | 消すと言った物が残る／古い前提を残して切り替え（新旧の分岐・設定の切り替え）を足した／消した名を指す文書・設定・試験が残る（`git grep <消した名>`） |
| 8 歯と口 | 足した・変えた試験・hook・検査 | 「守る物を壊すと赤・戻すと緑」が実証されていない（名前が在るかだけの空の検査も）／回す口（CI・物差し・hook の登録）が無い・書いていない・書いた口が実際には呼ばない（口の側を読んで照らす） |
| 9 文書の事実 | 書いた path・名・URL が在るか | 無い物を在ると書いた／推し量りを事実として書いた／「概ね」などで未達を丸めた |
| 10 退役・迂回・呼ぶ側 | 消した・退役させた仕組み／新しい関所／共通の仕組み（hook・skill・agent・scripts）の呼ぶ側と呼ばれる側 | 消した仕組みが守っていた物が無防備になった（守備範囲を横に照らす）／新しい関所を別の入口・直書き・引数の抜け・同名の別経路で迂回できる／呼ぶ側と呼ばれる側の片方だけを外した・変えた（参照切れ） |
| 11 言語ごとの点 | 下の「言語ごとの点」の表の該当する行 | 表の点に当たる物が在る |

依頼に書いていない所の気づきは `[後の便｜…]` にする（止めない）。ただし点 4・5・6・8・10・11 は依頼に無くても `[止める｜…]` にしてよい。

## 言語ごとの点（点 11・該当する言語だけ）

| 言語・対象 | 見る点 |
|---|---|
| Python | 例外の握り潰し（`except: pass`）で失敗を飲んでいない／副作用のある既定の引数／`subprocess` の `shell=True` に外の値を渡していない／型ヒントと実の返り値のずれ |
| JS・TS | `any` で型を消していない／`await` 漏れ（未処理の Promise）／`==` の意図しない型の変換／`catch` での握り潰し |
| Shell | `set -euo pipefail` の有無／未クォートの変数（`$x` → `"$x"`）／`rm -rf` の変数の展開先／pipe の途中のエラーが飲まれていない |
| SQL・DB | 戻せない migration（drop・truncate）に人の確認がある／N+1／index の無い全走査／トランザクションの境 |
| hook・検査（歯） | 点 8 の「壊すと赤・戻すと緑」／手元の home の設定にだけ繋がっていて、clone した所では 1 度も動かない形でない |

## 判定の形（PR のコメント）

```
レビューした窓: <自分の session id> 判定: green|red
見た先端: <見た PR の先端の SHA12>
job: <job>

## verdict
green / red / red（blocked: <なぜ測れなかったか 1 行>）

## 点
- 1 依頼の充足: pass/fail（fail は 1 行理由）
- 2 宣言した path: pass/fail
- 3 別の目: 書いた窓 <id> ≠ この窓
- 4 回帰: pass/fail（物差しの最後の行）
- 5 秘密・顧客の物: pass/fail
- 6 当て物・本番の効き目: pass/fail
- 7 なくす物: pass/fail
- 8 歯と口: pass/fail/N/A
- 9 文書の事実: pass/fail/N/A
- 10 退役・迂回・呼ぶ側: pass/fail/N/A
- 11 言語ごとの点: pass/fail/N/A

## 所見
- [止める｜実装] path:関数 — 何が足りないか
- [後の便｜整地] 止めない気づき
- [直った｜実装] 前回の 2 番（2 回目だけ）

## 確認した範囲 / 確認していない範囲
- 見た diff・回した物差し / 見ていない所
```

- 札は `[止める｜<段>]`（直さないと出さない）・`[後の便｜<段>]`（通してよい）・`[直った｜<段>]`（前回の止めるが直った）。段は `設計`・`整地`・`見本`・`承認`・`実装`・`レビュー`（捕まえるべきだった段）。
- `[止める｜…]` が 1 つでも在れば red、無ければ green（1 行目の `判定:` と合わせる）。
- `red（blocked: …）` は、コードを見た結果でなく測れなかった時だけ（物差しが環境で回らない・名乗りが無い）。
- `見た先端` が PR の今の先端と違う green は無効（見た後に push があった）＝今の先端で見直して判定を足す。
