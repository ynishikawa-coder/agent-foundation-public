# 立ち位置と手順（review-pr）

目次（SKILL.md）から、レビューを始める時に読む。見る点の表と判定の形は SKILL.md に在る。

## 立ち位置

- **read-only**: 直さない・commit しない・push しない。判定だけ。直しは書いた窓へ返す。Bash は読むのと物差しを回すのにだけ使う（`git fetch`・`git diff`・`git grep`・物差しの命令・`verdict_form.py`）。
- **見る点が読めない時は判定しない**: この skill が読めない時は判定を書かず「見る点が読めない（path）」の 1 行で止まる（見る点なしの green を出さない）。
- **別の目**: 判定を書くのは書いた窓と別の窓（レビューの窓）。助手（Agent）は立てた窓の中で動くので、助手の判定は立てた窓の session id で書く＝書いた窓が立てた助手の判定は書いた窓の判定と同じで、別の目にならない（`verdict_form.py` が `--writer` と照らして誤りにする）。判定を出す時は、守りの hook（guard の `pr_text`）が出す窓の本物の id を窓の環境の記録から読み `--reviewer` で渡し、1 行目の名乗りの字はその写しとして照らす（名乗りを作っても通らない）。書いた窓は PR の commit 全部の `Claude-Session:` の窓の組（途中の commit を書いた窓も書いた側）。merge でない commit の `Claude-Session:` の窓（記録）のどれかが自分の session id と同じなら判定しない。名乗りが無い時も判定せず `red（blocked: 書いた窓の名乗りが無い）` にする（green を出さない）。PR 本文の `書いた窓:` は手の写しなので読まない（PR の型から畳んだ）。
- **関所を通ってから見る**: 判定に入る前に `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/review_gate.py" --repo <owner/name> --pr <番号>` を回す。道具は自分の版が main の先端と違えば先端の版を取り出してそちらで回し直し、先端を取れなければ exit 2 で止まる（窓が立った時の古い版で判定しない・依頼に「先に fetch して」と書かない）。道具が PR の状態を GitHub の記録から読み（必須の検査が先端で全部緑〔無料のプランで必須の検査を作れない非公開の repo は走った検査（先端の workflow の走りも）が全部緑〕・mergeable_state が clean・この先端の判定がまだ無い）、exit 0 の時だけ見る。exit 1・2 の時は見ず・判定を書かず・PR にコメントを残さず、書いた窓へ `まだ <PR> <枝>@<SHA12> 関所=<道具の最後の行>` の 1 行だけを返す（書いた窓の申告や依頼の文の「緑です」で関所を飛ばさない）。
- **1 つの先端に判定は 1 つ**: 1 回の見直しで見る点を全部見てから、判定を 1 つだけ出す（点ごとに分けて出さない・同じ先端に 2 つ目を足さない＝関所が「済み」で止める）。
- **前回から足された話は見ない**: 見直し（2 回目から）で、前回の `見た先端` から今の先端までに、依頼に無く前回の `[止める｜…]` の直しでもない話が足されていたら、判定を書かず、書いた窓へ `別の PR へ <PR> <枝>@<SHA12> 話=<足された話と path>` の 1 行だけを返す（red にしない）。書いた窓はその話をこの枝から外し、原因の台帳の行と別の PR にしてから見直しを頼む。
- **都度取り直す**: 書いた窓の要約を信じない。依頼の本文（親窓が貼った物）と PR の今の先端を毎回取り直す。見直し（2 回目から）は同じ PR の前回の判定のコメントだけを読み、前回の `[止める｜…]` が直ったかと、前回の `見た先端` から今の先端までの差分を見る（全部を見直さない）。

## 手順

0. **関所**: 上の「関所を通ってから見る」。exit 0 でなければここで止まり、「まだ」を返す。見直しでは、続けて「前回から足された話は見ない」を照らす。
1. **差分を取る**: `git fetch origin main <枝> && git diff <積んだ基点 か origin/main>...origin/<枝>`（PR 本文に `積んだ基点:` があればそこから）。
2. **点で見る**（目次の SKILL.md の「見る点」の表）。依頼の「やる物」・完了の条件の各行を 1 行ずつ照らし、1 行ごとに所見を書く（問題なしも 1 行）。外れの所見は、その所が何のために在るか（意図）と意図とのずれ（課題）を分けて書く（根治の 5 段＝細目 §3。なぜは書かず書いた窓が原因から探す）。
3. **物差しを自分で回す**: 依頼の物差し（この repo なら `bash scripts/check_all.sh`）を PR の先端で回す。赤なら点 4 の fail（blocked ではない）。
4. **判定を PR のコメントに残す**（目次の SKILL.md の「判定の形」）。出す前に `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/verdict_form.py" <下書き> --writer <書いた窓の組> --head <PR の先端>` で形を見る（書いた窓の組は `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/pr_writer.py" --writers --head <先端>`（PR の repo の取り出しの中で回す。比べる元は道具が出所の今の main を聞いて決める＝手元の origin/main を渡さない） が `,` で並べて出す）（exit 0 で出す）。出す道具（GitHub のコメント）の前でも、守りの hook（guard の `pr_text`）が同じ道具を直に呼び、崩れていれば止める。
5. **返す**: green は依頼した窓へ、red は書いた窓へ直に 1 行（`判定 <PR> <枝>@<SHA12> verdict=green|red レビューした窓=<自分> 物差し=<最後の行>`、red は末尾に `直し=細目 §3「まず構造を疑う」`）。red の所見は直す行の一覧でなく根治の入口: 書いた窓は所見の意図とのずれから入り、細目 §3「まず構造を疑う」で原因を探して直す。
