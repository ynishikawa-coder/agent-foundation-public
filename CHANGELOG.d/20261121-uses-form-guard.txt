- 直した: guard の spec_gate と irreversible（DB の破棄・値の表の irreversible_bash_extra）は、命令の行全体を読み切れた時だけ（変数・展開・$( )・heredoc・redirect・代入・export・tee など file や環境へ出す手が 1 つも無い決まった単純な形）、commit の文・grep の語・echo の字・注釈で名を挙げるだけの所を外す（git commit -m '…'・grep・echo '…'・gh pr create --body '…' は止めない）。1 つでも読み切れない物が在れば前の版と同じく命令の字全体で見る（heredoc で file へ書く形・git commit -m "$(cat <<EOF …)"・変数を使う形も前の版どおり）。| で外の命令へ流す形・git／gh／rg の中で命令を動かす形は今も止まる。値の表が git・gh を狙う行〔git push --force など〕も当たる。git・rg の前置きは動かす口の無いと分かっている一覧で通し、一覧の外の前置き〔git push --receive-pack・git fetch --upload-pack など〕は動く側に数える）
- 直した: guard の paid_upstream は試験の file のコードの所（注釈と Python の docstring を除く。Edit は手元の file に当てた全体で読み、置き換えの後にだけ在るコードの行に在る印を数える）だけを見る。逃げ道の印 PAID_UPSTREAM_GUARD を注釈で名指すだけの file は前と同じく止めない。手元で見つかる共通の補助（上の dir の conftest.py・import する手元の module）のコードが印を読めば黙って通し、見つからなければ書いた後に「関所を見つけられなかった」と知らせる（関所の置き方は pytest_plugins・jest の setupFiles・TS の別名・shell の source など限りなく在るので、探し方の外の正しい置き方を止めない）
- 直した: 整地の雛形の置き場は、括弧ごと `…` に入れて挙げた説明なら残りに数えない（中に `…` を含む置き場も雛形のままなら数える）
- 直した: spec-doc の seal.py は §6 の節の見出しを前の版と同じ形（§6・行頭の 6.・決定照合 を含む）で見つけ、そこから別の節の番号で始まる見出しが中で指すだけの物（## 7. 実装（§6 の結果を受けて）・## 2. 決定照合の進め方）とコードの囲みの中を除く。理由の未定の印は前の版の語（未定・未照合・まだ・聞く・保留・TBD・TODO）に当たり、かつ文節の読みでも未決の時だけ未決とする（「未定義」・前はまだ無かった・聞いた などの経緯の説明は済み。前の版より止める側を広げない）
