- 壊れる（1 段目）: plugin checker のレビューは、始めた時の決まりで見る。判定の 3 行目に `決まりの版: <土台の commit の SHA 先頭 12 文字>` を書き、`verdict_form.py` に `--first <この PR の初めの判定の決まりの版|なし>` を渡す。初めの判定は main の先端の版で書き、2 回目からは初めの判定と同じ版で書く。見る点・選べる値・札はその版の review-pr の SKILL.md から読む（決まりの git は環境変数 AF_RULES_GIT、無ければ ~/.claude/plugins/marketplaces/agent-foundation）。途中で main に足された見る点で red を返し合わない。ただし `- 版によらず当てる点:` の点（今は 5 秘密・顧客の物）は main の先端の名と値で必ず見る。版が読めない時は照らさずに exit 2。`review_gate.py` は入ってよい時に従う版と `--first` の値を出し、guard の pr_text は判定を出す前に PR の初めの判定の版で照らす（古い checker には `--first` を渡さない）。1 段目の間は古い形も通る: 3 行目の無い判定と `--first` の無い呼び方は、今までどおり main の先端の点で照らす。使う側がやる事: 判定を数える関所が `verdict_form.check` を直に呼んでいれば `verdict_form.check_posted(本文, first, …)` に替える（古い形 `verdict-no-rules-line` として起動の hook が名指す）。使う側が移ったのを `kaku.py olds` で確かめた 2 段目で、3 行目の無い判定と `--first` の無い呼び方を拒む。
- 直した: `scripts/pr_overlap.py` の重なりの知らせは、順（先に開いた PR が先に入り、後の PR は入った main を取り込んで続ける＝AI が決める）と、オーナーに聞く時（片方がもう片方の通る条件を変える・2 つの意図が逆向き）だけを言う（オーナーの答え 2026-11-23）。
