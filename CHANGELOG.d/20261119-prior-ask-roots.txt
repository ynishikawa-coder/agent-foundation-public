- 壊れる（1 段目）: guard の跡の形（値の表 `guard.ask_prior_lookup`・`guard.context_handoff`）に、道具の名と入力の欄で見る新しい形を足した。`{"tool": 名の正規表現}` は名の全体に当て、`{"tool": 名, "input": {欄: 正規表現}}` は名と挙げた欄の全部に当たる時だけ跡に数える（入力にその字を含むだけの呼び出しは跡に数えない）。`input` を書くなら欄を 1 つ以上（`[]`・`null`・`""`・`{}` は読めない形として名指し、名だけの形に広げない）。文字列だけの古い形（「道具の名 + 入力の JSON」の字に当てる）は今までどおり読み、起動の時に values_keys と plugin core の古い形の見張り（`古い形.json` の `guard-trace-string`）が名指す。使う側がやる事: `config/skill-values.json` の 2 つの鍵の文字列を新しい形へ移す（2 段目で文字列を読まなくなる）。既定の `context_handoff` は新しい形で書き、組み込みの `SendMessage` を足し、引き継ぎの file は Write・Edit・MultiEdit の `file_path` の名で見る。

- 壊れる（土台の中だけ）: 値の表に `guard.ask_prior_lookup` が無い repo では、窓ごとの最初の選択肢の画面で 1 回止めるのをやめた（止める物を知らせる物に緩めた）。代わりに `docs-kit.qa-html.prior_check_cmd` が在れば、その命令か `check.mjs --run-prior` を Bash で走らせた跡を引いた跡に数える。走らせたかは命令の字で見ず、shell の字を区切って走る道具と引数の並びで見る（前置きの env・command・time・sudo を外し、`bash -c`・eval の中へ降り、`&&`・`;`・`|` で分ける。`echo`・`grep` の引数・`#` の注にその字が在るだけでは数えない）。どちらも無ければ照らさず（止めない）、値の表を持つ repo では起動の時に照らしていない事と値を足す道を知らせる。使う側の物は変えなくてよい。
- 直した: 値の表の壊れた値を黙って通さない。prior_ask・context_size は読めない跡の形を跡に数えず、止める・差し戻す文で名指す。起動の時に values_keys が、値の表の問題の名指しの 1 か所（guard_common.values_problems＝鍵と型の照らしに、guard の読めない正規表現・読めない跡の形・古い形の跡を足した物）を知らせる。
- 壊れる（土台の中だけ）: prior_ask の「引いた跡」を、頼んだ命令の字でなく走った証で見る。道具の呼び出しは同じ tool_use_id の返り（tool_result）に結び、返りが無い・拒まれた・hook に止められた・中断した物は数えない（`ask_prior_lookup` の跡も同じ）。`prior_check_cmd` の道では、Bash の命令を guard_common.parse_shell（PR #70・#77 と同じ名と意味の読み口・`shell_runs` を置き換え）で読み、読み切れない形（`&&`・`||`・`$(…)`・`` `…` ``・制御の語・`exit` の後・`| bash`・表に無い前置き等）が在れば数えない。ヒアドキュメントの本文は走る命令に数えない。その上で `check.mjs --run-prior` は返りに `prior-check: <n> 件` の行が在る時（ページが赤でも可）、値の表の命令そのものは誤りなく返り出力が空でない時だけ数える。使う側がやる事: 引く命令を `cd x && …` 等で包まず 1 つの素の命令で走らせる（数えなかった時は止めた文が理由を名指す）。値の表の `prior_check_cmd` が読み切れない形なら止めた文で名指し、`check.mjs --run-prior` だけを数える。
- 足した: qa-html の `check.mjs --run-prior` は、引き終えた時だけ出力の最後の行に `prior-check: <問いの数> 件` を出す（`--json` の時は標準エラー）。
