- 壊れる: guard の跡の形（値の表 `guard.ask_prior_lookup`・`guard.context_handoff`）を、「道具の名 + 入力の JSON」の字に当てる正規表現から、道具の名と入力の欄で見る形に替えた。文字列は道具の名の全体に当てる正規表現、`{"tool": 名, "input": {欄: 正規表現}}` は名と挙げた欄の全部に当たる時だけ跡に数える。入力にその字を含むだけの呼び出し（Bash の命令の字・Grep の探す字）はもう跡に数えない。入力の JSON に当てる古い形（`"` や空白を含む文字列）は読まず、止めた文・差し戻しの文・起動の時の知らせで名指す。使う側で値を書いた repo は新しい形へ直す（2 つの鍵は 2026-11-19 に足したばかり）。`context_handoff` の既定に組み込みの `SendMessage` を足し、引き継ぎの file は Write・Edit・MultiEdit の `file_path` の名で見る。
- 直した: prior_ask の頼みの境を、人の行の頼みの印（promptId）で切る。hook の差し戻しの行（`Stop hook feedback:` の頭・版によって isMeta が付かない）は頼みの境に数えない（guard_common.is_owner_row と session-watch の is_owner_text も同じ）。
- 壊れる: 値の表に `guard.ask_prior_lookup` が無い repo では、窓ごとの最初の選択肢の画面で 1 回止めるのをやめた。代わりに `docs-kit.qa-html.prior_check_cmd` が在ればその命令（か check.mjs --run-prior）を Bash で走らせた跡を引いた跡に数える。どちらも無ければ照らさず（止めない）、値の表を持つ repo では起動の時に照らしていない事と値を足す道を知らせる。
- 直した: 値の表の壊れた値を黙って通さない。prior_ask・context_size は読めない跡の形を跡に数えずに止める・差し戻す（全部壊れていても通さない）文で名指す。起動の時（values_keys）に guard の値の型の違い・読めない正規表現・読めない跡の形を名指しで知らせる。
