- 壊れる（1 段目）: 値の表の字・正規表現の鍵の当て方（何に・全体か一部か）を型の正本 skill-values/schema.json の鍵の spec（型 patterns の against・match／型 words／型 globs）の 1 か所に持ち、道具は値の表の口（skill_values.py の compile_patterns・hit・words_in・glob_match）だけで当てる（鍵ごとに re.search・fullmatch・部分文字列・fnmatch を書き分けない）。全体に当てる鍵: irreversible_tools_extra（道具の名）・qa_page_exempt（問いのページの path を repo の根から。repo の上の dir の名に当たらない）・ask_term_allow（見つけた字の塊）・outbound_secret_allow（鍵の形に当たった塊。codex の entropy_allow と同じ全体の当て方）・ask_prior_lookup と context_handoff（道具の呼び出し 1 つ＝道具の名・空白・入力の JSON。道具の名から書くので Bash の echo や別の道具の入力の語に当たらない・context_handoff の既定も道具の名から書き、handoff の file を Read しただけでは数えない）。^…$ でない行は前の形として前の読み方（一部に当てる）のまま効かせ、値の表の照らしが名指す（古い形.json に values-pattern-partial を足した）。使う側がやる事: 値の表のこれらの鍵の行を ^…$ で相手の全体の形に書き直す（例は skill guard:guard-rules の値の表）。2 段目（前の形の受けを畳む）は原因の台帳の行。
- 壊れる: dev-flow の codex の self_allow・clients.<名>.paths の glob は path の全体に当て、* と ? は / をまたがない（下の dir まで許すのは **）。前は tools/* が tools/sub/deep/x.py も許した。顧客の物の見分けだけは前の読み方でも当たれば顧客の物と見る（見落とす側へ狭めない）。使う側がやる事: 下の dir まで載せたい self_allow の行を dir/** に書き直す（書き直さないと builder が self_allow の外として止める＝外へ出ない側に倒れる）。
- 直した: paid_markers_extra は字のまま一部に当てる（型 words）と型の正本に書き、正規表現のつもりの行（\ を含む）を値の表の照らしが名指す。値の表の照らしは型 patterns の鍵の読めない行を名指す（その行だけが効かず、同じ鍵の正しい行は効き続ける）。
